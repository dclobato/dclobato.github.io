    Cadeias de caracteres¶

    Em C, não existe um tipo próprio para textos. Uma cadeia de caracteres (string) é um arranjo de char em que o final do texto é marcado por um caractere especial, o caractere nulo ('\0', cujo código é zero). Todas as funções que trabalham com cadeias percorrem os caracteres até encontrar o '\0': é ele, e não o tamanho do arranjo, que diz onde o texto termina.

    Esta página mostra como declarar, ler, copiar, comparar, buscar, converter e dividir cadeias. As funções usadas estão nos cabeçalhos string.h (cópia, comparação e busca), ctype.h (classificação e conversão de caracteres) e stdlib.h (conversão entre textos e números). Um resumo de todas elas está na biblioteca de códigos.

    Representação¶

    Na declaração char s[10] = "Sol";, o arranjo tem 10 posições, mas o texto ocupa apenas 4: as três letras e o '\0', que o compilador acrescenta automaticamente ao final de todo literal entre aspas duplas. As posições restantes recebem zero.

#include <string.h>

int main(void)
{
    char s[10] = "Sol";
    printf("strlen = %zu, sizeof = %zu\n", strlen(s), sizeof(s));
    for (int i = 0; i <= 3; i++) {
        printf("s[%d] = '%c' (código %d)\n", i, s[i] ? s[i] : '0', s[i]);
    }
    printf("strlen(\"Olá\") = %zu\n", strlen("Olá"));
    return 0;
}

    strlen = 3, sizeof = 10
s[0] = 'S' (código 83)
s[1] = 'o' (código 111)
s[2] = 'l' (código 108)
s[3] = '0' (código 0)
strlen("Olá") = 4
    • strlen(s) devolve a quantidade de caracteres antes do '\0': o tamanho do texto;
    • sizeof(s) devolve o tamanho do arranjo, em bytes, qualquer que seja o texto guardado nele;
    • Para guardar um texto com n caracteres, o arranjo precisa de pelo menos n + 1 posições. Um nome com até 49 letras precisa de char nome[50];.

    A última linha da saída mostra que strlen("Olá") vale 4, e não 3. Na codificação UTF-8, usada pela maioria dos editores e sistemas, as letras sem acento ocupam 1 byte, mas as letras acentuadas e o ç ocupam 2 bytes, e strlen conta bytes, e não letras. O mesmo vale para a largura nas opções de formatação do printf e para o acesso por índice: "Olá"[2] não é o á, mas o primeiro dos seus dois bytes. Programas que trabalham letra por letra com textos acentuados precisam levar isso em conta; nos problemas de programação competitiva, os textos costumam ter apenas letras sem acento.

    Aspas simples ou duplas?

    Aspas simples indicam um caractere, que é um número inteiro (o código do caractere): 'a' vale 97. Aspas duplas indicam uma cadeia, que é um arranjo terminado em '\0': "a" ocupa 2 bytes. Por isso, char c = "a"; está errado, e 'abc' não é uma cadeia.

    #include <stdio.h>

int main(void)
{
    char arranjo[] = "texto";        // cópia que pode ser alterada
    const char *ponteiro = "texto";  // aponta para o literal, que não pode ser alterado

    arranjo[0] = 'T';
    printf("%s %s\n", arranjo, ponteiro);                  // Texto texto
    printf("sizeof(arranjo) = %zu, sizeof(ponteiro) = %zu\n", sizeof(arranjo), sizeof(ponteiro));
    // sizeof(arranjo) = 6, sizeof(ponteiro) = 8
    return 0;
}
    • char arranjo[] = "texto"; cria um arranjo com 6 posições e copia para ele os caracteres do literal. O arranjo pertence ao programa, e pode ser alterado à vontade;
    • const char *ponteiro = "texto"; cria um ponteiro que guarda o endereço do literal. Tentar modificar um literal tem comportamento indefinido: o programa pode ser encerrado com Segmentation fault, mas essa reação não é garantida. O const impede alterações por meio desse ponteiro, e por isso deve ser usado sempre que um ponteiro apontar para um literal.

    A seção sobre funções mostra como passar cadeias como parâmetros, e a seção sobre ponteiros, a relação entre arranjos e ponteiros, que explica boa parte do comportamento das cadeias.

    Lendo e escrevendo cadeias¶

    Cadeias são escritas com o especificador %s do printf, ou com puts, que acrescenta uma quebra de linha. Para ler, há duas opções, apresentadas em detalhes na seção sobre entrada e saída:

    • scanf("%49s", palavra) lê uma palavra, parando no primeiro espaço. O número entre o % e o s limita a quantidade de caracteres lidos ao tamanho do arranjo menos um, e não deve ser omitido;
    • fgets(linha, sizeof(linha), stdin) lê uma linha inteira, com espaços, incluindo o '\n' do final, que pode ser removido com linha[strcspn(linha, "\n")] = '\0';.

    Copiando e concatenando¶

    Um arranjo não pode receber outro com =: nome = "Ana"; e destino = origem; não compilam. Para copiar uma cadeia, usa-se strcpy(destino, origem), e, para acrescentar uma cadeia ao final de outra, strcat(destino, origem). Uma forma mais segura de fazer as duas coisas é a função snprintf, que funciona como printf, mas escreve em um arranjo, sem nunca passar do tamanho indicado:

    strcpy e strcat não verificam o tamanho do destino

    strcpy e strcat copiam caracteres até encontrar o '\0' da origem, sem saber o tamanho do destino. Se o destino for pequeno demais, os caracteres excedentes são escritos além do final do arranjo, sobre outras variáveis do programa: é o estouro de buffer (buffer overflow), um dos erros mais comuns e mais perigosos em C. Antes de usá-las, garanta que o destino tem espaço suficiente (incluindo o '\0'), ou use snprintf, que trunca o texto quando ele não cabe e sempre termina a cadeia com '\0'.

    Cuidado também com strncpy(destino, origem, n): apesar do nome, ela não termina a cadeia com '\0' quando a origem tem n caracteres ou mais. Depois de strncpy(destino, "abcdef", 4), o destino contém a, b, c e d, sem o '\0', e qualquer função que o leia vai continuar pela memória seguinte. Se usá-la, termine a cadeia manualmente: destino[n - 1] = '\0';.

    Comparando¶

    O operador == aplicado a duas cadeias compara os endereços onde elas estão, e não os caracteres (a seção sobre ponteiros explica o motivo). Para comparar o conteúdo, usa-se strcmp(a, b), que devolve zero se as cadeias forem iguais, um número negativo se a vier antes de b na ordem dos códigos dos caracteres, e um número positivo se vier depois. strncmp(a, b, n) compara apenas os n primeiros caracteres:

    #include <ctype.h>
#include <stdio.h>
#include <string.h>

int compara_sem_caixa(const char *a, const char *b)
{
    while (*a != '\0' && tolower((unsigned char) *a) == tolower((unsigned char) *b)) {
        a++;
        b++;
    }
    return tolower((unsigned char) *a) - tolower((unsigned char) *b);
}

int main(void)
{
    printf("%d\n", strcmp("abc", "abc") == 0);                  // 1
    printf("%d\n", strcmp("abc", "abd") < 0);                   // 1
    printf("%d\n", strcmp("Zebra", "abelha") < 0);              // 1: maiúsculas vêm antes
    printf("%d\n", strncmp("programa", "progresso", 4) == 0);   // 1
    printf("%d\n", compara_sem_caixa("Zebra", "abelha") > 0);   // 1
    printf("%d\n", compara_sem_caixa("CASA", "casa") == 0);     // 1
    return 0;
}

    strcmp compara os códigos dos caracteres, e, na tabela ASCII, todas as letras maiúsculas (65 a 90) vêm antes das minúsculas (97 a 122). Por isso, "Zebra" vem antes de "abelha". Para comparar sem diferenciar maiúsculas de minúsculas, é preciso converter cada caractere antes de comparar, como faz a função compara_sem_caixa. (Muitos sistemas oferecem a função strcasecmp, que faz isso, mas ela não faz parte do C padrão.) Letras acentuadas também não ficam na ordem alfabética do português, porque os seus códigos são maiores que os de todas as letras sem acento.

    Não esqueça do == 0

    Como strcmp devolve zero quando as cadeias são iguais, a condição if (strcmp(a, b)) é verdadeira quando elas são diferentes. Escreva sempre a comparação completa: if (strcmp(a, b) == 0).

    Buscando¶

    strchr(s, c) e strrchr(s, c) buscam a primeira e a última ocorrência de um caractere, e strstr(s, t) busca a primeira ocorrência de uma cadeia dentro de outra. #include <string.h>

int main(void)
{
    const char *texto = "programar em C e programar bem";

    const char *p = strchr(texto, 'm');
    printf("primeiro 'm' na posição %td\n", p - texto);

    p = strrchr(texto, 'm');
    printf("último 'm' na posição %td\n", p - texto);

    p = strstr(texto, "programar");
    int ocorrencias = 0;
    while (p != NULL) {
        ocorrencias++;
        printf("\"programar\" na posição %td\n", p - texto);
        p = strstr(p + 1, "programar");
    }
    printf("%d ocorrências\n", ocorrencias);

    if (strstr(texto, "devagar") == NULL) {
        printf("\"devagar\" não aparece\n");
    }
    return 0;
}

    Para encontrar todas as ocorrências, a busca recomeça a partir do caractere seguinte ao da última encontrada (p + 1). A diferença entre dois ponteiros é do tipo ptrdiff_t, escrito com %td. Outras funções úteis são strspn(s, conjunto) e strcspn(s, conjunto), que devolvem o tamanho do trecho inicial de s formado só por caracteres do conjunto, ou só por caracteres fora dele.

    Trabalhando caractere por caractere¶

    #include <ctype.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
    char s[] = "Linguagem C, versao 17!";
    int letras = 0, digitos = 0, espacos = 0;

    for (size_t i = 0; s[i] != '\0'; i++) {
        unsigned char c = (unsigned char) s[i];
        if (isalpha(c)) letras++;
        else if (isdigit(c)) digitos++;
        else if (isspace(c)) espacos++;
        s[i] = (char) toupper(c);
    }
    printf("%s\n", s);
    printf("%d letras, %d dígitos, %d espaços\n", letras, digitos, espacos);

    char c = 'g';
    printf("'%c' é a letra número %d do alfabeto\n", c, c - 'a' + 1);
    printf("depois de '%c' vem '%c'\n", c, c + 1);
    printf("o dígito '7' vale %d\n", '7' - '0');
    return 0;
}

    LINGUAGEM C, VERSAO 17!
16 letras, 2 dígitos, 3 espaços
'g' é a letra número 7 do alfabeto
depois de 'g' vem 'h'
o dígito '7' vale 7

    As letras de 'a' a 'z', de 'A' a 'Z' e os dígitos de '0' a '9' têm códigos consecutivos. Por isso, c - 'a' dá a posição da letra no alfabeto (começando em 0), c + 1 é a letra seguinte, e c - '0' converte um dígito no número que ele representa.

    Veja bem, preste atenção!

    As funções de ctype.h recebem um int que precisa ser um valor de unsigned char (de 0 a 255) ou EOF. Como o char tem sinal no GCC, os bytes das letras acentuadas são valores negativos, e passá-los diretamente para isalpha ou toupper é comportamento indefinido. Por isso, converta sempre o caractere para unsigned char antes da chamada, como no exemplo. Mesmo assim, essas funções só reconhecem letras sem acento: toupper não converte á em Á.

    #include <ctype.h>
#include <stdio.h>

int main(void)
{
    int freq[26] = {0};
    int c;

    while ((c = getchar()) != EOF) {
        if (isalpha(c)) {
            freq[tolower(c) - 'a']++;
        }
    }
    for (int i = 0; i < 26; i++) {
        if (freq[i] > 0) {
            printf("%c: %d\n", 'a' + i, freq[i]);
        }
    }
    return 0;
}

void inverte(char *s)
{
    size_t n = strlen(s);
    for (size_t i = 0; i < n / 2; i++) {
        char aux = s[i];
        s[i] = s[n - 1 - i];
        s[n - 1 - i] = aux;
    }
}

int eh_palindromo(const char *s)
{
    size_t n = strlen(s);
    for (size_t i = 0; i < n / 2; i++) {
        if (s[i] != s[n - 1 - i]) {
            return 0;
        }
    }
    return 1;
}

int main(void)
{
    char palavra[] = "programa";
    inverte(palavra);
    printf("%s\n", palavra);                                       // amargorp
    printf("%d %d\n", eh_palindromo("arara"), eh_palindromo("casa"));  // 1 0
    return 0;
}

    Não chame strlen na condição do laço

    Como a cadeia não guarda o seu tamanho, strlen precisa percorrer todos os caracteres até o '\0' a cada chamada: ela é \(O(n)\). Em um laço como for (i = 0; i < strlen(s); i++), que altera a cadeia, ela é chamada a cada repetição, e o laço inteiro passa a ser \(O(n^2)\) (veja a seção sobre complexidade). Nos testes feitos para este texto, converter para maiúsculas uma cadeia com 200 mil caracteres levou cerca de 0,45 segundo com o strlen na condição, e menos de um milésimo de segundo calculando o tamanho uma única vez, antes do laço: size_t n = strlen(s);. Quando o laço não altera a cadeia, o compilador pode fazer essa troca sozinho com -O2, mas não conte com isso.

    Convertendo entre textos e números¶

    As funções atoi e atof, de stdlib.h, convertem um texto em int e em double, mas não indicam erros: um texto que não é um número resulta em 0, e um número grande demais resulta em um valor sem sentido. As funções strtol (para inteiros) e strtod (para reais) permitem detectar os dois problemas: elas recebem o endereço de um ponteiro, onde guardam a posição do primeiro caractere que não fez parte do número, e indicam valores fora do limite na variável errno, de errno.h. #include <stdio.h>
#include <stdlib.h>

int main(void)
{
    const char *entradas[] = {"42", "  -17", "12abc", "abc", "99999999999999999999"};

    for (int i = 0; i < 5; i++) {
        const char *s = entradas[i];
        char *fim;
        errno = 0;
        long valor = strtol(s, &fim, 10);

        printf("%-22s atoi = %-11d ", s, atoi(s));
        if (fim == s) {
            printf("strtol: não é um número\n");
        } else if (errno == ERANGE) {
            printf("strtol: fora do limite\n");
        } else if (*fim != '\0') {
            printf("strtol: %ld, mas sobrou \"%s\"\n", valor, fim);
        } else {
            printf("strtol: %ld\n", valor);
        }
    }

    double d = strtod("3.75e2", NULL);
    printf("strtod: %.1f\n", d);

    char texto[32];
    snprintf(texto, sizeof(texto), "%d|%.2f", 2026, 3.14159);
    printf("número para texto: [%s]\n", texto);
    return 0;
}

    • Se fim aponta para o início da cadeia, nenhum caractere foi convertido: o texto não começa com um número;
    • Se errno vale ERANGE, o número não cabe no tipo (com atoi, o resultado é imprevisível);
    • Se fim não aponta para o '\0', sobraram caracteres depois do número. Dependendo do caso, isso pode ser aceitável (como em "12 maçãs") ou um erro.

    O terceiro argumento de strtol é a base: 10 para decimal, 16 para hexadecimal, 2 para binário. As funções de leitura da biblioteca de códigos usam strtol e strtod dessa forma.

    char linha[] = "maçã, banana,,laranja , uva";
    int n = 0;

    for (char *parte = strtok(linha, ","); parte != NULL; parte = strtok(NULL, ",")) {
        n++;
        printf("%d: [%s]\n", n, parte);
    }
    printf("linha depois do strtok: [%s]\n", linha);
    return 0;
}

    1: [maçã]
2: [ banana]
3: [laranja ]
4: [ uva]
linha depois do strtok: [maçã]

    A saída mostra três características de strtok que é preciso conhecer:

    • Delimitadores consecutivos são tratados como um só: a parte vazia entre as duas vírgulas de ",," desapareceu;
    • Os espaços em volta das partes são mantidos. Para removê-los, use a função da biblioteca de códigos, ou inclua o espaço entre os delimitadores (", ");
    • strtok altera a cadeia original, colocando um '\0' no lugar de cada delimitador encontrado: depois da divisão, linha contém só "maçã". Por isso, ela não pode ser usada com literais, e, se o texto original ainda for necessário, é preciso trabalhar sobre uma cópia.

    Como strtok guarda internamente a posição em que parou, não é possível dividir duas cadeias ao mesmo tempo, intercalando as chamadas. Quando as partes têm um formato fixo, como os campos de uma data, sscanf costuma ser mais simples, como mostra a seção sobre entrada e saída.

    Listas de cadeias¶

    Uma lista de textos pode ser guardada de duas formas: como um arranjo de ponteiros (const char *frutas[]), em que cada elemento aponta para um literal (ou para uma cadeia alocada com malloc), ou como uma matriz de caracteres (char nomes[4][20]), em que cada linha é um arranjo de tamanho fixo, que pode ser alterado.     #include <stdio.h>
#include <stdlib.h>
#include <string.h>

int compara_cadeias(const void *a, const void *b)
{
    const char *x = *(const char *const *) a;
    const char *y = *(const char *const *) b;
    return strcmp(x, y);
}

int compara_linhas(const void *a, const void *b)
{
    return strcmp((const char *) a, (const char *) b);
}

int main(void)
{
    const char *frutas[] = {"uva", "banana", "laranja", "abacaxi"};
    int n = sizeof(frutas) / sizeof(frutas[0]);
    qsort(frutas, n, sizeof(frutas[0]), compara_cadeias);
    for (int i = 0; i < n; i++) {
        printf("%s ", frutas[i]);
    }
    printf("\n");

    char nomes[4][20] = {"Davi", "Ana", "Carla", "Bruno"};
    qsort(nomes, 4, sizeof(nomes[0]), compara_linhas);
    for (int i = 0; i < 4; i++) {
        printf("%s ", nomes[i]);
    }
    printf("\n");
    printf("sizeof(frutas) = %zu, sizeof(nomes) = %zu\n", sizeof(frutas), sizeof(nomes));
    return 0;
}

    abacaxi banana laranja uva
Ana Bruno Carla Davi
sizeof(frutas) = 32, sizeof(nomes) = 80
    • Em frutas, cada elemento é um ponteiro (8 bytes), e a função de comparação recebe o endereço de um ponteiro: é preciso uma indireção a mais para chegar à cadeia. O qsort troca apenas os ponteiros, sem mover os textos;
    • Em nomes, cada elemento é uma linha de 20 caracteres, e a função de comparação recebe o endereço do início da linha, que já é a cadeia. O qsort move os 20 bytes de cada linha a cada troca.

    A seção sobre funções explica como as funções de comparação do qsort funcionam.

    Erros comuns¶

    Erro O que acontece Como evitar
    Arranjo sem espaço para o '\0' Funções que leem a cadeia continuam pela memória seguinte Declare o arranjo com, pelo menos, o tamanho do texto mais 1
    = para copiar e == para comparar Não compila, ou compara endereços Use strcpy (ou snprintf) e strcmp
    if (strcmp(a, b)) É verdadeiro quando as cadeias são diferentes Escreva strcmp(a, b) == 0
    strcpy/strcat em destino pequeno Estouro de buffer Verifique o tamanho, ou use snprintf
    %s sem limite no scanf Estouro de buffer com palavras longas Use %49s para um arranjo de 50 posições
    Alterar um literal Segmentation fault Use const char * para literais e char s[] para cadeias alteráveis
    strlen na condição do laço O laço vira \(O(n^2)\) Calcule o tamanho uma vez, antes do laço
    Esquecer o '\n' deixado por fgets Comparações e saídas com um caractere a mais s[strcspn(s, "\n")] = '\0';
    char direto em toupper/isalpha Comportamento indefinido com acentos Converta para unsigned char
