    Entrada e saída de dados¶

    As funções de entrada e saída de dados estão declaradas no cabeçalho stdio.h (standard input/output). Elas trabalham com fluxos (streams): sequências de caracteres que o programa lê ou escreve, uma depois da outra. Todo programa começa com três fluxos já abertos:

    • stdin (standard input): o fluxo de entrada padrão, normalmente associado ao teclado;
    • stdout (standard output): o fluxo de saída padrão, normalmente associado à tela;
    • stderr (standard error): o fluxo de saída de erros, usado para mensagens de erro e de diagnóstico. Normalmente, ele também aparece na tela, mas pode ser separado da saída padrão.

    Funções como printf e scanf usam stdout e stdin. Os mesmos fluxos podem ser redirecionados para arquivos, e o programa pode abrir outros fluxos para ler e escrever em arquivos.

    Saída de dados¶

    Função printf()¶

    A função printf() escreve na saída padrão um texto formatado. O primeiro argumento é a cadeia de formato, que contém o texto a ser escrito e, no lugar de cada valor, um especificador de formato iniciado por %. Os argumentos seguintes são os valores, na mesma ordem dos especificadores:

    Exemplos de uso de printf()
    int idade = 30;
double altura = 1.75;
char nome[] = "Carlos";

printf("Idade: %d anos\n", idade);
printf("%s tem %d anos e %.2f m de altura\n", nome, idade, altura);
printf("Caracteres especiais: Tab\tNova linha\n");

    Os especificadores mais usados são %d para int, %lld para long long, %f para double, %c para char e %s para cadeias de caracteres. A tabela completa está na biblioteca de códigos, e a seção sobre tipos de dados mostra qual especificador usar com cada tipo. As sequências de escape, como \n e \t, foram apresentadas anteriormente.

    Veja bem, preste atenção!

    O printf não verifica se os tipos dos argumentos combinam com os especificadores. Escrever um double com %d, ou um long long com %d, produz valores sem sentido. Felizmente, o compilador verifica a cadeia de formato quando ela é um literal, e avisa sobre esses erros com -Wall (format '%d' expects argument of type 'int', but argument 2 has type 'double').

    Formatando a saída¶

    Entre o % e a letra do especificador, é possível indicar opções de formatação: largura mínima, alinhamento, preenchimento com zeros, quantidade de casas decimais e outras. A forma geral é:

    %[opções][largura][.precisão]tipo

    As opções de formatação mais comuns aparecem nos exemplos a seguir. Nas saídas, os colchetes foram colocados em volta de cada valor para mostrar onde ele começa e termina.

    A precisão, escrita depois de um ponto, define a quantidade de casas decimais de um número real. Sem ela, %f escreve 6 casas. O valor é arredondado para a casa pedida.

    putchar(), puts() e fputs()¶

    Quando não é preciso formatar valores, há funções mais simples. putchar(c) escreve um único caractere. puts(s) escreve uma cadeia de caracteres e uma quebra de linha. fputs(s, fluxo) escreve uma cadeia em qualquer fluxo, sem acrescentar a quebra de linha. Para escrever no fluxo de erros, usa-se fprintf(stderr, ...) ou fputs(..., stderr):

{

    puts("Segunda linha");

    fputs("Sem quebra de linha automática", stdout);
    fputs("\n", stdout);

    return 0;
}

    putchar(c) é equivalente a putc(c, stdout): a função putc recebe o fluxo como segundo argumento, e pode escrever em qualquer fluxo, inclusive em arquivos.

    Entrada de dados¶

    Função scanf()¶

    A função scanf() lê valores da entrada padrão, de acordo com uma cadeia de formato, e os guarda nas variáveis indicadas. O f no nome indica que ela faz uma entrada formatada:

    Lendo a idade
    int idade;
scanf("%d", &idade);
printf("Você tem %d anos.\n", idade);

    Repare no & antes do nome da variável: scanf precisa guardar um valor na variável, e para isso recebe o seu endereço, e não o seu valor. A seção sobre funções explica esse mecanismo em detalhes. Esquecer o & é um dos erros mais comuns em C: o programa compila (com um aviso) e é encerrado com Segmentation fault. A exceção são as cadeias de caracteres (%s), em que o nome do arranjo já é um endereço.

    Um único scanf() pode ler vários valores: basta escrever um especificador para cada um, e passar as variáveis na mesma ordem. Os especificadores numéricos e o %s pulam os espaços em branco (espaços, tabulações e quebras de linha) antes do valor, e por isso os valores podem estar separados por um ou mais espaços, ou estar em linhas diferentes:

    int a, b, c;
double f;
scanf("%d %d %d %lf", &a, &b, &c, &f);

    Veja bem, preste atenção!

    Em scanf, %f lê um float e %lf lê um double. Trocar um pelo outro produz valores sem sentido. Em printf, os dois funcionam para double. Para long long, use %lld nos dois.

    Verificando o retorno de scanf()¶

    A função scanf() devolve a quantidade de valores lidos e guardados com sucesso. Se a entrada não tiver o formato esperado, a leitura para no primeiro valor que não pôde ser convertido, e as variáveis seguintes ficam como estavam. Uma falha de entrada antes da primeira conversão concluída faz a função devolver EOF, uma constante negativa de stdio.h, normalmente igual a -1:

    Entrada inválida (scanf leu 1 valor(es))

    Verificar o retorno de scanf() evita que o programa continue trabalhando com variáveis que não receberam nenhum valor, e é a base para ler a entrada até o final.

    Retorno válido não verifica o intervalo do número

    Se a entrada representa um número que não cabe no tipo de destino, a conversão de scanf tem comportamento indefinido. Para validar entradas arbitrárias, leia a linha e use strtol ou strtod, conferindo o fim da conversão, errno e os limites do tipo. A biblioteca de códigos apresenta funções que fazem essas verificações.

    Lendo até o final da entrada¶

    Muitos problemas não informam quantos valores serão lidos: o programa deve ler até o final da entrada. Como scanf() devolve a quantidade de valores lidos, basta repetir a leitura enquanto ela devolver o valor esperado:

    int x, quantidade = 0;

    while (scanf("%d", &x) == 1) {
        soma += x;
        quantidade++;
    }
    printf("%d valores, soma %lld\n", quantidade, soma);

    Compare com == 1, e não com != EOF: se a entrada tiver algo que não é um número, scanf devolve 0 (e não EOF), não consome nada, e um laço com != EOF nunca terminaria.

    E como termino a entrada no teclado?

    Lendo palavras e linhas¶

    O especificador %s lê uma palavra: ele pula os espaços em branco iniciais e para no primeiro espaço seguinte. Por isso, ele não serve para ler um nome completo:

    Uma chamada nem sempre lê a linha inteira

    Se a linha tiver mais caracteres do que cabem no arranjo, fgets entrega apenas um trecho e deixa o restante para a próxima leitura. Remover o '\n' com strcspn não resolve esse truncamento. A ausência de '\n' também pode ocorrer na última linha de um arquivo sem quebra final. Para ler linhas completas sem um limite fixo, use lerLinhaArquivo, que amplia o armazenamento conforme a necessidade.

    fgets e getchar podem sinalizar tanto fim de arquivo quanto erro de leitura. Depois que um laço de leitura terminar, ferror(fluxo) identifica um erro, e feof(fluxo) informa se uma tentativa de leitura encontrou o fim do arquivo. Não use while (!feof(arquivo)): o indicador só é ativado depois de uma tentativa de ler além do fim. Controle o laço pelo retorno da função de leitura.

    Nunca use gets()

    A função gets(), que lia uma linha sem nenhum limite de tamanho, era tão perigosa (qualquer linha maior que o arranjo corrompia a memória) que foi removida da linguagem no C11. Os compiladores atuais avisam ou recusam o seu uso. Use fgets().

    Na cadeia de formato, os caracteres que não fazem parte de um especificador, como as barras de "%d/%d/%d", precisam aparecer exatamente assim na entrada.     O %49[^,] lê até 49 caracteres diferentes da vírgula. A biblioteca de códigos tem funções que leem números de forma segura em programas interativos, pedindo o valor novamente quando o usuário digita algo inválido.

    Arquivos texto¶

    Para ler ou escrever em um arquivo, é preciso abri-lo com a função fopen(), que recebe o nome do arquivo e o modo de abertura, e devolve um ponteiro para FILE, usado em todas as operações seguintes. Se o arquivo não puder ser aberto, fopen() devolve NULL, e isso sempre deve ser verificado. Depois de usar o arquivo, ele deve ser fechado com fclose(), o que garante que tudo o que foi escrito seja gravado e libera os recursos do sistema.

    Modo Descrição
    "r" Leitura. O arquivo precisa existir; se não existir, fopen() devolve NULL
    "w" Escrita. Cria o arquivo ou, se ele existir, apaga todo o seu conteúdo
    "a" Anexação. Escreve no final do arquivo, preservando o conteúdo; cria o arquivo se ele não existir
    "r+" Leitura e escrita. O arquivo precisa existir, e o conteúdo é preservado
    "w+" Leitura e escrita. Cria o arquivo ou apaga o seu conteúdo
    "a+" Leitura e anexação. A escrita é sempre feita no final do arquivo

    As funções de escrita e de leitura em arquivos são as mesmas já vistas, com um f no início do nome e o arquivo como argumento: fprintf(arquivo, ...), fputs(texto, arquivo), fscanf(arquivo, ...), fgets(linha, tamanho, arquivo) e getc(arquivo). Os fluxos padrão também podem ser usados nessas funções: fprintf(stdout, ...) é o mesmo que printf(...).

    Arquivos binários¶

    Além de arquivos de texto, é possível trabalhar com arquivos binários, que guardam os dados como uma sequência de bytes, sem conversão para texto. Ao gravar um int diretamente, ele ocupa sizeof(int) bytes no arquivo (4 nos ambientes dos exemplos), qualquer que seja o valor. Em um arquivo de texto, o número 1234567 ocupa 7 caracteres. Arquivos binários são usados para guardar estruturas, imagens, sons e outros dados que não precisam ser lidos por pessoas.

    A abertura é feita com fopen(), acrescentando um b ao modo de abertura: "rb", "wb", "ab", "rb+", "wb+" e "ab+". A leitura e a escrita são feitas com as funções fread() e fwrite():

    size_t fwrite(const void *dados, size_t tamanho, size_t quantidade, FILE *arquivo);
size_t fread(void *dados, size_t tamanho, size_t quantidade, FILE *arquivo);

    As duas recebem o endereço dos dados, o tamanho de cada elemento (normalmente obtido com sizeof), a quantidade de elementos e o arquivo, e devolvem a quantidade de elementos efetivamente gravados ou lidos. O programa abaixo grava um arranjo de estruturas Aluno de uma só vez, e o seguinte lê os registros de volta, um de cada vez, até o final do arquivo:

Estruturas com ponteiros não devem ser gravadas dessa forma: o arquivo guardaria o endereço, e não os dados apontados, e o endereço não faz sentido em outra execução do programa. É por isso que o nome do Aluno é um arranjo de char com tamanho fixo, e não um char *.

    Posicionando a leitura e a escrita¶

    Todo arquivo aberto tem uma posição atual, onde será feita a próxima leitura ou escrita, que avança a cada operação. A função fseek() muda essa posição, e a função ftell() informa a posição atual, em bytes a partir do início do arquivo:

    int fseek(FILE *arquivo, long deslocamento, int origem);
long ftell(FILE *arquivo);

    O deslocamento, que pode ser negativo, é contado a partir da origem: SEEK_SET (o início do arquivo), SEEK_CUR (a posição atual) ou SEEK_END (o final do arquivo). A função rewind(arquivo) volta ao início, como fseek(arquivo, 0, SEEK_SET). Ir para o final e perguntar a posição é uma forma de descobrir o tamanho do arquivo:

Usar fseek() entre as duas operações, como no exemplo, atende a essas regras.

    Evite fseek() em arquivos texto

    Em arquivos texto, fseek() só funciona de forma confiável com posições obtidas por ftell(), porque alguns sistemas operacionais convertem a quebra de linha \r\n em \n, e a quantidade de bytes no arquivo não corresponde à quantidade de caracteres lidos. Use o posicionamento em arquivos binários.

    Redirecionamento dos fluxos padrão¶

    Os fluxos padrão podem ser redirecionados quando o programa é executado no terminal. Com <, a entrada padrão passa a ser lida de um arquivo; com >, a saída padrão passa a ser gravada em um arquivo (que é criado, ou tem o conteúdo apagado). O programa não precisa de nenhuma alteração: para ele, scanf continua lendo de stdin, e printf continua escrevendo em stdout.

    #include <stdio.h>

int main(void)
{
    int num;
    while (scanf("%d", &num) == 1) {
        printf("O dobro de %d é %d\n", num, num * 2);
    }
    return 0;
}

    C:\Users\aluno> dobro.exe < entrada.txt
O dobro de 4 é 8
O dobro de 10 é 20

    Na segunda execução, nada aparece na tela: a saída foi gravada em saida.txt. Com 2>, é o fluxo de erros que é redirecionado (./programa 2> erros.txt).

    O redirecionamento é muito útil para testar programas: em vez de digitar os dados a cada execução, eles são guardados em um arquivo. É também exatamente assim que os juízes online executam os programas: a entrada de cada caso de teste é redirecionada para a entrada padrão, e a saída padrão é comparada com a saída esperada.

    Dicas para juízes online¶

    Escreva apenas o que foi pedido

    O juiz compara a saída do programa, caractere por caractere, com a saída esperada. Mensagens como Digite um número:, que são úteis em um programa interativo, fazem a resposta ser considerada errada. Escreva exatamente o formato pedido no enunciado, incluindo espaços, quebras de linha e a quantidade de casas decimais. Mensagens de depuração podem ser escritas em stderr (fprintf(stderr, ...)), que normalmente não é comparado pelo juiz, mas o ideal é removê-las antes de enviar.

    Problemas interativos

    Quando a saída padrão não é a tela (como no juiz, ou em um redirecionamento), o que o programa escreve é acumulado em uma área de memória, o buffer, e só é gravado quando o buffer enche ou quando o programa termina. Isso torna a escrita muito mais rápida. Em problemas interativos, em que o programa conversa com o juiz (escreve uma pergunta, lê a resposta, escreve outra pergunta...), a pergunta precisa chegar ao juiz antes de o programa tentar ler a resposta: chame fflush(stdout) depois de cada escrita.

    Leitura rápida

    Para a grande maioria dos problemas, scanf e printf são rápidos o suficiente. Mas, quando a entrada tem milhões de números, o tempo de leitura pode fazer diferença. Nos testes feitos para este texto, ler 5 milhões de inteiros com scanf levou entre 0,37 e 0,57 segundo, e com a função abaixo, que lê caractere por caractere com getchar, cerca de 0,16 segundo:

    int le_int(void)
{
    int c = getchar();
    while (c == ' ' || c == '\n' || c == '\r' || c == '\t') {
        c = getchar();
    }
    int negativo = 0;
    if (c == '-') {
        negativo = 1;
        c = getchar();
    }
    int valor = 0;
    while (c >= '0' && c <= '9') {
        valor = valor * 10 + (c - '0');
        c = getchar();
    }
    return negativo ? -valor : valor;
}

    A função supõe que a entrada está correta (ela não detecta o final da entrada nem caracteres inválidos), e deve ser usada só quando a leitura for, comprovadamente, o gargalo do programa.
