    Tipos de dados em C¶

    Em C, os tipos de dados definem a semântica, as características de armazenamento e as operações permitidas para elementos de dados, sendo expressos na sintaxe por meio de declarações de variáveis; a linguagem oferece tipos aritméticos básicos (inteiros e reais) e sintaxe para construir arranjos (arrays) e tipos compostos.

    O valor máximo que um determinado tipo de dados pode armazenar depende de fatores como sistema operacional e tipo de processador. Uma forma de verificar os limites na máquina que você está usando é consultar os valores disponíveis no cabeçalho limits.h.

    Tipos principais¶

    A linguagem C fornece quatro especificadores de tipos de dados aritméticos: char, int, float e double (além do tipo lógico bool), e os modificadores signed, unsigned, short e long. A combinação dos tipos com os modificadores produz os seguintes tipos de dados.

    Tipo Detalhes bits Sufixo para constantes

    Não existem sufixos para os tipos char e short: uma constante inteira decimal sem sufixo é do tipo int quando seu valor cabe nele (como 42), ou de um tipo inteiro com sinal maior quando necessário, e é convertida para o tipo da variável na atribuição. Os sufixos podem ser combinados em qualquer ordem e com letras maiúsculas ou minúsculas (10UL, 10lu), mas prefira as maiúsculas: o l minúsculo é facilmente confundido com o dígito 1.

    Os valores mínimos e máximos de cada tipo de dados também podem ser consultados na biblioteca limits.h.

    A relação entre os modificadores exige que long long não seja menor que long, que não é menor que int, que não é menor que short. O menor tamanho é do tipo char. O tipo int deve ser o tipo inteiro que o processador manipula com mais eficiência.

    O padrão define apenas os tamanhos mínimos. Nos computadores atuais, com processadores de 64 bits, os tamanhos e os limites são os da tabela abaixo, que também mostra os especificadores usados para escrever e ler cada tipo com printf e scanf:

    Tipo Tamanho Menor valor Maior valor printf scanf
    char 1 byte -128 127 %c %c
    int 4 bytes -2.147.483.648 2.147.483.647 (\(\approx 2{,}1 \times 10^9\)) %d %d
    unsigned int 4 bytes 0 4.294.967.295 (\(\approx 4{,}3 \times 10^9\)) %u %u
    long 8 bytes no Linux, 4 no Windows %ld %ld
    long long 8 bytes \(\approx -9{,}2 \times 10^{18}\) \(\approx 9{,}2 \times 10^{18}\) %lld %lld
    unsigned long long 8 bytes 0 \(\approx 1{,}8 \times 10^{19}\) %llu %llu
    float 4 bytes cerca de 6 dígitos significativos %f %f
    double 8 bytes cerca de 15 dígitos significativos %f ou %lf %lf

    Qual tipo usar?

    Para inteiros, use int quando os valores couberem com folga em \(\pm 2 \times 10^9\), e long long quando puderem passar disso (somas de muitos valores, produtos, contagens grandes). Evite long, que tem 8 bytes no Linux e só 4 no Windows: um programa que funciona em um sistema pode transbordar no outro. Para números reais, prefira sempre double: o float tem pouca precisão, e as funções de math.h trabalham com double.

    Repare que, em scanf, %f lê um float e %lf lê um double; trocar um pelo outro produz valores sem sentido. Em printf, os dois funcionam para double.

    O sinal do tipo char (sem signed ou unsigned) depende do compilador e do processador: no GCC em computadores comuns, ele tem sinal e vai de -128 a 127. O padrão C99 também adicionou os tipos complexos (float _Complex, double _Complex e long double _Complex), usados com a biblioteca complex.h.

    Veja bem, preste atenção!

    O que acontece se eu tentar colocar um número maior que o maior valor que determinado tipo de dado pode armazenar? É como tentar colocar um tênis tamanho 45 numa caixa de sapato feita para tamanho 38.

    A linguagem C não avisa com erros de compilação ou de execução sobre isso. Esse problema se chama transbordamento (overflow), e o que acontece depende do tipo:

    • Com tipos sem sinal (unsigned), o valor "dá a volta": o resultado é calculado módulo \(2^b\), em que \(b\) é o número de bits do tipo. UINT_MAX + 1 vale 0, e 0u - 1 vale UINT_MAX;
    • Com tipos com sinal, o transbordamento é comportamento indefinido. Na prática, o valor costuma "dar a volta" para o lado negativo, mas o compilador pode supor que isso nunca acontece e otimizar o código de formas inesperadas.

    O erro mais comum em programação competitiva é calcular um valor que só cabe em long long usando apenas variáveis int:

    int n = 100000;
long long errado = n * n;       // comportamento indefinido com int de 32 bits
long long certo = 1LL * n * n;  // 10000000000

    Guardar o resultado em um long long não basta: a multiplicação n * n é feita com o tipo dos operandos (int), transborda, e só depois o resultado (já errado) é convertido. Multiplicar primeiro por 1LL faz com que toda a conta seja feita em long long. O compilador pode não diagnosticar esse erro.

    Tipos de tamanho fixo

    Os tipos inteiros em C foram projetados para tornar o código portátil entre máquinas com diferentes tamanhos de palavra, o que significa que cada tipo pode ter diferentes intervalos de valores dependendo da arquitetura. No entanto, essa variação pode ser problemática quando um programa precisa operar com um intervalo específico de inteiros ou um tamanho fixo de armazenamento, independentemente da máquina em que será executado. A partir da versão C99 foram introduzidas definições de tipos que permitem declarar inteiros com tamanhos exatos, garantindo que o código-fonte do programa permaneça independente da arquitetura subjacente. Os tipos são os seguintes:

    • int\(b\)_t: inteiro com exatamente \(b\) bits e com sinal
    • uint\(b\)_t: inteiro com exatamente \(b\) bits e sem sinal

    Se não for necessário um tamanho específico, mas o menor tipo capaz de guardar um número de \(b\) bits, pode-se usar os seguintes tipos:

    • int_least\(b\)_t: inteiro com pelo menos \(b\) bits e com sinal
    • uint_least\(b\)_t: inteiro com pelo menos \(b\) bits e sem sinal

    Por questões de projeto do hardware do computador, alguns tamanhos podem ter um desempenho maior ou menor. Para isso, foram criados os tipos abaixo para representar os tipos de acesso mais rápido com pelo menos \(b\) bits.

    • int_fast\(b\)_t: inteiro de acesso mais rápido com pelo menos \(b\) bits e com sinal
    • uint_fast\(b\)_t: inteiro de acesso mais rápido com pelo menos \(b\) bits e sem sinal

    Para \(b \in \{8, 16, 32, 64\}\), os tipos int_least e int_fast, com e sem sinal, são obrigatórios. Já os tipos de tamanho exato, como int32_t, só existem se a implementação oferecer uma representação adequada, sem bits de preenchimento. Portanto, nem todo tipo de tamanho exato é obrigatório.

    Esses tipos estão definidos no cabeçalho stdint.h. Para escrevê-los com printf, o cabeçalho inttypes.h define macros com os especificadores corretos, como em printf("%" PRId64 "\n", x) para um int64_t.

    Mais detalhes podem ser obtidos na referência de tipos inteiros do cppreference ou no manual da GNU C Library.

    Constantes¶

    Usamos constantes para dar nomes a valores que permanecem fixos no programa. No C17, é importante distinguir uma macro, substituída pelo pré-processador, de um objeto qualificado com const, cujo valor não pode ser alterado após a inicialização. Esses mecanismos têm usos semelhantes, mas regras diferentes.

    Veja bem, preste atenção!

    Na prática, o uso de const é preferível na grande maioria dos casos devido à segurança de tipo, possibilidade de depuração e escopo mais restrito. Use #define apenas se você tiver uma razão forte para isso, como definir o tamanho de um arranjo global (veja o aviso mais abaixo).

    As formas mais comuns de nomear esses valores são a diretiva de pré-processador #define e a palavra-chave const na declaração de um objeto. Constantes de enumeração também podem ser usadas para valores inteiros.

    Usando #define¶

    A diretiva #define é processada pelo pré-processador antes da compilação. O pré-processador substitui todas as ocorrências do nome da constante pelo seu valor antes de o código ser compilado. Isso significa que:

    • A macro não declara um objeto com tipo próprio. Após a substituição, os literais e as expressões usados nela são analisados com as regras normais de tipos;
    • Como a substituição ocorre antes da análise do código pelo compilador, erros podem ser mais difíceis de detectar;
    • A macro é uma substituição textual, e não uma variável armazenada na memória. O resultado da substituição pode, contudo, criar objetos, como acontece com literais de texto.

    Exemplo:

    #include <stdio.h>

#define PI 3.14159

    No código acima, o pré-processador transforma PI * raio * raio em 3.14159 * raio * raio antes da compilação.

    Usando const¶

    O uso de const define uma variável que é tratada como uma constante pelo compilador. Diferente de #define, essa constante tem um tipo definido e ocupa espaço na memória (a menos que o compilador otimize e substitua seu uso diretamente).

    • A constante tem um tipo de dado explícito, permitindo verificações de tipo pelo compilador;
    • Segue as regras de escopo da linguagem; uma macro fica definida do seu #define até o #undef correspondente ou o fim da unidade de tradução, sem respeitar os blocos delimitados por chaves;
    • Pode ser usada para ponteiros, arranjos e outras estruturas de dados.

    Exemplo:

    const double PI = 3.14159; // Constante com tipo definido

    Aqui, PI é tratado como uma variável que não pode ser modificada. Diferente de #define, ele tem um tipo e ocupa uma posição de memória.

    Veja bem, preste atenção!

    Em C, uma variável const não é uma constante de compilação: o compilador não pode usar o seu valor onde a linguagem exige um valor conhecido durante a compilação. Declarar um arranjo global com const int N = 100; e int v[N]; não compila (variably modified 'v' at file scope). Usar N como rótulo de um case também não é permitido pelo padrão: o GCC 13.2 com -std=c17 recusa (case label does not reduce to an integer constant), embora o GCC aceite esse uso como extensão em outros modos (como o gnu11 da Maratona) e na versão 14. Para tamanhos de arranjos e rótulos de case, use #define N 100 ou uma enumeração: enum { N = 100 };.

    Enumerações¶

    As enumerações (ou enums) na linguagem C são tipos de dados definidos pelo usuário que consistem em conjuntos de constantes inteiras nomeadas. Elas fornecem uma maneira de criar nomes descritivos e significativos para um conjunto de valores inteiros, tornando o código mais legível e fácil de manter.

    Para declarar uma enumeração em C, utiliza-se a palavra-chave enum seguida pelo nome da enumeração e a lista de constantes entre chaves:

    enum nome_enum {
    const1,
    const2,
    const3
};

    Por padrão, a primeira constante recebe o valor 0, a segunda recebe 1, e assim por diante. No entanto, é possível atribuir valores específicos às constantes, como no exemplo a seguir:

    enum direcao {
    NORTE = 10,
    SUL = 20,
    LESTE = 30,
    OESTE = 40
};

    Após definir um tipo de enumeração, é possível declarar variáveis desse tipo:

    1
2
    enum direcao minhaVar;
minhaVar = LESTE; // Atribui o valor 30 à variável

    Características importantes

    • Tamanho em memória: No C17, o tipo inteiro compatível com cada enumeração é escolhido pela implementação, desde que represente seus valores. O tamanho não é obrigatoriamente igual ao de int; consulte sizeof(enum nome).
    • Uso em Expressões: As constantes de enumeração podem ser usadas em qualquer lugar onde a linguagem C permite uma expressão inteira.
    • Escopo: Os identificadores em uma lista de enumeração devem ser distintos de outros identificadores no mesmo escopo com a mesma visibilidade.

    Uma aplicação interessante das enumerações é o uso como flags (sinalizadores). Neste caso, cada constante é definida como uma potência de 2 para permitir a combinação de múltiplas flags usando operadores bit a bit.

    #include <stdio.h>

    As enumerações são particularmente úteis quando:

    • Você tem um conjunto de valores relacionados que não mudarão, como dias da semana, meses, cores, etc.
    • Você precisa de constantes nomeadas para melhorar a legibilidade do código.
    • Você está trabalhando com flags e precisa combinar múltiplos valores.
    • Você quer evitar o uso de números mágicos no código.

    Embora seja possível realizar quase tudo em C sem usar enumerações, elas proporcionam uma maneira elegante e legível de trabalhar com conjuntos de constantes relacionadas, tornando o código mais fácil de entender e manter.

    Sequências de escape¶

    Alguns caracteres podem ser representados como sequências de escape: são conjuntos de dois ou mais caracteres que, na realidade, representam apenas um caractere. Um exemplo de sequência de escape é o \n, utilizado para representar o final de uma linha.

    Qualquer caractere pode ser representado pela sequência de escape \ooo, onde ooo é o número octal do caractere na tabela ASCII1. Outra possibilidade é representar o caractere utilizando a sequência de escape \xhh, onde hh é o número hexadecimal do caractere na tabela ASCII. Assim, a letra A pode ser armazenada como A, ou como \101, que é a representação em octal do valor 65 associado à letra A maiúscula na tabela ASCII, ou como \x41, que é a representação em hexadecimal de 65.

    Há algumas sequências de escape já definidas na linguagem C, para os caracteres mais comuns que não podem ser diretamente digitados.

    Sequência Significado
    \a Alerta (bipe, sino)
    \b Backspace
    \f Avanço/quebra de página
    \n Avanço de linha
    \r Retorno de carro
    \t Tabulação horizontal
    \v Tabulação vertical
    \\ Barra invertida (backslash)
    \' Apóstrofo, ou aspas simples
    \" Aspas duplas
    \? Ponto de interrogação
    \ooo O byte cujo valor numérico está representado como o número octal ooo
    \xhh O byte cujo valor numérico está representado como o número hexadecimal hh

    Arranjos (arrays)¶

    Para cada tipo T, exceto o tipo void, existe um tipo "arranjo de \(N\) elementos do tipo T". Um arranjo é uma coleção de valores, todos do mesmo tipo, armazenados de forma contígua na memória. Os elementos que compõem um arranjo de tamanho \(N\) são indexados por inteiros que variam de 0 até N-1. Por exemplo:

    Declaração de arranjo unidimensional em C
    int faltas[10];  // arranjo com 10 elementos, cada
                 // um do tipo inteiro

faltas[3] = 8;   // O quarto elemento do arranjo recebe
                 // o valor 8

    Um arranjo pode ser inicializado na declaração, com os valores entre chaves. Se houver menos valores que elementos, os elementos restantes recebem zero; se o tamanho for omitido, ele é calculado a partir da quantidade de valores:

    Inicialização de arranjos
    int primos[5] = {2, 3, 5, 7, 11};
int notas[100] = {0};          // todos os 100 elementos valem 0
int dias[] = {31, 28, 31, 30}; // tamanho 4, calculado pelo compilador
int n = sizeof(dias) / sizeof(dias[0]);   // quantidade de elementos: 4

    Um arranjo local automático declarado sem inicialização contém valores indeterminados; lê-los pode causar comportamento indefinido. Arranjos globais ou declarados com static, quando não têm inicialização explícita, recebem inicialização com zero.

    Veja bem, preste atenção!

    A linguagem não verifica se o índice está dentro dos limites do arranjo. Em um arranjo com 10 elementos, faltas[10] (o décimo primeiro elemento, que não existe) e faltas[-1] compilam normalmente, e acessam a memória que estiver naquela posição. O resultado é comportamento indefinido: o programa pode escrever valores sem sentido, alterar outras variáveis, ser encerrado com Segmentation fault, ou parecer funcionar. Em um laço que percorre um arranjo de N elementos, a condição é i < N, e não i <= N.

    Arranjos também não podem ser atribuídos nem comparados de uma só vez: a = b não compila, e a == b compara endereços, como mostra a seção sobre ponteiros. Para copiar um arranjo, copie elemento por elemento (ou use a função memcpy, de string.h).

    Arranjos com mais de uma dimensão (às vezes chamados de matrizes) são definidos como um "arranjo de arranjos".

    Declaração de arranjo bidimensional em C
    int a[10][8];  // arranjo de 10 elementos, cada um do tipo
               // 'arranjo de 8 elementos inteiros'

int m[2][3] = {{1, 2, 3},
               {4, 5, 6}};   // m[1][2] vale 6

    Cadeias de caracteres¶

    Em C, não existe um tipo de dado específico para textos. Uma cadeia de caracteres (string) é representada como um arranjo de char, em que o final do texto é marcado pelo caractere nulo ('\0'). Por isso, para guardar um nome com até 49 letras, é preciso declarar char nome[50];: uma posição a mais, para o '\0'.

    char palavra[4] = "Sol";  // Ocupa 4 bytes: 'S', 'o', 'l' e '\0'
char c = 'a';             // aspas simples: um caractere
char s[] = "abc";         // aspas duplas: uma cadeia (4 bytes)

    Como são arranjos, as cadeias não podem ser atribuídas com = nem comparadas com ==: para isso, existem as funções strcpy e strcmp, do cabeçalho string.h. As cadeias são o assunto da seção Cadeias de caracteres, que mostra como declará-las, lê-las, copiá-las, compará-las, convertê-las em números e dividi-las em partes.

    Estruturas¶

    Estruturas agregam o armazenamento de múltiplos itens de dados, de mesmo tipo ou não, em um único bloco de memória referenciado por uma única variável. O exemplo abaixo cria uma estrutura chamada aniversario para armazenar o nome e a data de nascimento de uma pessoa; em seguida, temos a declaração de uma variável chamada Abelardo do tipo struct aniversario.

    Exemplo de estrutura em C
    1

    struct aniversario {
    char nome[20];
    int dia;
    int mes;
    int ano;
};

struct aniversario Abelardo;

    Uma estrutura também pode ser inicializada na declaração, com os valores na ordem dos membros ou, a partir do C99, indicando o nome de cada membro (os membros não mencionados recebem zero):

    Inicialização de estruturas
    struct aniversario ana = {"Ana Souza", 21, 7, 2004};
struct aniversario bia = {.nome = "Bia Lima", .dia = 2, .mes = 12, .ano = 2005};

    Diferentemente dos arranjos, uma estrutura pode ser atribuída a outra do mesmo tipo: bia = ana; copia todos os membros, inclusive os arranjos que estão dentro dela. Mas duas estruturas não podem ser comparadas com ==: é preciso comparar membro por membro.

    Acessando membros de estruturas¶

    As estruturas em C são uma forma poderosa de organizar dados relacionados sob um único nome. Quando trabalhamos com o exemplo da estrutura aniversario, precisamos entender como acessar e manipular cada um dos membros individuais dessa estrutura.

    Para acessar os membros de uma estrutura em C, utilizamos o operador ponto (.). Este operador conecta o nome da variável da estrutura com o membro específico que desejamos acessar.

    Considerando a estrutura aniversario e a variável Abelardo do exemplo, podemos acessar e atribuir valores aos membros da seguinte forma:

    Ponteiros¶

    Para cada tipo T, existe também o tipo "ponteiro para T": uma variável que guarda o endereço de memória de uma variável do tipo T. Ponteiros são declarados com um asterisco antes do nome da variável, como em int *p;. Eles são o assunto da seção Ponteiros e memória, que mostra como declará-los e usá-los, a relação entre ponteiros e arranjos e a alocação dinâmica de memória.

    Sinônimos de tipos (typedef)¶

    O comando typedef em C é usado para criar sinônimos ou "aliases" para tipos de dados existentes. Ele permite renomear tipos de dados, facilitando a organização e o entendimento do código.

    Veja bem, preste atenção!

    É importante ressaltar que o typedef não cria um novo tipo de dado, apenas permite que um tipo existente seja denominado de uma forma diferente.

    A sintaxe básica do typedef é:

    typedef <tipo_existente> <novo_nome>;

    O uso de typedef em programação oferece diversas vantagens. Em primeiro lugar, ele aprimora a legibilidade do código ao simplificar declarações complexas, facilitando o entendimento; em segundo lugar, facilita a manutenção, permitindo que a alteração de um tipo de dado seja feita em um único local, sem a necessidade de modificar cada instância de uso; por fim, ele simplifica as declarações de estruturas, reduzindo a necessidade de utilizar repetidamente a palavra-chave struct.
