    Funções¶

    À medida que os programas crescem, escrever tudo dentro de main deixa de ser viável: o código fica longo, difícil de entender, e trechos parecidos começam a se repetir em vários lugares. Funções resolvem esses problemas. Uma função é um bloco de código com um nome, que recebe dados de entrada (os parâmetros), executa uma tarefa e, opcionalmente, devolve um resultado (o valor de retorno). Depois de escrita, ela pode ser chamada quantas vezes for necessário, de qualquer parte do programa.

    A ideia de dar um nome a um trecho de um algoritmo para reutilizá-lo, na forma de funções e procedimentos, foi apresentada na seção sobre reuso. Dividir um programa em funções traz várias vantagens:

    • Reutilização: um trecho de código escrito uma vez pode ser usado em vários lugares, sem repetição;
    • Legibilidade: um nome bem escolhido, como calcula_media ou le_matriz, explica o que um trecho de código faz, sem que seja preciso ler cada linha dele;
    • Manutenção: se houver um erro no cálculo da média, ele é corrigido em um único lugar;
    • Teste: cada função pode ser testada isoladamente, com entradas conhecidas.

    Você já usa funções desde o primeiro programa: printf, scanf, sqrt e strlen são funções da biblioteca padrão, e o próprio main é uma função, chamada automaticamente quando o programa começa.

    Definindo e chamando funções¶

    A definição de uma função tem a forma:

    tipo_de_retorno nome(lista_de_parâmetros)
{
    // corpo da função
}
    • O tipo de retorno indica o tipo do valor devolvido pela função. Uma função que não devolve nada tem tipo de retorno void;
    • O nome segue as mesmas regras dos nomes de variáveis;
    • A lista de parâmetros declara, separados por vírgulas, o tipo e o nome de cada dado que a função recebe. Uma função sem parâmetros tem a lista (void);
    • O corpo contém as instruções executadas quando a função é chamada. A instrução return encerra a função e devolve o valor indicado para quem a chamou.

    #include <stdio.h>

int quadrado(int x)
{
    return x * x;
}

void linha(int tamanho)
{
    for (int i = 0; i < tamanho; i++) {
        putchar('-');
    }
    putchar('\n');
}

int main(void)
{
    int a = 7;
    int q = quadrado(a);

    linha(20);
    printf("O quadrado de %d é %d\n", a, q);
    printf("O quadrado de 12 é %d\n", quadrado(12));
    printf("Soma de quadrados: %d\n", quadrado(3) + quadrado(4));
    linha(20);
    return 0;
}

    Na chamada quadrado(a), o valor de a (o argumento) é usado para inicializar o parâmetro x, o corpo da função é executado, e o valor devolvido pelo return toma o lugar da chamada na expressão. Como a chamada de uma função que devolve um valor é uma expressão, ela pode ser usada em qualquer lugar onde um valor desse tipo seria aceito: em uma atribuição, como argumento de printf, como parte de uma conta ou como argumento de outra função.

    A função linha tem tipo de retorno void: ela executa uma tarefa (escrever uma linha de traços), mas não devolve nenhum valor. Por isso, ela é chamada como uma instrução isolada, e não faz sentido usá-la em uma expressão. Em uma função void, a instrução return; (sem valor) pode ser usada para encerrar a função antes do final do corpo.

    Veja bem, preste atenção!

    Uma função com tipo de retorno diferente de void precisa executar um return com um valor em todos os caminhos possíveis. Na função abaixo, quando x vale zero, a execução chega ao final do corpo sem passar por nenhum return:

    int sinal(int x)
{
    if (x > 0) {
        return 1;
    } else if (x < 0) {
        return -1;
    }
}   // e se x == 0?

    O programa compila (com o aviso control reaches end of non-void function, quando se usa -Wall), mas o valor usado por quem chamou é imprevisível. Com o mesmo código, sinal(0) resultou em 4198729 no GCC 13.2 sem otimizações, e em 0 no GCC 14.2 com -O2. Um programa que funciona "por sorte" em um computador pode falhar no juiz online.

    A única exceção é main: se a execução chegar ao final de main sem um return, o efeito é o mesmo de return 0;.

    Cada parâmetro e cada variável declarada no corpo de uma função são variáveis locais: elas existem apenas enquanto a função está sendo executada e não são visíveis fora dela. Duas funções diferentes podem ter variáveis com o mesmo nome sem nenhum conflito. Os conceitos de escopo e tempo de vida são apresentados na seção sobre variáveis, e a seção Variáveis locais, globais e estáticas, mais adiante, mostra os outros tipos de variáveis que interessam no estudo de funções.

    Funções sem parâmetros¶

    Uma função que não recebe parâmetros deve ser declarada com void entre os parênteses, como em int main(void). No C17, uma declaração com parênteses vazios, como int sorteia();, não informa os tipos nem a quantidade de parâmetros para a verificação das chamadas. Isso pode deixar passar uma chamada incorreta:

    #include <stdio.h>

int sorteia()
{
    return 4;
}

int main(void)
{
    printf("%d\n", sorteia(10, 20));   // pode compilar; a chamada é inválida
    return 0;
}

    Com int sorteia(void), a chamada sorteia(10, 20) é rejeitada pelo compilador (too many arguments to function 'sorteia'). Por isso, prefira sempre (void) nas funções sem parâmetros.

    A definição de sorteia do exemplo não recebe parâmetros. Chamar essa função com dois argumentos tem comportamento indefinido no C17, mesmo que o compilador aceite o código. A ausência de um diagnóstico não torna a chamada correta.

    Essa regra muda no C23

    O exemplo acima segue o C17. No C23, uma lista de parâmetros vazia também significa que a função não recebe argumentos, e a chamada com dois argumentos deve ser diagnosticada. Ao comparar comportamentos de compiladores, selecione explicitamente o padrão com -std=c17 ou -std=c23.

    Declaração e definição¶

    O compilador lê o código de cima para baixo e precisa conhecer uma função antes de compilar uma chamada a ela. Por isso, até aqui, as funções foram escritas antes de main. Quando isso não for conveniente, a função pode ser declarada antes de ser usada e definida depois. A declaração, também chamada de protótipo, é apenas a primeira linha da função, terminada com ponto e vírgula:

    #include <stdio.h>

double media(double a, double b);   // declaração (protótipo)

int main(void)
{
    printf("%.2f\n", media(7.0, 8.5));   // 7.75
    return 0;
}

double media(double a, double b)    // definição
{
    return (a + b) / 2;
}

    A declaração informa ao compilador o nome da função, os tipos dos parâmetros e o tipo de retorno, o que é suficiente para verificar se as chamadas estão corretas. O corpo pode estar mais adiante no mesmo arquivo, ou até em outro arquivo. Os cabeçalhos da biblioteca padrão, como stdio.h e math.h, são basicamente coleções de protótipos: é por isso que é preciso incluí-los antes de usar printf ou sqrt.

    Veja bem, preste atenção!

    O que acontece quando uma função é chamada antes de ser declarada? Versões antigas da linguagem permitiam isso, e o compilador "adivinhava" que a função devolvia um int. Esse comportamento foi removido da linguagem em 1999, mas os compiladores demoraram a deixar de aceitá-lo:

    int main(void)
{
    printf("%d\n", dobro(21));   // dobro ainda não foi declarada
    return 0;
}

int dobro(int x) { return 2 * x; }

    O GCC 13.2 apenas avisa (warning: implicit declaration of function 'dobro') e gera o programa. O GCC 14.2 trata a mesma situação como erro (error: implicit declaration of function 'dobro'), e o programa não compila. Um código que compila no seu computador pode não compilar no juiz online. Não ignore esse aviso: ele também aparece quando você esquece de incluir um cabeçalho, como math.h antes de usar sqrt.

Marcar como static tudo o que não faz parte da "interface" de um arquivo é uma boa prática.

    Passagem de parâmetros¶

    Esta é uma das partes mais importantes sobre funções: entender o que acontece com uma variável quando ela é passada como argumento. A regra é simples: todos os argumentos são passados por valor. A função sempre recebe uma cópia do valor do argumento. Quando a função precisa alterar uma variável de quem a chamou, ela recebe uma cópia do endereço dessa variável, e acessa a variável original por meio dele.

    Passagem por valor¶

    Na passagem por valor, o parâmetro é uma nova variável, inicializada com uma cópia do valor do argumento. A função trabalha com essa cópia, e qualquer alteração feita no parâmetro não afeta a variável usada na chamada:

    #include <stdio.h>

void dobra(int x)
{
    x = x * 2;
    printf("Dentro de dobra: x = %d\n", x);
}

void troca(int a, int b)
{
    int aux = a;
    a = b;
    b = aux;
}

int main(void)
{
    int n = 5;
    dobra(n);
    printf("Depois de dobra: n = %d\n", n);

    int p = 1, q = 2;
    troca(p, q);
    printf("Depois de troca: p = %d, q = %d\n", p, q);
    return 0;
}

    Dentro de dobra: x = 10
Depois de dobra: n = 5
Depois de troca: p = 1, q = 2

    A função dobra dobrou o valor de x, mas n continuou valendo 5: x é outra variável, que apenas começou com o mesmo valor de n. Pelo mesmo motivo, a função troca trocou os valores de a e b, que são cópias, e p e q ficaram como estavam. Não há erro de compilação: o programa simplesmente não faz o que parece fazer.

    A passagem por valor é adequada quando a função só precisa ler o argumento. Ela tem uma vantagem importante: a função não tem como alterar, nem por engano, as variáveis de quem a chamou.

    Passagem por endereço (ponteiros)¶

    Para que uma função consiga alterar uma variável de quem a chamou, a função recebe o endereço da variável, em um parâmetro do tipo ponteiro. Na chamada, o endereço é obtido com o operador &; dentro da função, a variável original é acessada com o operador de desreferência *. Essa técnica é chamada de passagem por endereço, ou de passagem por referência:

    #include <stdio.h>

void dobra(int *x)
{
    *x = *x * 2;
    printf("Dentro de dobra: *x = %d\n", *x);
}

void troca(int *a, int *b)
{
    int aux = *a;
    *a = *b;
    *b = aux;
}

int main(void)
{
    int n = 5;
    dobra(&n);
    printf("Depois de dobra: n = %d\n", n);

    int p = 1, q = 2;
    troca(&p, &q);
    printf("Depois de troca: p = %d, q = %d\n", p, q);
    return 0;
}

    Dentro de dobra: *x = 10
Depois de dobra: n = 10
Depois de troca: p = 2, q = 1

    Agora as duas funções fazem o que prometem. Repare que a regra da passagem por valor continua valendo: x é uma variável nova, que recebeu uma cópia do endereço de n. Mas, como a cópia aponta para o mesmo lugar, *x é a própria variável n, e alterar *x altera n.

    Repare também que a chamada deixa explícito que a variável pode ser alterada: quem lê troca(&p, &q) sabe, sem olhar a definição da função, que p e q podem mudar.

    Veja bem, preste atenção!

    Como o parâmetro guarda um endereço, o argumento precisa ser o endereço de uma variável. Uma chamada como dobra(&5) não compila (lvalue required as unary '&' operand), porque o número 5 não está guardado em uma variável que possa ser alterada.

    O erro mais comum, no entanto, é esquecer o &. Em dobra(n), o valor 5 é passado onde se esperava um endereço, e a função tenta alterar o conteúdo do "endereço 5". O GCC 13.2 apenas avisa (passing argument 1 of 'dobra' makes pointer from integer without a cast), gera o programa, e ele é encerrado com Segmentation fault; o GCC 14.2 trata a mesma situação como erro. Os avisos do compilador existem por um motivo: compile sempre com -Wall -Wextra e leia o que ele diz.

    Você já usou isso: scanf¶

    A passagem por endereço explica por que é preciso escrever scanf("%d", &n), com &, mas printf("%d", n), sem. A função printf só precisa ler o valor de n, e uma cópia é suficiente. A função scanf precisa guardar um valor em n, e para isso precisa saber onde n está na memória.

    Funções escritas por você podem seguir o mesmo modelo: devolver um código indicando se deu certo, e entregar os dados lidos ou calculados por meio de parâmetros ponteiros.     #include <stdio.h>

int le_intervalo(int *inicio, int *fim)
{
    if (scanf("%d %d", inicio, fim) != 2) {
        return 0;                   // falha na leitura
    }
    if (*inicio > *fim) {
        int aux = *inicio;
        *inicio = *fim;
        *fim = aux;
    }
    return 1;                       // sucesso
}

int main(void)
{
    int a, b;
    while (le_intervalo(&a, &b)) {
        printf("De %d até %d\n", a, b);
    }
    return 0;
}

    Dentro de le_intervalo, inicio e fim já são endereços, e por isso são passados para scanf sem &. Escrever &inicio passaria o endereço do ponteiro, e não o endereço da variável a.

    Comparando as duas formas¶

    O diagrama abaixo mostra a memória durante a execução de troca em cada uma das formas:

    • Por valor, a e b são variáveis novas, com cópias dos valores de p e q. A troca acontece nas cópias, que deixam de existir quando a função termina;
    • Por endereço, a e b também são variáveis novas, mas guardam os endereços de p e q. A troca acontece em *a e *b, que são as próprias p e q.

    Um teste de mesa das duas versões deixa a diferença ainda mais clara. Na passagem por valor, a, b e aux são variáveis da função, e p e q nunca mudam:

    Momento p q a b aux
    Antes da chamada 1 2
    Início da função (cópias) 1 2 1 2
    Depois de aux = a 1 2 1 2 1
    Depois de a = b 1 2 2 2 1
    Depois de b = aux 1 2 2 1 1
    Depois da chamada 1 2 (destruída) (destruída) (destruída)

    Na passagem por endereço, a e b guardam os endereços de p e q (representados aqui como &p e &q) e nunca mudam: o que muda são as variáveis apontadas por eles:

    Momento p (= *a) q (= *b) a b aux
    Antes da chamada 1 2
    Início da função (cópias dos endereços) 1 2 &p &q
    Depois de aux = *a 1 2 &p &q 1
    Depois de *a = *b 2 2 &p &q 1
    Depois de *b = aux 2 1 &p &q 1
    Depois da chamada 2 1 (destruída) (destruída) (destruída)

    Ponteiros para constantes¶

    Às vezes, uma função recebe um endereço apenas para evitar a cópia de um dado grande, e não para alterá-lo. Nesses casos, o parâmetro deve ser declarado como ponteiro para constante (const int *x): a função recebe o endereço, mas o compilador impede qualquer alteração no valor apontado:

    void mostra(const int *x)
{
    printf("%d\n", *x);   // leitura: permitido
    *x = 0;               // erro: assignment of read-only location '*x'
}

    O const impede alterações no objeto por meio desse parâmetro. Na declaração double distancia(const struct ponto *a, const struct ponto *b), os pontos são acessados para leitura. Outros ponteiros modificáveis para o mesmo objeto ainda podem alterá-lo, se ele não tiver sido definido com const. As seções a seguir mostram esse uso com arranjos, cadeias e estruturas.

    Arranjos como parâmetros¶

Quando o nome de um arranjo é usado como argumento, o que a função recebe é o endereço do primeiro elemento. Por isso, uma função que altera os elementos de um arranjo recebido como parâmetro altera o arranjo original:

double media(const double valores[], int n)       // apenas leitura
{
    double soma = 0;
    for (int i = 0; i < n; i++) {
        soma += valores[i];
    }
    return soma / n;
}

void normaliza(double valores[], int n, double maximo)   // altera o original
{
    for (int i = 0; i < n; i++) {
        valores[i] = valores[i] / maximo * 10;
    }
}

int main(void)
{
    double notas[] = {40, 75, 90, 60};
    int n = sizeof(notas) / sizeof(notas[0]);

    printf("Média: %.2f\n", media(notas, n));        // 66.25

    normaliza(notas, n, 100);
    printf("Depois de normalizar:");
    for (int i = 0; i < n; i++) {
        printf(" %.1f", notas[i]);                   // 4.0 7.5 9.0 6.0
    }
    printf("\n");
    return 0;
}
    • media recebe o arranjo como const double valores[]: lê todos os elementos e não pode alterá-los;
    • normaliza recebe o arranjo como double valores[]: altera os elementos do arranjo notas de main, sem nenhum & na chamada.

    Na lista de parâmetros, as declarações double valores[] e double *valores são equivalentes: nos dois casos, o parâmetro é um ponteiro para o primeiro elemento. A forma com colchetes é preferida por deixar claro que a função espera um arranjo, e não o endereço de uma única variável.

    Como a função recebe apenas um endereço, ela não tem como saber quantos elementos o arranjo tem. Por isso, o tamanho precisa ser passado em outro parâmetro, como o n dos exemplos.

    sizeof não funciona com arranjos recebidos como parâmetro

    Dentro de main, sizeof(notas) é o tamanho do arranjo inteiro, em bytes. Dentro de uma função, sizeof aplicado ao parâmetro devolve o tamanho de um ponteiro:

    void tamanho(int v[])
{
    printf("Dentro da função: %zu bytes\n", sizeof(v));   // 8
}

int main(void)
{
    int v[10];
    printf("Em main: %zu bytes\n", sizeof(v));            // 40
    tamanho(v);
    return 0;
}

    O compilador avisa ('sizeof' on array function parameter 'v' will return size of 'int *'). Calcule o tamanho em quem declarou o arranjo e passe-o como argumento.

int conta_vogais(const char *s)
{
    int total = 0;
    for (int i = 0; s[i] != '\0'; i++) {
        char c = tolower((unsigned char) s[i]);

{

    printf("%s\n", frase);                            // PROGRAMAR EM C

    A função conta_vogais recebe const char *, porque apenas lê a cadeia; com isso, ela aceita tanto arranjos quanto literais, como "abacaxi".     Não altere literais

    Um literal como "abc" fica guardado em uma área de memória que não deve ser alterada. O código abaixo compila sem nenhum aviso, mas o programa é encerrado com Segmentation fault:

    char *p = "abc";
para_maiusculas(p);   // tenta alterar o literal

    Para ter uma cadeia que pode ser alterada, declare um arranjo, que recebe uma cópia do literal: char p[] = "abc";. E, para que o compilador ajude a evitar o problema, declare como const char * todo ponteiro que aponta para um literal.

#include <stdio.h>

struct ponto {
    double x;
    double y;
};

void mostra(struct ponto p)                        // recebe uma cópia
{
    printf("(%.1f, %.1f)\n", p.x, p.y);
}

void desloca(struct ponto *p, double dx, double dy)   // altera o original
{
    p->x += dx;
    p->y += dy;
}

double distancia(const struct ponto *a, const struct ponto *b)   // leitura, sem cópia
{
    return sqrt((a->x - b->x) * (a->x - b->x) + (a->y - b->y) * (a->y - b->y));
}

struct ponto ponto_medio(struct ponto a, struct ponto b)   // devolve uma estrutura
{
    struct ponto m = {(a.x + b.x) / 2, (a.y + b.y) / 2};
    return m;
}

int main(void)
{
    struct ponto a = {1.0, 2.0};
    struct ponto b = {4.0, 6.0};

    printf("Distância: %.1f\n", distancia(&a, &b));   // 5.0

    struct ponto m = ponto_medio(a, b);
    mostra(m);                                         // (2.5, 4.0)

    desloca(&a, 10, 10);
    mostra(a);                                         // (11.0, 12.0)
    return 0;
}
    • mostra recebe a estrutura por valor. Para uma estrutura pequena, como um ponto com dois double, a cópia não custa quase nada;
    • desloca recebe o endereço da estrutura e altera os membros do ponto a de main;
    • distancia recebe ponteiros para constantes: lê os pontos sem copiá-los e sem poder alterá-los. Essa é a forma recomendada para estruturas grandes, como uma estrutura com um nome de 100 caracteres;
    • ponto_medio devolve uma estrutura. Isso é permitido e é uma forma prática de uma função produzir um dado composto.

    Lembre-se de compilar com -lm quando usar funções de math.h, como sqrt.

    Nunca devolva o endereço de uma variável local¶

    Uma função pode devolver um ponteiro, mas nunca um ponteiro para uma de suas variáveis locais. As variáveis locais deixam de existir quando a função termina, e o endereço devolvido passa a apontar para uma área de memória inválida:

    Incorreto

    int *cria_vetor(void)
{
    int v[3] = {1, 2, 3};
    return v;   // v deixa de existir aqui
}

int main(void)
{
    int *p = cria_vetor();
    printf("%d\n", p[0]);   // Segmentation fault
    return 0;
}

    O compilador avisa (function returns address of local variable). Nos testes com o GCC 13.2 e o GCC 14.2, o programa foi encerrado com Segmentation fault; em outras situações, ele pode escrever valores sem sentido, ou até parecer funcionar.

    A forma mais comum de resolver esse problema é inverter a responsabilidade: quem chama declara o arranjo e passa o seu endereço (e o seu tamanho) para a função preenchê-lo, como faz a função snprintf:

    Correto

    void formata_hora(int segundos, char destino[], size_t tamanho)
{
    snprintf(destino, tamanho, "%02d:%02d:%02d",
             segundos / 3600, segundos / 60 % 60, segundos % 60);
}

int main(void)
{
    char texto[9];
    formata_hora(3725, texto, sizeof(texto));
    printf("%s\n", texto);   // 01:02:05
    return 0;
}

    Outra solução é a alocação dinâmica de memória, com a função malloc: a memória alocada continua existindo depois que a função termina, e quem chama fica responsável por liberá-la com free quando não precisar mais dela.

    Variáveis locais, globais e estáticas¶

    Além das variáveis locais, que existem apenas durante a execução da função, há outros dois tipos de variáveis que interessam no estudo de funções:

    • Variáveis globais são declaradas fora de qualquer função. Elas existem durante toda a execução do programa e podem ser acessadas por qualquer função do arquivo;

Elas só podem ser acessadas dentro da função, como as locais, mas existem durante toda a execução do programa, como as globais: são inicializadas uma única vez, e mantêm o valor entre uma chamada e outra.

    Veja bem, preste atenção!

    Variáveis globais devem ser evitadas. Como qualquer função pode alterá-las, fica difícil saber quem mudou o valor e quando, e a função deixa de poder ser entendida (e testada) apenas pelos seus parâmetros e pelo seu valor de retorno. Prefira passar os dados por parâmetros. As exceções aceitáveis são constantes usadas por todo o programa e, em programação competitiva, arranjos muito grandes: declarados como globais, eles não ocupam a pilha de execução, que tem tamanho limitado, e são inicializados automaticamente com zero.

    Recursão¶

    Uma função pode chamar a si mesma. Isso se chama recursão, e é uma forma natural de resolver problemas que podem ser divididos em versões menores do mesmo problema.     #include <stdio.h>

long long fatorial(int n)
{
    if (n <= 1) {                   // caso base
        return 1;
    }
    return n * fatorial(n - 1);     // caso recursivo
}

int mdc(int a, int b)
{
    if (b == 0) {
        return a;
    }
    return mdc(b, a % b);
}

int main(void)
{
    printf("5! = %lld\n", fatorial(5));                // 120
    printf("20! = %lld\n", fatorial(20));              // 2432902008176640000
    printf("mdc(48, 18) = %d\n", mdc(48, 18));         // 6
    return 0;
}

    A função fatorial usa a definição \(n! = n \times (n-1)!\), com \(1! = 1\). A função mdc usa o algoritmo de Euclides: o máximo divisor comum de \(a\) e \(b\) é igual ao de \(b\) e \(a \bmod b\), e o de \(a\) e \(0\) é \(a\).

    Cada chamada recursiva tem as suas próprias variáveis locais. Na execução de fatorial(5), existem, ao mesmo tempo, cinco variáveis n diferentes (com os valores 5, 4, 3, 2 e 1), uma para cada chamada ainda não terminada.

    Veja bem, preste atenção!

    Cada chamada de função ocupa um espaço na pilha de execução, que só é liberado quando a chamada termina. Uma recursão sem caso base (ou com um caso base que nunca é atingido) continua chamando a função até esgotar a pilha, e o programa é encerrado com um erro de estouro de pilha (stack overflow), que normalmente aparece como Segmentation fault. O mesmo pode acontecer com uma recursão correta, mas muito profunda (centenas de milhares de níveis). Nesses casos, reescreva a função com um laço.

    Ordenando com qsort¶

    O uso mais frequente de ponteiros para funções é a função qsort, de stdlib.h, que ordena um arranjo de qualquer tipo. Como qsort não sabe o que está ordenando, ela recebe uma função de comparação, escrita por você, que diz qual de dois elementos deve vir primeiro:

    void qsort(void *base, size_t quantidade, size_t tamanho_do_elemento,
           int (*compara)(const void *, const void *));

    O nome não obriga a implementação a usar quicksort, e o padrão C não fixa uma complexidade para qsort. Ela também não garante uma ordenação estável: elementos considerados iguais podem trocar de ordem. Quando for preciso preservar a ordem de entrada entre empates, acrescente a posição original como último critério de comparação.

    int n = sizeof(v) / sizeof(v[0]);

    qsort(v, n, sizeof(v[0]), crescente);
    for (int i = 0; i < n; i++) printf("%d ", v[i]);
    printf("\n");

    qsort(v, n, sizeof(v[0]), decrescente);
    for (int i = 0; i < n; i++) printf("%d ", v[i]);
    printf("\n");

    struct aluno turma[] = {{"Bruno", 7}, {"Ana", 9}, {"Carla", 7}, {"Davi", 9}};
    qsort(turma, 4, sizeof(turma[0]), por_nota_e_nome);
    for (int i = 0; i < 4; i++) {
        printf("%s (%d)\n", turma[i].nome, turma[i].nota);
    }
    return 0;
}

    • Em crescente, os ponteiros genéricos são convertidos para const int * e desreferenciados. A expressão (x > y) - (x < y) vale -1, 0 ou 1, conforme x seja menor, igual ou maior que y;
    • decrescente reaproveita crescente, trocando a ordem dos argumentos;
    • por_nota_e_nome compara primeiro as notas (em ordem decrescente) e, em caso de empate, os nomes, com strcmp, que segue a mesma convenção de negativo, zero e positivo.

    Cuidado com a subtração na função de comparação

    É comum encontrar funções de comparação escritas como return *(const int *) a - *(const int *) b;. Isso funciona com valores pequenos, como as notas de 0 a 10 do exemplo, mas a subtração pode transbordar quando os valores são grandes, e o sinal do resultado fica errado. Ordenando {INT_MAX, -10, INT_MIN, 5} com essa função, o resultado foi 5 2147483647 -2147483648 -10, que não está em ordem nenhuma. Use comparações, como em crescente.

    #include <stdarg.h>
#include <stdio.h>

int soma(int quantidade, ...)
{
    va_list args;
    va_start(args, quantidade);

    int total = 0;
    for (int i = 0; i < quantidade; i++) {
        total += va_arg(args, int);
    }

    va_end(args);
    return total;
}

int main(void)
{
    printf("%d\n", soma(3, 10, 20, 30));        // 60
    printf("%d\n", soma(5, 1, 2, 3, 4, 5));     // 15
    printf("%d\n", soma(0));                    // 0
    return 0;
}
    • va_list é o tipo da variável que percorre os argumentos extras;
    • va_start prepara essa variável, a partir do último parâmetro fixo (quantidade);
    • cada va_arg(args, int) devolve o próximo argumento, interpretado como um int;
    • va_end encerra a leitura.

    A função não tem como saber quantos argumentos extras recebeu, nem de que tipo eles são: essas informações precisam vir de um parâmetro fixo. Em soma, é a quantidade; em printf, é a cadeia de formato, em que cada %d ou %f indica um argumento e o seu tipo. Se a informação estiver errada, o compilador não tem como detectar o erro, e o resultado é imprevisível. Por isso, prefira funções com parâmetros fixos sempre que possível.

    #include <stdio.h>
#include <stdlib.h>

int main(int argc, char *argv[])
{
    printf("Programa: %s\n", argv[0]);
    printf("Quantidade de argumentos: %d\n", argc - 1);

    int soma = 0;
    for (int i = 1; i < argc; i++) {
        printf("argv[%d] = \"%s\"\n", i, argv[i]);
        soma += atoi(argv[i]);
    }
    printf("Soma: %d\n", soma);
    return 0;
}

    • argc (argument count) é a quantidade de argumentos, incluindo o nome do programa;
    • argv (argument vector) é um arranjo de cadeias de caracteres: argv[0] é o nome do programa, e argv[1] até argv[argc - 1] são os argumentos, na ordem em que foram escritos.

    Os argumentos chegam sempre como cadeias de caracteres, e precisam ser convertidos quando representam números. A função atoi faz essa conversão, mas devolve 0 quando a cadeia não representa um número, como aconteceu com "abc", sem nenhuma indicação de erro. A função strtol permite detectar esse tipo de problema.

    O valor devolvido por main também é usado: ele é entregue ao sistema operacional quando o programa termina. Por convenção, 0 indica que o programa terminou com sucesso, e qualquer outro valor indica um erro. Juízes online costumam considerar um valor diferente de 0 como erro de execução, mesmo que a saída esteja correta.
