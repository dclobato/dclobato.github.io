    Expressões e operadores¶

    Nas subseções a seguir, letras minúsculas como a e b representam valores literais ou nomes de variáveis, o que for apropriado no contexto. Ao avaliar uma expressão, os seguintes operadores podem ser usados. T indica um tipo de dados.

    Expressões e operadores aritméticos¶

    Uma expressão aritmética vai ser construída a partir de operadores aritméticos e variáveis ou constantes numéricas.

    Operador Sintaxe Exemplo e/ou observações
    Adição a + b
    Subtração a - b
    Mais unário +a
    Menos unário (inverso aditivo) -a
    Multiplicação a * b O produto será do tipo com maior precisão entre os fatores
    Divisão a / b O quociente será do tipo com maior precisão entre o divisor e o dividendo
    Módulo a % b Resto da divisão de a por b
    Pré-incremento ++a Incrementa em uma unidade o valor de a e depois utiliza o valor
    Pós-incremento a++ Utiliza o valor de a e depois o incrementa em uma unidade
    Pré-decremento --a Decrementa em uma unidade o valor de a e depois utiliza o valor
    Pós-decremento a-- Utiliza o valor de a e depois o decrementa em uma unidade

    No pré-incremento (++x) ou pré-decremento (--x), o valor da variável é alterado antes de ser utilizado na expressão. Já no pós-incremento (x++) ou pós-decremento (x--), o valor original da variável é usado na expressão antes que o incremento ou decremento ocorra. Essa diferença, embora sutil, pode gerar resultados distintos em operações combinadas, como atribuições ou chamadas de funções. Por exemplo:

int y = x++; // y será 5, x será 6

    Vamos analisar a linha c = a++ + --b;, com os valores iniciais a = 5 e b = 10:

    1. a++ usa o valor atual de a (5) na expressão, e a passa a valer 6;
    2. --b decrementa b de 10 para 9, e usa esse valor (9) na expressão;
    3. A soma é 5 + 9, e c recebe 14.

    No fim, a = 6, b = 9 e c = 14.

    Veja bem, preste atenção!

    Nas expressões abaixo, a mesma variável é modificada mais de uma vez, ou é modificada e lida para outro cálculo, sem sequenciamento entre essas operações. Isso é comportamento indefinido: a linguagem não estabelece um resultado válido. A presença de duas alterações na mesma expressão, por si só, não basta para caracterizar o erro: operadores como &&, || e vírgula podem estabelecer uma sequência entre elas.

    c = a++ + --b + ++a - b--;   // a e b alterados duas vezes
i = i++;                     // i alterado duas vezes
v[i] = i++;                  // i lido e alterado
printf("%d %d\n", x, x++);   // a ordem de avaliação dos argumentos não é definida

    O compilador avisa sobre esses casos quando usado com -Wall (operation on 'a' may be undefined). Se você precisar incrementar uma variável e usar o valor, faça isso em instruções separadas.

    Promoções e conversões entre tipos¶

    Antes de muitas operações, C realiza promoções inteiras: valores de tipos como char e short são convertidos para int, se todos os valores do tipo couberem nele, ou para unsigned int caso contrário. Isso pode acontecer mesmo quando os dois operandos têm o mesmo tipo. Nos ambientes com unsigned char de 8 bits e int de 32 bits, somar dois valores unsigned char produz um int; o resultado só volta a ser um byte se for convertido ou atribuído a uma variável desse tipo.

    As operações aritméticas também aplicam regras para encontrar um tipo comum entre os operandos. Por exemplo, na soma de um int com um double, o inteiro é convertido para double. Para tipos inteiros, a escolha depende da ordem dos tipos e dos intervalos que cada um representa: não existe uma simples escada em que todo tipo com sinal é convertido para o seguinte sem sinal.

    Misturar inteiros com e sem sinal

    Na comparação -1 < 1u, os operandos são int e unsigned int. O -1 é convertido para unsigned int e passa a valer UINT_MAX; por isso, a comparação é falsa. Isso também merece atenção ao comparar índices com tamanhos obtidos por sizeof ou strlen, que usam size_t, um tipo inteiro sem sinal. Verifique valores negativos antes de convertê-los e use tipos adequados ao intervalo dos dados.

    Veja bem, preste atenção!

    Na divisão entre inteiros, o resultado também é inteiro. Guardá-lo depois em uma variável float ou double não recupera a parte fracionária descartada. 5/2 vale 2; para obter 2.5, use 5.0/2, 5/2.0 ou converta um dos operandos antes da divisão.

    Não lembrar desse pequeno detalhe pode acabar produzindo resultados não esperados durante a execução dos programas.

    Incorreto

    float r;
int a, b;

a = 5; b = 2;
r = a / b;     // r = 5/2

    Correto

    float r;
int a, b;

a = 5; b = 2;
r = (float)a / b;     // r = 5.0/2

    Divisão e resto com números negativos¶

    Na divisão entre inteiros, o resultado é truncado em direção ao zero: a parte fracionária é simplesmente descartada. O resto (%) é definido de forma que (a / b) * b + a % b seja igual a a, e por isso ele tem sempre o mesmo sinal do dividendo:

    #include <stdio.h>

int main(void)
{
    printf(" 7 / 2 = %d,  7 %% 2 = %d\n", 7 / 2, 7 % 2);
    printf("-7 / 2 = %d, -7 %% 2 = %d\n", -7 / 2, -7 % 2);
    printf(" 7 / -2 = %d,  7 %% -2 = %d\n", 7 / -2, 7 % -2);

    int n = -7, m = 3;
    printf("resto não negativo de %d por %d: %d\n", n, m, ((n % m) + m) % m);
    return 0;
}

     7 / 2 = 3,  7 % 2 = 1
-7 / 2 = -3, -7 % 2 = -1
 7 / -2 = -3,  7 % -2 = 1
resto não negativo de -7 por 3: 2

    Na divisão euclidiana com divisor positivo, o resto da divisão de \(-7\) por \(3\) é \(2\). Quando precisamos desse resto não negativo, uma forma comum é ((n % m) + m) % m, como na última linha do exemplo. Essa expressão exige m > 0 e que a soma intermediária caiba no tipo. Para evitar que a soma transborde quando m for grande, calcule r = n % m e some m apenas se r < 0. Para verificar se um número é ímpar, prefira n % 2 != 0 a n % 2 == 1, que falha com números negativos.

    Divisão por zero

    No C17, a regra geral é que a divisão por zero tem comportamento indefinido, inclusive com operandos de ponto flutuante. Implementações que seguem as regras adicionais de IEC 60559/IEEE 754, com o tratamento padrão das exceções, podem produzir inf, -inf ou nan em operações com números reais; isso não é uma garantia para qualquer implementação de C. Com inteiros, também é inválida uma divisão cujo quociente não cabe no tipo: em máquinas com int de 32 bits, INT_MIN / -1 e INT_MIN % -1 têm comportamento indefinido. Verifique esses casos antes da operação.

    Arredondamento exato com aritmética inteira¶

    Para calcular e formatar uma razão \(A/B\) (ou um percentual \(100 \times A/B\)) com exatamente \(K\) casas decimais, podemos usar aritmética inteira escalonada. Assim, definimos o arredondamento sem depender da aproximação de double nem do modo de arredondamento usado na formatação de ponto flutuante.

    Para esta fórmula, assumimos \(A \ge 0\), \(B > 0\) e \(K \ge 0\). Definimos o fator de escala como \(S = 10^K\) para razões simples, ou \(S = 10^{K+2}\) para valores percentuais. Ao multiplicar o valor exato por \(S\), reduzimos o problema a encontrar o inteiro \(q\) mais próximo de \(\frac{S \cdot A}{B}\), arredondando empates exatos na metade (\(0,5\)) para cima (round half up).

    A fórmula geral utilizando divisão inteira é:

    \[q = \left\lfloor \frac{2 \cdot S \cdot A + B}{2B} \right\rfloor\]

    Na aritmética modular, escrevendo \(S \cdot A = aB + r\) com \(0 \le r \lt B\), a expressão garante que:

    • \(q = a\), se \(2r \lt B\);
    • \(q = a + 1\), se \(2r \ge B\).

    Em C, todos os cálculos intermediários precisam caber no tipo escolhido, incluindo \(2 \cdot S \cdot A + B\), \(2B\) e a própria potência usada em \(S\). Use long long quando seus limites forem suficientes. O tipo __int128, oferecido por alguns compiladores, é uma extensão e não faz parte do C17. Para imprimir com long long e \(K > 0\), separe a parte inteira (q / S) da fracionária (q % S) e preencha esta última com zeros à esquerda até completar \(K\) dígitos, como em printf("%lld.%0*lld\n", q / S, K, q % S). Para \(K = 0\), imprima apenas a parte inteira.

    #include <stdio.h>

int main(void) {
    long long A = 1;
    long long B = 128;
    int K = 4;

    // Fator de escala para K casas decimais
    long long S_exibicao = 1;
    for (int i = 0; i < K; ++i) {
        S_exibicao *= 10;
    }
    long long S_calculo = S_exibicao * 100; // Fator extra de 100 para percentual

    // Fórmula de arredondamento exato
    long long q = (2 * S_calculo * A + B) / (2 * B);

    // Impressão separando parte inteira e fracionária
    printf("%lld.%0*lld\n", q / S_exibicao, K, q % S_exibicao);

    return 0;
}

    Operadores lógicos¶

    Em C, as condições não precisam ter o tipo bool: qualquer valor numérico ou ponteiro pode ser usado. Zero é falso e qualquer valor numérico diferente de zero é verdadeiro; para ponteiros, o ponteiro nulo é falso. Por isso, if (x) é equivalente a if (x != 0), e if (!x), a if (x == 0). Os operadores lógicos e relacionais devolvem int: 1 para verdadeiro e 0 para falso.

        printf("42 é verdadeiro\n");

    O tipo bool, com os valores true e false, existe desde o C99, mas apenas como um apelido: é preciso incluir o cabeçalho stdbool.h para usá-lo (a partir do C23, bool, true e false são palavras-chave). Um bool guarda apenas 0 ou 1, e os operadores continuam devolvendo int.

    Em C, a avaliação de operadores lógicos como && (E lógico) e || (OU lógico) segue uma estratégia conhecida como "curto-circuito". Esse mecanismo otimiza a execução do código ao interromper a avaliação de uma expressão lógica assim que o resultado final pode ser determinado de forma inequívoca.

    No caso do operador &&, a avaliação ocorre da esquerda para a direita. Se o primeiro operando for avaliado como falso, o resultado final da expressão será necessariamente falso, independentemente do valor do segundo operando. Portanto, o segundo operando não é avaliado, evitando cálculos desnecessários e possíveis efeitos colaterais. Um exemplo prático seria a verificação de um ponteiro antes de acessar a memória que ele aponta: if (ptr != NULL && *ptr == 10). Se ptr for NULL, a segunda parte da condição (*ptr == 10) não será avaliada, evitando um erro de acesso à memória inválida.

    De forma semelhante, o operador || também utiliza o curto-circuito. Se o primeiro operando for avaliado como verdadeiro, o resultado final da expressão será necessariamente verdadeiro, independentemente do valor do segundo operando. Logo, o segundo operando não é avaliado. Um exemplo comum é a verificação de múltiplas condições alternativas: if (opcao == 'a' || opcao == 'b' || opcao == 'c'). Se opcao for igual a a, as outras comparações não serão realizadas.

    Essa característica dos operadores lógicos em C não apenas melhora a eficiência do código, mas também permite escrever expressões mais seguras, prevenindo erros que poderiam ocorrer se todos os operandos fossem avaliados indiscriminadamente.

    Operadores relacionais¶

    Os operadores relacionais devolvem um valor do tipo int: 1 se a relação é verdadeira, 0 se é falsa.

    Operação Sintaxe Exemplo e/ou observações
    Igual a a == b a igual a b
    Não igual a
    (diferente de)    		 a != b a diferente de b
    Maior que a > b a maior que b
    Menor que a < b a menor que b
    Maior ou igual a a >= b a maior ou igual a b
    Menor ou igual a a <= b a menor ou igual a b

    Em C, o operador de igualdade é um sinal de igual duplo (==), enquanto o sinal de igual simples (=) é utilizado para atribuição. No início, é comum confundir os sinais, então cuidado e atenção! Se você acidentalmente usar = em vez de == dentro de uma condição, poderá ter resultados inesperados.

    Por exemplo, a expressão abaixo não verifica se a é igual a b, mas sim atribui b a a. Como a atribuição retorna o valor atribuído, a condição será verdadeira sempre que b for diferente de zero:

    if (a = b) {  // ERRO: deveria ser "a == b"
    printf("A condição é verdadeira!\n");
}

    Se b for diferente de zero, a receberá b, e a condição será avaliada como verdadeira. Esse erro pode causar um comportamento inesperado no código. Para verificar a igualdade corretamente, sempre use ==:

    if (a == b) {  // Comparação correta
    printf("A condição é verdadeira!\n");
}

    Veja bem, preste atenção!

    Se você quer saber se um número está entre outros dois, a expressão usada na matemática (\(10 < n < 50\)) não vai funcionar em C. Se você usar essa expressão, o compilador vai avaliar a primeira parte (\(10 < n\)) e o resultado dessa comparação será comparado com 50.

    A forma correta envolve o operador AND (&&): 10 < n && n < 50.

    Cuidado ao comparar números reais

    Os números reais (float e double) são guardados de forma aproximada, em binário, e muitos valores simples, como 0,1, não têm representação exata. Por isso, contas que deveriam dar resultados iguais podem diferir na última casa:

    double a = 0.1 + 0.2;
printf("%.17f\n", a);                  // 0.30000000000000004
printf("%d\n", a == 0.3);              // 0
printf("%d\n", fabs(a - 0.3) < 1e-9);  // 1

    Em vez de comparar números reais com ==, verifique se a diferença entre eles é menor que uma tolerância pequena, com a função fabs (valor absoluto de um double), de math.h.

    Operadores de bit¶

    Você sabia?

    Os operadores de deslocamento podem ser usados para efetuar multiplicação e divisão.

    Suponha que temos um número inteiro a = 5. Em representação binária, 5 é 00000101. Agora, vamos realizar um deslocamento à esquerda de 2 bits (a << 2). O resultado são os bits de a "empurrados" 2 posições para a esquerda, resultando em 00010100. Os bits vazios à direita são preenchidos com zeros. Como 00010100 em binário corresponde a 20 em decimal, 5 << 2 resulta em 20.

    Usando o mesmo número a = 5 (binário 00000101), um deslocamento à direita de 1 bit (a >> 1) resulta em 00000010, que vale 2. Para valores sem sinal ou valores com sinal não negativos, o resultado corresponde à divisão inteira por uma potência de 2. No C17, deslocar um valor com sinal negativo para a direita tem resultado definido pela implementação; no GCC, o bit de sinal é replicado.

    Resumo:

    • a << b: para valores sem sinal, multiplica por \(2^b\) com redução ao intervalo do tipo; para valores com sinal, exige a >= 0 e resultado representável nesse tipo;
    • a >> b: divide por \(2^b\) para valores sem sinal ou com sinal não negativos. Para valores com sinal negativos, consulte as regras da implementação.

    Nos dois operadores, b precisa ser não negativo e menor que a largura do operando esquerdo após as promoções inteiras. Para manipular máscaras de bits, prefira tipos sem sinal e confira a largura antes de deslocar.

    Os operadores de bit operam sobre os valores binários das variáveis.

    Operação Sintaxe Exemplo e/ou observações
    NOT ~a Inverte os bits de a
    AND a & b Efetua a operação AND bit a bit sobre os operandos a e b
    OR a | b Efetua a operação OR bit a bit sobre os operandos a e b
    XOR a ^ b Efetua a operação XOR (OU-exclusivo) bit a bit sobre os operandos a e b
    Deslocamento à esquerda a << b Desloca os bits de a para a esquerda por b posições. Os bits à direita são preenchidos com zeros
    Deslocamento à direita a >> b Desloca os bits de a para a direita por b posições. Se a for unsigned, os bits à esquerda são preenchidos com zeros (deslocamento lógico); se a for um número negativo, o resultado depende do compilador (no GCC, o bit de sinal é replicado, o que se chama deslocamento aritmético)

    O operador XOR (OU-exclusivo) compara cada par de bits: o bit do resultado vale 1 quando os bits correspondentes são diferentes. A tabela abaixo vale para operandos booleanos, representados por 0 e 1. Para inteiros em geral, o resultado não se limita a 0 ou 1: 5 ^ 3 vale 6.

    O símbolo ^ não calcula potências. Para números reais, use a função pow de math.h; para potências inteiras exatas, use multiplicações com um tipo capaz de representar os resultados intermediários.

    a XOR b
    Verdadeiro Falso Verdadeiro
    Verdadeiro Verdadeiro Falso
    Falso Verdadeiro Verdadeiro
    Falso Falso Falso

    Operadores de atribuição¶

    Para operadores combinados na forma \(a~ \circledcirc= b\), o cálculo corresponde a \(a = a \circledcirc b\), mas o destino é avaliado apenas uma vez. Por exemplo, v[i++] += 2 incrementa i uma vez; não o reescreva como v[i++] = v[i++] + 2, que tem comportamento indefinido.

    Adição combinada a += b Equivalente a a = a + b
    Subtração combinada a -= b Equivalente a a = a - b
    Multiplicação combinada a *= b Equivalente a a = a * b
    Divisão combinada a /= b Equivalente a a = a / b
    Módulo combinado a %= b Equivalente a a = a % b (resto da divisão)
    AND bit a bit combinado a &= b Equivalente a a = a & b
    OR bit a bit combinado a |= b Equivalente a a = a | b
    XOR bit a bit combinado a ^= b Equivalente a a = a ^ b
    Deslocamento à esquerda combinado a <<= b Equivalente a a = a << b
    Deslocamento à direita combinado a >>= b Equivalente a a = a >> b

    Precedência dos operadores¶

    A precedência determina como a expressão é agrupada: a + b * c significa a + (b * c). Ela não determina a ordem em que os operandos são executados. Por exemplo, em f() + g() * h(), a multiplicação agrupa os resultados de g() e h(), mas isso não garante que essas funções sejam chamadas antes de f().

    A tabela abaixo mostra a prioridade, da maior para a menor, e a associatividade, que determina o agrupamento entre operadores do mesmo nível. Por exemplo, a - b - c agrupa como (a - b) - c. As setas indicam o sentido desse agrupamento.

    Os operadores pós-fixados (a++, a--, chamada de função, acesso a posição de arranjo e acesso a membro) têm prioridade maior que os prefixados (++a, --a, sinais, negações, conversão de tipo, indireção, endereço e sizeof). Por isso, *p++ incrementa o ponteiro p (e não o valor apontado), e -x[2] é o inverso do elemento x[2]. Repare também que *, &, + e - aparecem duas vezes na tabela: como operadores unários (indireção, endereço e sinais) e como operadores binários (multiplicação, E bit a bit, soma e subtração).

    Na linha dos operadores de atribuição, op= representa os operadores na forma \(a~ \circledcirc= b\) listados na seção anterior. O operador vírgula, na última linha, avalia o operando da esquerda, descarta o resultado, e então avalia o da direita; ele aparece quase sempre no laço for, como em for (i = 0, j = n - 1; i < j; i++, j--).
