    Ponteiros e memória¶

    Durante a execução de um programa, todas as variáveis ficam guardadas na memória do computador. Podemos imaginar a memória como uma rua muito longa, com bilhões de casas numeradas: cada casa guarda um byte, e o número da casa é o seu endereço. Uma variável do tipo int, que ocupa 4 bytes, ocupa quatro casas vizinhas, e o endereço da variável é o endereço da primeira delas.

    Na maior parte do tempo, não precisamos saber onde as variáveis estão: usamos seus nomes, e o compilador cuida dos endereços. Mas há situações em que é útil (ou necessário) trabalhar diretamente com endereços: para que uma função altere uma variável de quem a chamou, para evitar copiar dados grandes, para criar variáveis durante a execução do programa ou para montar estruturas de dados como listas e árvores. Para isso, existem os ponteiros.

    Ponteiros¶

    Um ponteiro é uma variável que guarda um endereço de memória. Um "ponteiro para T" guarda o endereço de uma variável do tipo T: um ponteiro para int guarda o endereço de um int, um ponteiro para double guarda o endereço de um double, e assim por diante. Cada tipo T tem um tipo "ponteiro para T" correspondente.

    Ponteiros são declarados com um asterisco (*) antes do nome da variável:

    Declaração de ponteiros
    char *letra;     // 'letra' guarda o endereço de uma variável do tipo char
double *salario; // 'salario' guarda o endereço de uma variável do tipo double
int *faltas;     // 'faltas' guarda o endereço de uma variável do tipo int

    Veja bem, preste atenção!

    O asterisco pertence à variável, e não ao tipo. Na linha int *a, b;, apenas a é um ponteiro; b é um int comum. Para evitar confusão, declare um ponteiro por linha.

    Você vai encontrar as formas int *p, int* p e int * p, que são equivalentes. Neste texto usamos int *p, que deixa claro que o asterisco se aplica a p.

    Dois operadores são usados com ponteiros:

    • O operador &, chamado de operador de endereço, devolve o endereço de memória de uma variável. Se x é uma variável inteira, &x é o endereço onde x está guardada, e pode ser atribuído a um ponteiro para int;
    • O operador *, chamado de operador de indireção ou de desreferência, acessa a variável que está no endereço guardado pelo ponteiro. Se o ponteiro p guarda o endereço de x, então *p é a variável x: podemos ler o valor de x com *p e alterá-lo com *p = ....

    Ponteiros também podem apontar para outros ponteiros. Um "ponteiro para ponteiro para T" (declarado com **) guarda o endereço de uma variável que, por sua vez, guarda o endereço de um T (uma indireção dupla). Veja o exemplo a seguir:

    #include <stdio.h>

int main(void)
{
    int valor = 10;          // variável inteira comum
    int *ptr = &valor;       // ponteiro para a variável 'valor'
    int **ptr_ptr = &ptr;    // ponteiro para o ponteiro 'ptr'

    printf("valor:     %d\n", valor);
    printf("&valor:    %p\n", (void *) &valor);
    printf("ptr:       %p\n", (void *) ptr);
    printf("*ptr:      %d\n", *ptr);
    printf("&ptr:      %p\n", (void *) &ptr);
    printf("ptr_ptr:   %p\n", (void *) ptr_ptr);
    printf("*ptr_ptr:  %p\n", (void *) *ptr_ptr);
    printf("**ptr_ptr: %d\n", **ptr_ptr);

    *ptr = 25;               // altera 'valor' por meio do ponteiro
    printf("valor agora: %d\n", valor);
    return 0;
}

    O especificador %p escreve um endereço, em hexadecimal, e espera um argumento do tipo void * (por isso as conversões (void *)). Os endereços mudam a cada execução. O diagrama mostra a situação da memória no programa acima:

    flowchart LR
  pp["ptr_ptr<br/>guarda 0x7fff8154c1f8"] --> p["ptr (em 0x7fff8154c1f8)<br/>guarda 0x7fff8154c204"] --> v["valor (em 0x7fff8154c204)<br/>guarda 10"]
    • valor é uma variável comum, guardada no endereço 0x7fff8154c204;
    • ptr guarda o endereço de valor. Por isso, ptr e &valor escrevem o mesmo número, e *ptr é o próprio valor;
    • ptr_ptr guarda o endereço de ptr. *ptr_ptr é o próprio ptr (e escreve o endereço de valor), e **ptr_ptr é *ptr, ou seja, valor;
    • A atribuição *ptr = 25 altera valor, sem usar o nome valor.

    Repare que um ponteiro é uma variável como outra qualquer: ele ocupa espaço na memória, tem o seu próprio endereço (&ptr) e guarda um valor, que por acaso é um endereço. Os tipos precisam ser compatíveis: int **ptr_ptr = &valor; está errado, porque &valor é um "ponteiro para int", e não um "ponteiro para ponteiro para int" (o GCC 13.2 avisa, com initialization of 'int **' from incompatible pointer type 'int *', e o GCC 14.2 trata a mesma situação como erro).

    O ponteiro nulo (NULL)¶

    Um ponteiro que não aponta para nenhuma variável deve guardar o valor especial NULL, definido em stdio.h, stdlib.h e em outros cabeçalhos. Desreferenciar um ponteiro nulo é um erro, que normalmente encerra o programa com Segmentation fault. Por isso, quando um ponteiro pode ser nulo, ele deve ser testado antes de ser usado:

void mostra(const int *p)

        printf("(nenhum valor)\n");

    mostra(q);    // (nenhum valor)

    Veja bem, preste atenção!

    Um ponteiro declarado sem inicialização, como int *p;, guarda um endereço qualquer, que estava na memória naquele momento. Desreferenciar esse ponteiro pode alterar outra variável do programa, encerrar o programa, ou parecer funcionar. Sempre inicialize os ponteiros: com o endereço de uma variável ou com NULL.

    Ponteiros e arranjos¶

    Ponteiros e arranjos estão intimamente ligados. Os elementos de um arranjo ficam em posições consecutivas da memória e, na maioria das expressões, o nome de um arranjo é convertido automaticamente em um ponteiro para o seu primeiro elemento: v vale o mesmo que &v[0]. Esse comportamento é chamado de decaimento do arranjo (array decay).

    Somar um inteiro n a um ponteiro faz com que ele avance n elementos, e não n bytes. Se p aponta para v[0], então p + 1 aponta para v[1], e *(p + 1) é o próprio v[1]. Essa é a aritmética de ponteiros, e o operador de indexação é definido a partir dela: v[i] é, por definição, o mesmo que *(v + i).

    #include <stdio.h>

int main(void)
{
    int v[5] = {10, 20, 30, 40, 50};
    int *p = v;                         // o mesmo que p = &v[0]

    printf("p     = %p, *p       = %d\n", (void *) p, *p);
    printf("p + 1 = %p, *(p + 1) = %d\n", (void *) (p + 1), *(p + 1));
    printf("p + 4 = %p, *(p + 4) = %d\n", (void *) (p + 4), *(p + 4));
    printf("v[2] = %d, *(v + 2) = %d, p[2] = %d\n", v[2], *(v + 2), p[2]);

    int soma = 0;
    for (int *q = v; q < v + 5; q++) {  // percorre o arranjo com um ponteiro
        soma += *q;
    }
    printf("soma = %d\n", soma);

    int *fim = &v[4];
    printf("fim - p = %td elementos\n", fim - p);
    return 0;
}

    p     = 0x7ffcead0ad50, *p       = 10
p + 1 = 0x7ffcead0ad54, *(p + 1) = 20
p + 4 = 0x7ffcead0ad60, *(p + 4) = 50
v[2] = 30, *(v + 2) = 30, p[2] = 30
soma = 150
fim - p = 4 elementos

    Repare nos endereços: de p para p + 1, o endereço avançou 4 bytes (...d50 para ...d54), que é o tamanho de um int; de p para p + 4, avançou 16 bytes. Com um ponteiro para double, cada passo avançaria 8 bytes. Também é possível subtrair dois ponteiros para o mesmo arranjo: o resultado é a quantidade de elementos entre eles, do tipo ptrdiff_t, que é escrito com %td.

    É essa ligação entre arranjos e ponteiros que explica por que uma função que recebe um arranjo pode alterar os seus elementos, e por que ela precisa receber o tamanho do arranjo em outro parâmetro, como mostra a seção sobre funções.

    Veja bem, preste atenção!

    Apesar da conversão automática, um arranjo não é um ponteiro. Um arranjo não pode receber uma atribuição (v = outro; não compila), e sizeof(v) devolve o tamanho do arranjo inteiro, e não o tamanho de um ponteiro.

    Cuidado também com as declarações: int *v[10]; declara um arranjo de 10 ponteiros para int, porque [] tem prioridade maior que *. Um ponteiro para um arranjo de 10 inteiros seria int (*v)[10];, uma forma muito menos usada.

    A linguagem não verifica se um ponteiro (ou um índice) está dentro dos limites do arranjo. v[5], v[-1] ou *(p + 10) compilam normalmente, e acessam a memória que estiver naquela posição, que pode pertencer a outra variável. O resultado é comportamento indefinido: o programa pode escrever valores sem sentido, alterar outras variáveis, ser encerrado, ou parecer funcionar.

    Por que o operador == não funciona para cadeias?¶

    Como cadeias de caracteres são arranjos de char, o decaimento também explica por que não é possível compará-las com ==. Na expressão senha1 == senha2, os dois arranjos são convertidos em ponteiros para os seus primeiros elementos, e o que se compara são os endereços onde os arranjos começam, e não os caracteres guardados neles:

    char senha1[20] = "secreta";
char senha2[20] = "secreta";

if (senha1 == senha2) {  // compara &senha1[0] com &senha2[0]
    // nunca executado: são dois arranjos diferentes
}

    Cada arranjo ocupa o seu próprio espaço na memória. Mesmo que dois arranjos tenham exatamente o mesmo conteúdo, eles estão em endereços diferentes, e a comparação é sempre falsa:

    Para comparar o conteúdo, use a função strcmp, que percorre as duas cadeias caractere a caractere. Pelo mesmo motivo, uma cadeia não pode ser copiada com =: é preciso usar strcpy.

    Veja bem, preste atenção!

    Se duas variáveis ponteiros (e não arranjos) forem inicializadas com o mesmo literal, elas podem apontar para o mesmo endereço, porque o compilador pode guardar uma única cópia do literal:

    const char *ptr1 = "literal";
const char *ptr2 = "literal";  // ptr1 e ptr2 podem apontar para o mesmo endereço

    Nesse caso, ptr1 == ptr2 pode ser verdadeiro, mas isso é uma otimização do compilador, e não um comportamento garantido pela linguagem: com outro compilador, ou com outras opções de compilação, o resultado pode ser outro. Para comparar cadeias, use sempre strcmp.

    Acessando estruturas via ponteiros¶

    Quando temos um ponteiro para uma estrutura, os membros podem ser acessados de duas formas: desreferenciando o ponteiro e usando o operador ponto, como em (*p).dia, ou usando o operador seta, como em p->dia. As duas formas são equivalentes, e o operador seta é o mais usado, por ser mais conciso:

    #include <stdio.h>
#include <string.h>

struct aniversario {
    char nome[20];
    int dia;
    int mes;
    int ano;
};

int main(void)
{
    struct aniversario abelardo;
    struct aniversario *p = &abelardo;

    strcpy(p->nome, "Abelardo Silva");
    p->dia = 15;
    (*p).mes = 3;                       // o mesmo que p->mes = 3
    p->ano = 1985;

    printf("%s: %02d/%02d/%d\n", abelardo.nome, abelardo.dia, abelardo.mes, abelardo.ano);
    // Abelardo Silva: 15/03/1985
    return 0;
}

    Os parênteses em (*p).mes são necessários: como o operador ponto tem prioridade maior que o *, a expressão *p.mes seria interpretada como *(p.mes), o que não compila.

    Ponteiros e const¶

    A palavra-chave const pode ser aplicada ao valor apontado, ao próprio ponteiro ou aos dois. const int *p e int const *p qualificam o inteiro apontado; int *const p qualifica o ponteiro. Observe os exemplos:

    int a = 1, b = 2;

const int *p1 = &a;        // ponteiro para constante
*p1 = 10;                  // erro: assignment of read-only location '*p1'
p1 = &b;                   // ok: o ponteiro pode apontar para outra variável

int *const p2 = &a;        // ponteiro constante
*p2 = 10;                  // ok: o valor apontado pode ser alterado
p2 = &b;                   // erro: assignment of read-only variable 'p2'

const int *const p3 = &a;  // nem o valor apontado, nem o ponteiro podem mudar

    A forma mais usada é a primeira, o ponteiro para constante, nos parâmetros de funções que recebem um endereço apenas para ler o valor apontado, como em size_t strlen(const char *s). O compilador impede a alteração por meio desse ponteiro. Isso não torna o objeto original imutável se ele foi criado sem const: outra referência modificável ainda pode alterá-lo.

    Ponteiros genéricos (void *)¶

    Um ponteiro do tipo void * é um ponteiro genérico: ele pode guardar o endereço de uma variável de qualquer tipo, mas não pode ser desreferenciado diretamente, porque não se sabe o tipo (nem o tamanho) do que está no endereço. Antes de usar o valor apontado, é preciso convertê-lo para um ponteiro do tipo correto:

    int x = 42;
void *g = &x;             // qualquer endereço pode ser guardado em um void *
int *p = g;               // conversão automática de void * para int *
printf("%d\n", *p);       // 42
printf("%d\n", *(int *) g);   // 42: conversão explícita

    Ponteiros genéricos são usados por funções que trabalham com dados de qualquer tipo, como a função de ordenação qsort (cujas funções de comparação recebem const void *) e as funções de alocação de memória, apresentadas a seguir.

    Memória automática, estática e dinâmica¶

    As variáveis de um programa podem ficar em três regiões da memória, que diferem no tempo de vida e no tamanho disponível:

    Região O que fica nela Quando é criada Quando é liberada Tamanho
    Pilha (stack), ou memória automática Variáveis locais e parâmetros Quando a execução entra no bloco ou na função Automaticamente, quando o bloco ou a função termina Pequeno: costuma ser de 8 MB no Linux e de 1 MB no Windows
    Memória estática Variáveis globais e variáveis locais static Antes do início do programa, com a inicialização indicada ou com zero por padrão Quando o programa termina Depende dos limites do ambiente e da memória disponível
    Heap, ou memória dinâmica Blocos alocados com malloc, calloc e realloc Quando o programa pede, durante a execução Quando o programa libera, com free Limitado apenas pela memória disponível

    A memória automática é a mais simples de usar: as variáveis são criadas e destruídas sem nenhuma ação do programador. Mas ela tem duas limitações. A primeira é o tamanho: um arranjo local muito grande não cabe na pilha, e o programa é encerrado com Segmentation fault assim que a função começa a usá-lo:

    Declarar o arranjo como static ou como variável global evita ocupar a pilha de execução, mas continua sujeito ao limite total de memória do programa. Essa é uma prática comum em programação competitiva, quando o tamanho máximo da entrada é conhecido. A segunda limitação é que o tamanho de um arranjo automático não pode mudar depois de sua criação. Um arranjo de tamanho variável pode usar uma dimensão conhecida durante a execução, se o compilador oferecer esse recurso, mas continua tendo duração automática. Quando os dados precisam crescer ou continuar existindo depois que a função termina, usa-se memória dinâmica.

    Alocação dinâmica de memória¶

    As funções de alocação dinâmica estão declaradas em stdlib.h:

    Função O que faz
    void *malloc(size_t bytes) Reserva um bloco com a quantidade de bytes indicada, sem inicializar o conteúdo, e devolve o endereço do bloco
    void *calloc(size_t quantidade, size_t tamanho) Reserva um bloco para quantidade elementos de tamanho bytes cada, com todos os bytes zerados
    void *realloc(void *p, size_t bytes) Muda o tamanho de um bloco já alocado, preservando o conteúdo, e devolve o endereço do bloco (que pode ter mudado de lugar)
    void free(void *p) Libera um bloco alocado por uma das funções acima

    As três funções de alocação devolvem NULL quando não conseguem reservar a memória pedida. O endereço devolvido é um void *, que é convertido automaticamente para o tipo do ponteiro que o recebe.

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int n;
    if (scanf("%d", &n) != 1 || n <= 0 ||
        (size_t) n > SIZE_MAX / sizeof(double)) {
        return 1;
    }

    double *notas = malloc(n * sizeof *notas);
    if (notas == NULL) {
        printf("Memória insuficiente\n");
        return 1;
    }

    double soma = 0;
    for (int i = 0; i < n; i++) {
        if (scanf("%lf", &notas[i]) != 1) {
            free(notas);
            return 1;
        }
        soma += notas[i];
    }

    double media = soma / n;
    printf("Média: %.2f\n", media);
    printf("Acima da média:");
    for (int i = 0; i < n; i++) {
        if (notas[i] > media) {
            printf(" %.1f", notas[i]);
        }
    }
    printf("\n");

    free(notas);
    notas = NULL;
    return 0;
}

    Média: 7.00
Acima da média: 7.5 9.0 8.0
    • malloc(n * sizeof *notas) reserva espaço para n elementos do tipo apontado por notas. Escrever sizeof *notas, em vez de sizeof(double), garante que o tamanho continua correto mesmo que o tipo de notas seja alterado depois;
    • O resultado de malloc é testado antes de ser usado. Pedidos pequenos raramente falham, mas um pedido grande demais devolve NULL;
    • Depois de alocado, o bloco é usado exatamente como um arranjo: notas[i], &notas[i];
    • free(notas) devolve a memória ao sistema quando ela não é mais necessária. Toda memória alocada deve ser liberada exatamente uma vez;
    • Depois do free, o ponteiro continua guardando o endereço antigo, que não pode mais ser usado. Atribuir NULL ao ponteiro evita que ele seja usado por engano.

{

    int *freq = calloc(contagem_letras, sizeof *freq);   // todos os elementos valem 0

    #include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    size_t capacidade = 2;
    size_t tamanho = 0;
    int *v = malloc(capacidade * sizeof *v);
    if (v == NULL) {
        return 1;
    }

    int x;
    while (scanf("%d", &x) == 1) {
        if (tamanho == capacidade) {
            if (capacidade > SIZE_MAX / 2 ||
                2 * capacidade > SIZE_MAX / sizeof *v) {
                free(v);
                return 1;
            }
            size_t nova_capacidade = 2 * capacidade;
            int *novo = realloc(v, nova_capacidade * sizeof *v);
            if (novo == NULL) {
                free(v);
                return 1;
            }
            v = novo;
            capacidade = nova_capacidade;
            printf("(capacidade aumentada para %zu)\n", capacidade);
        }
        v[tamanho++] = x;
    }

    printf("Lidos %zu valores, em ordem inversa:", tamanho);
    for (size_t i = tamanho; i > 0; i--) {
        printf(" %d", v[i - 1]);
    }
    printf("\n");

    free(v);
    return 0;
}

    (capacidade aumentada para 4)
(capacidade aumentada para 8)
Lidos 7 valores, em ordem inversa: 2 9 5 1 4 1 3

    O resultado de realloc é guardado em um ponteiro auxiliar (novo), e só depois atribuído a v. Se realloc falhar, ele devolve NULL, mas o bloco antigo continua alocado; escrever v = realloc(v, ...) perderia o único endereço desse bloco, que não poderia mais ser liberado. Como realloc pode mudar o bloco de lugar (copiando o conteúdo para o novo endereço), qualquer outro ponteiro que apontasse para o bloco antigo deixa de ser válido.

    Dobrar a capacidade, em vez de aumentá-la de um em um, faz com que o número de realocações seja pequeno: para guardar um milhão de valores começando com capacidade 2, são necessárias apenas 19 realocações.

    Conferindo o tamanho antes de alocar¶

    O tamanho passado a malloc ou realloc é um size_t, um tipo inteiro sem sinal. Se a multiplicação da quantidade de elementos pelo tamanho de cada um ultrapassar SIZE_MAX, ela pode produzir um número pequeno. A alocação desse bloco menor pode ter sucesso, mas escrever a quantidade original de elementos ultrapassaria seus limites. Testar apenas o retorno de malloc não evita isso.

int *aloca_inteiros(size_t quantidade)
{
    int *valores;
    if (quantidade == 0 || quantidade > SIZE_MAX / sizeof *valores) {
        return NULL;
    }
    return malloc(quantidade * sizeof *valores);
}

    Nesta função, quantidade zero é rejeitada por decisão da interface. SIZE_MAX é definido em stdint.h, e a divisão verifica o limite antes de realizar a multiplicação. Ao dobrar a capacidade de um vetor, confira também o limite antes de multiplicar a capacidade por dois. O vetor dinâmico mostra essa verificação.

    Evite realloc(p, 0)

    Para liberar um bloco, use free(p) e, quando apropriado, atribua NULL ao ponteiro. No C17, realloc com tamanho zero tem regras dependentes da implementação; no C23, esse uso tem comportamento indefinido. As regras de falha que preservam o bloco antigo devem ser aplicadas a pedidos de tamanho maior que zero.

    #include <stdio.h>
#include <stdlib.h>

int **cria_matriz(int linhas, int colunas)
{
    int **m = malloc(linhas * sizeof *m);
    if (m == NULL) {
        return NULL;
    }
    for (int i = 0; i < linhas; i++) {
        m[i] = calloc(colunas, sizeof *m[i]);
        if (m[i] == NULL) {
            for (int j = 0; j < i; j++) {
                free(m[j]);
            }
            free(m);
            return NULL;
        }
    }
    return m;
}

void libera_matriz(int **m, int linhas)
{
    for (int i = 0; i < linhas; i++) {
        free(m[i]);
    }
    free(m);
}

int main(void)
{
    int linhas = 3, colunas = 4;
    int **m = cria_matriz(linhas, colunas);
    if (m == NULL) {
        return 1;
    }

    for (int i = 0; i < linhas; i++) {
        for (int j = 0; j < colunas; j++) {
            m[i][j] = i * colunas + j;
        }
    }

    for (int i = 0; i < linhas; i++) {
        for (int j = 0; j < colunas; j++) {
            printf("%3d", m[i][j]);
        }
        printf("\n");
    }

    libera_matriz(m, linhas);
    return 0;
}

    m é um ponteiro para ponteiro: aponta para um arranjo de linhas ponteiros, e cada um deles aponta para um arranjo de colunas inteiros. O acesso continua sendo m[i][j]. A liberação é feita na ordem inversa da alocação: primeiro as linhas, depois o arranjo de ponteiros. Se m fosse liberado primeiro, os endereços das linhas seriam perdidos.

/* Devolve uma cópia de s, que deve ser liberada com free. */
char *duplica(const char *s)
{
    char *copia = malloc(strlen(s) + 1);     // + 1 para o '\0'
    if (copia != NULL) {
        strcpy(copia, s);
    }
    return copia;
}

int main(void)
{
    char *nome = duplica("Ada Lovelace");
    if (nome == NULL) {
        return 1;
    }
    nome[0] = 'E';
    printf("%s (%zu caracteres)\n", nome, strlen(nome));   // Eda Lovelace (12 caracteres)
    free(nome);
    return 0;
}

    Esquecer o + 1 para o caractere nulo é um dos erros mais comuns com cadeias alocadas dinamicamente: strcpy escreveria um byte além do fim do bloco.

    Erros comuns com memória dinâmica¶

    Gerenciar a memória manualmente exige disciplina. Os erros abaixo são frequentes e, em muitos casos, o programa compila sem nenhum aviso e parece funcionar nos primeiros testes:

    Erro O que acontece Exemplo
    Vazamento de memória (memory leak) Um bloco alocado nunca é liberado, normalmente porque o seu endereço foi perdido. Em programas que executam por muito tempo, a memória usada cresce sem parar p = malloc(...); dentro de um laço, sem free
    Uso depois da liberação (use after free) O bloco foi liberado, mas o ponteiro (agora um ponteiro pendente, ou dangling pointer) continua sendo usado. O bloco pode já ter sido entregue a outra parte do programa free(p); printf("%d", p[0]);
    Liberação dupla (double free) O mesmo bloco é liberado duas vezes, o que corrompe as estruturas internas do alocador free(p); free(p);
    Acesso fora dos limites (buffer overflow) O programa lê ou escreve além do final (ou antes do início) do bloco for (i = 0; i <= n; i++) v[i] = 0;
    Ponteiro não inicializado O ponteiro é usado antes de receber um endereço válido int *p; *p = 10;
    Liberar o que não foi alocado free recebe o endereço de uma variável automática, ou um endereço do meio de um bloco int x; free(&x);

    Os resultados desses erros são imprevisíveis: o programa pode ser encerrado (Segmentation fault, ou free(): double free detected), escrever valores sem sentido, ou funcionar no seu computador e falhar no juiz online. Nos testes feitos para este texto, o mesmo programa com uso depois da liberação escreveu 227970 sem otimizações e -936863756 com -O2, sem nenhuma mensagem de erro.

    Deixe o compilador procurar os erros por você

    O GCC tem um modo de compilação que verifica, durante a execução, todos os acessos à memória: a opção -fsanitize=address (o AddressSanitizer). O programa fica mais lento, mas, quando um dos erros da tabela acontece, ele é interrompido com uma mensagem que diz qual foi o erro e em que linha do código-fonte ele aconteceu. Compile também com -g, para que as linhas apareçam na mensagem:

    gcc -std=c17 -Wall -Wextra -g -fsanitize=address -o programa programa.c

    Com essa opção, um laço que escreve uma posição além do fim de um bloco de 5 inteiros produz:

    ==12==ERROR: AddressSanitizer: heap-buffer-overflow on address 0x603000000054 ...
WRITE of size 4 at 0x603000000054 thread T0
    #0 0x401210 in main /src/fora.c:8
0x603000000054 is located 0 bytes after 20-byte region [0x603000000040,0x603000000054)

    E um programa que aloca memória sem liberar termina com um relatório dos vazamentos:

    ==28==ERROR: LeakSanitizer: detected memory leaks
Direct leak of 4000000 byte(s) in 1000 object(s) allocated from:
    #1 0x401170 in main /src/vazamento.c:6

    Use essa opção enquanto testa o programa, e compile sem ela a versão final. A ferramenta valgrind faz verificações parecidas, sem precisar recompilar o programa.

    Algumas regras simples evitam a maior parte dos problemas:

    • Inicialize todo ponteiro, com um endereço válido ou com NULL;
    • Teste o resultado de malloc, calloc e realloc antes de usá-lo;
    • Para cada alocação, saiba onde está o free correspondente. De preferência, a mesma função (ou o mesmo par de funções, como cria_matriz e libera_matriz) aloca e libera;
    • Depois de free(p), faça p = NULL. Chamar free(NULL) não faz nada, e por isso a liberação dupla de um ponteiro anulado é inofensiva;
    • Quando o tamanho máximo dos dados é conhecido e não é grande demais, prefira arranjos automáticos ou estáticos, que não precisam ser liberados.

    Riscos e vantagens dos ponteiros¶

    A manipulação de ponteiros é frequentemente considerada o aspecto mais desafiador da linguagem. Os ponteiros possibilitam operações poderosas, mas também introduzem riscos significativos: como a linguagem não verifica se um endereço é válido, nem se um acesso está dentro dos limites de um bloco, os erros de memória não são detectados automaticamente. Acessos fora dos limites, além de causar resultados imprevisíveis, são uma das principais fontes de falhas de segurança em programas: um acesso além do final de um arranjo pode sobrescrever outras variáveis do programa e, nos casos mais graves, permitir a execução de código arbitrário.

    Por outro lado, os ponteiros permitem que os programas acessem e modifiquem dados diretamente na memória, sem cópias, o que é essencial em aplicações que exigem alto desempenho, como jogos, sistemas operacionais e sistemas embarcados. Eles permitem a criação de estruturas de dados dinâmicas, como listas ligadas e árvores, que crescem e diminuem conforme a necessidade. Em sistemas embarcados, ou em programas que manipulam diretamente o hardware, os ponteiros permitem ler e escrever em endereços específicos que correspondem a registradores dos dispositivos. E é por meio deles que uma função consegue alterar as variáveis de quem a chamou, como mostra a seção sobre passagem de parâmetros.

    Uma abordagem disciplinada elimina a maioria dos problemas: inicializar sempre os ponteiros, verificar se são nulos antes de desreferenciá-los, ter uma estratégia clara para a liberação da memória e testar os programas com as ferramentas de verificação.
