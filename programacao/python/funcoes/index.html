    Funções¶

    À medida que os programas crescem, escrever tudo em uma única sequência de instruções deixa de ser viável: o código fica longo, difícil de entender, e trechos parecidos começam a se repetir em vários lugares. Funções resolvem esses problemas. Uma função é um bloco de código com um nome, que recebe dados de entrada (os parâmetros), executa uma tarefa e, opcionalmente, devolve um resultado (o valor de retorno). Depois de escrita, ela pode ser chamada quantas vezes for necessário, de qualquer parte do programa.

    A ideia de dar um nome a um trecho de um algoritmo para reutilizá-lo, na forma de funções e procedimentos, foi apresentada na seção sobre reuso. Dividir um programa em funções traz várias vantagens:

    • Reutilização: um trecho de código escrito uma vez pode ser usado em vários lugares, sem repetição;
    • Legibilidade: um nome bem escolhido, como calcula_media ou le_matriz, explica o que um trecho de código faz, sem que seja preciso ler cada linha dele;
    • Manutenção: se houver um erro no cálculo da média, ele é corrigido em um único lugar;
    • Teste: cada função pode ser testada isoladamente, com entradas conhecidas.

    Você já usa funções desde o primeiro programa: print, input, len e int são funções embutidas na linguagem, e math.sqrt é uma função do módulo math.

    Definindo e chamando funções¶

    Uma função é definida com a palavra-chave def, seguida do nome da função, da lista de parâmetros entre parênteses e de dois pontos. O corpo da função é o bloco indentado logo abaixo:

    def nome(lista_de_parâmetros):
    pass  # substitua pelas instruções da função
    • O nome segue as mesmas regras dos nomes de variáveis. Por convenção, usam-se letras minúsculas, com as palavras separadas por sublinhado (calcula_media);
    • A lista de parâmetros contém, separados por vírgulas, os nomes dos dados que a função recebe. Ela pode ser vazia;
    • O corpo contém as instruções executadas quando a função é chamada. A instrução return encerra a função e devolve o valor indicado para quem a chamou.

    Na chamada quadrado(a), o valor de a (o argumento) é associado ao parâmetro x, o corpo da função é executado, e o valor devolvido pelo return toma o lugar da chamada na expressão. Como a chamada de uma função que devolve um valor é uma expressão, ela pode ser usada em qualquer lugar onde um valor seria aceito: em uma atribuição, dentro de uma f-string, como parte de uma conta ou como argumento de outra função.

    A função linha não tem return: ela executa uma tarefa (escrever uma linha de traços), mas não calcula nenhum resultado. Uma função que termina sem executar um return, ou que executa um return sem valor, devolve o valor especial None. É por isso que a última linha do programa escreveu None.

    Uma função precisa ser definida antes de ser chamada: as instruções de um programa são executadas de cima para baixo, e a instrução def é a que cria a função. Chamar uma função antes do def correspondente gera um NameError.

    Veja bem, preste atenção!

    Como uma função sem return devolve None, esquecer um return em algum caminho da função não gera erro na hora: o erro aparece mais adiante, quando o None é usado como se fosse um número:

    def sinal(x):
    if x > 0:
        return 1
    elif x < 0:
        return -1
    # e se x == 0?

print(sinal(5), sinal(-3), sinal(0))   # 1 -1 None
total = sinal(5) + sinal(0)
# TypeError: unsupported operand type(s) for +: 'int' and 'NoneType'

    O mesmo engano acontece com métodos que alteram um objeto e devolvem None, como list.sort(): a instrução lista = lista.sort() ordena a lista e, em seguida, troca a lista por None. Quando aparecer um erro mencionando NoneType, procure uma função que não devolveu o que você esperava.

    Documentação e anotações de tipo¶

    Uma função pode ser documentada com uma docstring: uma cadeia de caracteres escrita como primeira instrução do corpo.     def media(a: float, b: float) -> float:
    """Devolve a média aritmética de a e b."""
    return (a + b) / 2


def dobro(x: int) -> int:
    return x * 2


print(media(7, 8.5))      # 7.75
print(media.__doc__)      # Devolve a média aritmética de a e b.
print(dobro(21))          # 42
print(dobro("ab"))        # abab

    As anotações não impõem os tipos automaticamente: o interpretador não rejeita argumentos apenas por contrariá-las. No Python 3.14, sua avaliação é adiada por padrão até serem consultadas; isso não altera o funcionamento da chamada abaixo. A chamada dobro("ab") funciona sem erro (e devolve "abab", porque * repete cadeias), apesar de a anotação dizer que x deveria ser um int. Mesmo assim, elas são úteis: documentam a função para quem a lê, e são usadas pelos editores e por ferramentas de verificação, como o mypy, para apontar erros antes de o programa ser executado.

    Escopo de variáveis¶

    Parâmetros e nomes associados no corpo de uma função normalmente são locais, salvo declarações como global e nonlocal. O escopo local define onde esses nomes podem ser usados; não significa que seus objetos sejam destruídos no retorno. Objetos e valores capturados por closures podem continuar vivos. Duas chamadas têm estados locais separados. Consulte escopo e tempo de vida e a regra LEGB.

    Uma função pode ler uma variável global sem nenhuma declaração especial. Mas, se a função atribui um valor a um nome em qualquer ponto do seu corpo, esse nome passa a ser local em toda a função, o que causa um erro curioso:

def mostra():
    print(f"Lendo a global: {contador}")

    contador = contador + 1      # contador é local aqui: ainda não tem valor

    global contador

#                    where it is not associated with a value

    Em incrementa_errado, a atribuição faz de contador uma variável local, e a expressão contador + 1 tenta ler essa variável local antes que ela tenha recebido um valor. A declaração global contador, em incrementa, indica que o nome se refere à variável global. Para funções definidas dentro de outras funções, a declaração nonlocal faz o mesmo papel, como mostra a seção sobre closures.

    Como já foi dito na seção sobre escopo, o uso de variáveis globais deve ser evitado: prefira receber os dados por parâmetros e devolver os resultados com return.

    Passagem de parâmetros¶

    Esta é uma das partes mais importantes sobre funções: entender o que acontece com uma variável quando ela é passada como argumento. Para isso, é preciso lembrar como as variáveis funcionam: uma variável é um nome que aponta para um objeto. A atribuição n = 5 cria (ou reaproveita) um objeto int com o valor 5, e faz o nome n apontar para ele.

    Na chamada de uma função, cada parâmetro passa a ser mais um nome para o mesmo objeto passado como argumento (a seção sobre gerenciamento de memória mostra onde ficam os nomes e os objetos). Não há cópia do objeto. Esse modelo é chamado de passagem por atribuição (ou passagem por referência de objeto), porque funciona exatamente como uma atribuição parâmetro = argumento. O que acontece depois depende de duas coisas: se o objeto pode ser alterado, e se a função altera o objeto ou apenas faz o parâmetro apontar para outro objeto.

    Objetos imutáveis¶

    Números, cadeias de caracteres, tuplas e valores lógicos são objetos imutáveis: depois de criados, eles não podem ser alterados. Uma operação como x * 2 não altera o objeto apontado por x: ela produz um resultado, que pode ser um objeto novo ou reaproveitado, e a atribuição x = x * 2 faz o nome x apontar para ele. Por isso, uma função não tem como alterar um argumento imutável:

    Com listas, os operadores += e + têm comportamentos diferentes. v += [4] altera a lista (é equivalente a v.extend([4])), enquanto v = v + [4] cria uma lista nova e faz v apontar para ela:

    def com_mais_igual(v):
    v += [4]             # altera a lista recebida

def com_soma(v):
    v = v + [4]          # cria uma nova lista

a = [1, 2, 3]
com_mais_igual(a)
print(a)                 # [1, 2, 3, 4]

b = [1, 2, 3]
com_soma(b)
print(b)                 # [1, 2, 3]

    Com objetos imutáveis, como números, cadeias e tuplas, += não modifica o objeto original: o resultado pode ser novo ou reaproveitado, e é associado novamente ao nome.

    def media(valores):              # apenas leitura
    return sum(valores) / len(valores)


def normaliza(valores, maximo):  # altera a lista recebida
    for i in range(len(valores)):
        valores[i] = valores[i] / maximo * 10


def dobrados(valores):           # devolve uma lista nova
    return [v * 2 for v in valores]


notas = [40, 75, 90, 60]

print(f"Média: {media(notas)}")                          # 66.25

d = dobrados(notas)
print(f"notas[0] = {notas[0]}, d[0] = {d[0]}")           # 40 e 80

normaliza(notas, 100)
print(f"Depois de normalizar: {notas}")                  # [4.0, 7.5, 9.0, 6.0]
    • media apenas lê a lista. Não há cópia: a função percorre a própria lista notas;
    • normaliza altera os elementos da lista recebida, por meio de atribuições como valores[i] = ..., que alteram o objeto. As alterações aparecem em notas;
    • dobrados cria e devolve uma lista nova, sem alterar a original.

    Repare que, em normaliza, um laço como for v in valores: v = v / maximo * 10 não funcionaria: v é apenas um nome que aponta para cada número, e a atribuição faz v apontar para um novo número, sem alterar a lista. É preciso atribuir à posição da lista, com valores[i].

    Quando uma função altera um argumento, isso precisa ficar claro no nome e na documentação dela. Na dúvida, prefira funções que não alteram os argumentos e devolvem um resultado novo, como dobrados: elas são mais fáceis de entender e de testar. A própria linguagem segue esse padrão: lista.sort() altera a lista e devolve None, enquanto sorted(lista) devolve uma lista nova e não altera a original.

    Fazendo cópias¶

    Quando uma função precisa alterar uma lista sem afetar a original, ela (ou quem a chama) deve fazer uma cópia. Uma lista pode ser copiada com v[:], list(v) ou v.copy(). Essas três formas fazem uma cópia rasa: a lista é nova, mas os elementos são os mesmos objetos. Quando os elementos também são mutáveis, como em uma matriz (uma lista de listas), pode ser necessário copiar também esses elementos, por exemplo com uma cópia profunda, feita com copy.deepcopy:

    import copy


def zera_primeiro(v):
    v[0] = 0


original = [5, 6, 7]
zera_primeiro(original[:])          # passa uma cópia
print(original)                     # [5, 6, 7]

matriz = [[1, 2], [3, 4]]
rasa = matriz.copy()
profunda = copy.deepcopy(matriz)
matriz[0][0] = 99
print(rasa)                         # [[99, 2], [3, 4]]
print(profunda)                     # [[1, 2], [3, 4]]

    A cópia rasa rasa é uma lista nova, mas as linhas dentro dela são as mesmas listas que estão em matriz. Por isso, alterar matriz[0][0] alterou também rasa[0][0]. A cópia profunda copiou também as linhas, e não foi afetada.

    def minimo_e_maximo(valores):
    menor = maior = valores[0]
    for x in valores:
        if x < menor:
            menor = x
        if x > maior:
            maior = x
    return menor, maior


dados = [7, 2, 9, 4, 1, 8]

menor, maior = minimo_e_maximo(dados)
print(f"Menor: {menor}, maior: {maior}")     # Menor: 1, maior: 9

resultado = minimo_e_maximo(dados)
print(resultado, type(resultado).__name__)   # (1, 9) tuple

q, r = divmod(17, 5)
print(f"17 / 5 = {q}, resto {r}")            # 17 / 5 = 3, resto 2

    A função embutida divmod segue o mesmo modelo, e devolve o quociente e o resto da divisão inteira. (Para encontrar o menor e o maior valor de uma lista, as funções embutidas min e max já fazem o trabalho; a função acima serve apenas como exemplo.)

    Quando a função devolve muitos valores, uma tupla fica difícil de usar: é fácil esquecer se a nota vinha antes ou depois da idade. Nesses casos, prefira devolver um dicionário ou um objeto de uma classe de dados, em que cada valor tem um nome.

    Os parâmetros de uma função podem ter valores padrão, usados quando o argumento correspondente é omitido na chamada. Além disso, os argumentos podem ser passados por posição (na ordem em que os parâmetros foram definidos) ou por nome (parâmetro=valor), em qualquer ordem:

Na chamada, os argumentos posicionais vêm primeiro, e os nomeados depois. Os argumentos nomeados permitem pular parâmetros (como em saudar("Davi", repeticoes=2), que usa o valor padrão de saudacao) e deixam a chamada mais clara: print(*valores, sep=", ", end="") é um exemplo que você já conhece.

    Nunca use um objeto mutável como valor padrão

    O valor padrão é criado uma única vez, quando a instrução def é executada, e não a cada chamada. Se o valor padrão for uma lista, todas as chamadas que omitem o argumento compartilham a mesma lista:

    def adiciona_errado(item, lista=[]):
    lista.append(item)
    return lista

print(adiciona_errado("a"))   # ['a']
print(adiciona_errado("b"))   # ['a', 'b']   (!)
print(adiciona_errado("c"))   # ['a', 'b', 'c']   (!)

    A forma correta é usar None como valor padrão e criar a lista dentro da função:

    def adiciona(item, lista=None):
    if lista is None:
        lista = []
    lista.append(item)
    return lista

print(adiciona("a"))   # ['a']
print(adiciona("b"))   # ['b']

    Recursão¶

    Uma função pode chamar a si mesma. Isso se chama recursão, e é uma forma natural de resolver problemas que podem ser divididos em versões menores do mesmo problema. Toda função recursiva precisa de um caso base, que é resolvido diretamente, sem nova chamada, e de um caso recursivo, que reduz o problema e chama a função novamente:

    def fatorial(n):
    if n <= 1:                   # caso base
        return 1
    return n * fatorial(n - 1)   # caso recursivo


def mdc(a, b):
    if b == 0:
        return a
    return mdc(b, a % b)


print(f"5! = {fatorial(5)}")             # 120
print(f"20! = {fatorial(20)}")           # 2432902008176640000
print(f"30! = {fatorial(30)}")           # 265252859812191058636308480000000
print(f"mdc(48, 18) = {mdc(48, 18)}")    # 6

    A função fatorial usa a definição \(n! = n \times (n-1)!\), com \(1! = 1\). Como os inteiros não têm limite de tamanho, ela calcula corretamente até fatoriais enormes, como \(30!\). A função mdc usa o algoritmo de Euclides: o máximo divisor comum de \(a\) e \(b\) é igual ao de \(b\) e \(a \bmod b\), e o de \(a\) e \(0\) é \(a\).

    Cada chamada recursiva tem as suas próprias variáveis locais. Na execução de fatorial(5), existem, ao mesmo tempo, cinco variáveis n diferentes (com os valores 5, 4, 3, 2 e 1), uma para cada chamada ainda não terminada.

    Veja bem, preste atenção!

    Cada chamada de função ocupa memória até terminar, e o interpretador limita a profundidade da recursão para evitar que essa memória se esgote. O limite padrão é de 1000 níveis: a chamada fatorial(5000) termina com RecursionError: maximum recursion depth exceeded. O limite pode ser aumentado com sys.setrecursionlimit(10**6), o que é comum em programação competitiva, mas uma recursão muito profunda ainda pode esgotar a memória e encerrar o interpretador. Quando a profundidade puder chegar a dezenas de milhares de níveis, prefira reescrever a função com um laço.

    Memorização com @cache¶

    Algumas funções recursivas repetem o mesmo cálculo muitas vezes.     import time
from functools import cache


def fib_lento(n):
    if n < 2:
        return n
    return fib_lento(n - 1) + fib_lento(n - 2)


@cache
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)


inicio = time.perf_counter()
print(fib_lento(32))                                         # 2178309
print(f"Sem cache: {time.perf_counter() - inicio:.2f} s")

inicio = time.perf_counter()
print(fib(32))                                               # 2178309
print(f"Com cache: {time.perf_counter() - inicio:.6f} s")
print(fib(300))

    No computador usado nos testes, a versão sem cache levou cerca de 0,3 segundo para calcular fib(32), e a versão com cache, cerca de 30 milionésimos de segundo; fib(300), que levaria séculos na versão direta, é calculado instantaneamente. A técnica de guardar resultados já calculados se chama memorização (memoization), e só funciona com funções que sempre devolvem o mesmo resultado para os mesmos argumentos, que precisam ser hashable: devem oferecer um hash estável e uma igualdade compatível. Números e cadeias atendem a esse requisito; uma tupla só atende se todos os seus elementos também atenderem. O cache mantém referências aos argumentos e resultados; não o use para chamadas com efeitos colaterais ou resultados mutáveis que deveriam ser independentes. O que é um decorador é explicado mais adiante.

    Funções como argumentos: key¶

    O uso mais frequente de funções como argumentos é o parâmetro key das funções sorted, min e max e do método list.sort. A função passada em key é aplicada a cada elemento, e a comparação é feita entre os resultados, e não entre os elementos:

    nomes = ["Bruno", "Ana", "Carla", "Bia"]
print(sorted(nomes, key=len))   # ['Ana', 'Bia', 'Bruno', 'Carla']: ordena pelo tamanho
print(max(nomes, key=len))      # Bruno: o primeiro dos mais longos

    O exemplo mostra os usos mais comuns:

    • Para ordenar por mais de um critério, a função key devolve uma tupla, e as tuplas são comparadas elemento a elemento. Em (len(n), n), os nomes são ordenados pelo tamanho e, em caso de empate, por ordem alfabética;
    • Para ordenar em ordem decrescente por um critério numérico e crescente por outro, troca-se o sinal do critério numérico: em (-a[1], a[0]), os alunos são ordenados pela nota, da maior para a menor, e, em caso de empate, pelo nome;
    • As funções filter e map recebem uma função e a aplicam a cada elemento. Na maioria dos casos, uma compreensão de lista, como [x for x in v if x > limite], faz o mesmo de forma mais legível.

    Guardar uma lambda em uma variável, como em quadrado, funciona, mas não é recomendado pelo guia de estilo da linguagem: se a função precisa de um nome, use def.

    Closures¶

    Uma função pode ser definida dentro de outra função. A função interna enxerga as variáveis da função externa e, se for devolvida, continua tendo acesso a elas mesmo depois que a função externa terminou. Uma função que "lembra" das variáveis do lugar onde foi criada é chamada de closure:

    def multiplicador(fator):
    def multiplica(x):
        return x * fator
    return multiplica


def cria_contador():
    total = 0

    def conta():
        nonlocal total
        total += 1
        return total

    return conta


dobro = multiplicador(2)
triplo = multiplicador(3)
print(dobro(10), triplo(10))     # 20 30

c1 = cria_contador()
c2 = cria_contador()
print(c1(), c1(), c1())          # 1 2 3
print(c2())                      # 1
    • Cada chamada de multiplicador cria uma nova função multiplica, que lembra do fator com que foi criada: dobro lembra do 2, e triplo, do 3;
    • Em cria_contador, a função interna precisa alterar a variável total, da função externa. Sem a declaração nonlocal total, a atribuição total += 1 faria de total uma variável local de conta, e o resultado seria um UnboundLocalError. Cada contador criado tem o seu próprio total.

    Veja bem, preste atenção!

    Uma closure guarda a variável, e não o valor que ela tinha quando a função foi criada. O valor é consultado no momento da chamada. Isso causa um erro clássico ao criar funções dentro de um laço:

    funcoes = [lambda: i for i in range(3)]
print([f() for f in funcoes])    # [2, 2, 2], e não [0, 1, 2]

    As três funções consultam a mesma variável i, que vale 2 quando elas são chamadas. Uma solução é usar um parâmetro com valor padrão, que é calculado quando a função é criada:

    funcoes = [lambda i=i: i for i in range(3)]
print([f() for f in funcoes])    # [0, 1, 2]

    import functools
import time


def cronometra(funcao):
    @functools.wraps(funcao)
    def envolve(*args, **kwargs):
        inicio = time.perf_counter()
        resultado = funcao(*args, **kwargs)
        fim = time.perf_counter()
        print(f"{funcao.__name__} levou {fim - inicio:.3f} s")
        return resultado
    return envolve


@cronometra
def soma_quadrados(n):
    return sum(i * i for i in range(n))


print(soma_quadrados(1_000_000))
# soma_quadrados levou 0.079 s
# 333332833333500000

    A função envolve é uma closure que lembra da funcao original. Ela recebe quaisquer argumentos (*args e **kwargs), repassa-os para a função original, mede o tempo, escreve o resultado da medição e devolve o valor calculado. O decorador @functools.wraps copia o nome e a documentação da função original para a função envolvida.

    Você não precisa escrever decoradores para usar a linguagem, mas vai encontrá-los com frequência: @cache, apresentado na seção sobre recursão, e @property e @dataclass, apresentados na seção sobre orientação a objetos, são decoradores.

    def quadrados(n):
    for i in range(1, n + 1):
        yield i * i


def fibonacci():
    a, b = 0, 1
    while True:
        yield a
        a, b = b, a + b


for q in quadrados(5):
    print(q, end=" ")            # 1 4 9 16 25
print()

g = fibonacci()

    Um gerador pode ser usado em qualquer lugar que aceite um iterável: em um for, em list, sum, max e similares. Como os valores são produzidos sob demanda, um gerador não precisa guardar todos eles na memória, e pode até ser infinito, como fibonacci: a função next pede um valor de cada vez, e o laço termina quando o programa para de pedir.

Por isso, o bloco if __name__ == "__main__": é executado apenas no primeiro caso: ao executar main.py, os testes de geometria.py não aparecem.

    Organizando um programa em funções

    Mesmo em um programa de um único arquivo, como os de programação competitiva, vale a pena separar a leitura dos dados, o processamento e a escrita do resultado em funções, e reunir a parte principal em uma função main:

    def le_caso():
    a, b = map(int, input().split())
    return a, b


def resolve(a, b):
    return a + b


def main():
    t = int(input())
    for _ in range(t):
        a, b = le_caso()
        print(resolve(a, b))


if __name__ == "__main__":
    main()

    Cada função pode ser testada separadamente e, como as variáveis de main são locais, o acesso a elas é um pouco mais rápido do que às variáveis globais.
