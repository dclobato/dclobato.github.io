    Controle de fluxo¶

    As estruturas de controle de fluxo são componentes fundamentais de qualquer linguagem de programação. Elas permitem que o programador defina caminhos alternativos de execução e repita trechos de código, em vez de simplesmente executar as instruções uma após a outra, do início ao fim.

    A capacidade de alterar o fluxo de execução com base em valores de variáveis, em dados digitados pelo usuário ou em resultados de operações é o que torna os programas verdadeiramente dinâmicos e capazes de resolver problemas.

    Declarações e blocos¶

    Instruções¶

    Em C++, uma instrução (ou sentença) é um comando completo, que o compilador traduz em alguma ação. Cada instrução simples termina com um ponto e vírgula (;). Nem toda linha termina com ponto e vírgula: as linhas que abrem estruturas de controle, como if (...) e for (...), não são instruções completas, e sim o começo de uma.

    Exemplos de instruções
    int x = 10;                       // declaração de variável
std::cout << "Olá, mundo!\n";     // expressão (saída de dados)
return 0;                         // instrução de retorno

    Blocos e escopo¶

    Um conjunto de instruções delimitado por chaves ({ e }) é chamado de bloco (ou instrução composta). Os blocos agrupam instruções que devem ser executadas juntas, como o corpo de uma função ou o conjunto de instruções executadas por um if.

    Blocos definem o escopo, que determina onde um nome é visível. Isso é diferente do tempo de vida do objeto. Uma variável local automática normalmente é destruída ao sair do bloco, mas uma variável local static permanece entre chamadas. Objetos dinâmicos têm seu tempo de vida controlado separadamente, de preferência por contêineres e ponteiros inteligentes.

    Os blocos podem ser aninhados, criando uma hierarquia de escopos. Variáveis declaradas em blocos externos são acessíveis nos blocos internos, mas o contrário não é verdade. Os conceitos gerais de escopo e tempo de vida são apresentados na seção sobre variáveis, e o escopo das variáveis de uma função, na seção sobre funções.

    A declaração introduz o nome e o tipo. A inicialização acontece na criação do objeto, como em int x = 10;. Já int x; x = 10; declara primeiro um inteiro local sem valor inicial definido e depois faz uma atribuição: essa segunda operação não é inicialização. Após o uso, o objeto é destruído conforme sua duração de armazenamento.

    Veja bem, preste atenção!

    Variáveis globais são declaradas fora de qualquer bloco ou função e podem ser acessadas em qualquer parte do programa. O uso de variáveis globais é geralmente desencorajado porque dificulta a compreensão do código: qualquer parte do programa pode alterá-las, e fica difícil descobrir onde e por que um valor foi modificado.

    As únicas situações em que o uso de variáveis globais pode ser considerado aceitável são:

    • Constantes globais: se um valor não muda durante a execução do programa (por exemplo, o valor de \(\pi\)), ele pode ser declarado como uma constante (constexpr) no escopo mais externo;
    • Configurações compartilhadas: em programas grandes, algumas configurações globais podem ser mais fáceis de gerenciar, como o nível de detalhe das mensagens de depuração;
    • Gerenciamento de estado: em sistemas embarcados ou aplicações de tempo real, pode ser útil ter variáveis globais para armazenar estados do sistema.

    Mas a regra geral é: não use variáveis globais.

    #include <iostream>

int main()
{

    {
        int y = 20;  // variável no escopo interno
        std::cout << "Dentro do bloco interno: x = " << x << ", y = " << y << '\n';

        }

        std::cout << "De volta ao bloco interno: x = " << x << ", y = " << y << '\n';
    }

    // y não é acessível aqui
    std::cout << "No bloco externo: x = " << x << '\n';
    return 0;
}

    Neste exemplo, a variável x é acessível em todos os blocos, y é acessível apenas no bloco intermediário e no mais interno, e z é acessível apenas no bloco mais interno.

    Veja bem, preste atenção!

    Se um bloco interno declarar uma variável com o mesmo nome de uma variável de um bloco externo, a variável interna esconde a externa enquanto o bloco interno estiver em execução. São duas variáveis diferentes, e alterar uma não altera a outra:

    int contador = 1;
{
    int contador = 99;   // outra variável, que "esconde" a de fora
    std::cout << contador << '\n';   // 99
}
std::cout << contador << '\n';       // 1

    Esse tipo de código é permitido, mas confuso, e quase sempre indica um erro. Evite reutilizar nomes de variáveis em blocos aninhados.

    Estruturas condicionais¶

    As estruturas condicionais permitem que um programa execute diferentes trechos de código dependendo de condições. Em C++, há três formas de tomar decisões: a estrutura if/else, o operador ternário e a estrutura switch.

    Estrutura if-else¶

    A forma mais simples da estrutura if é:

    if (condição) {
    a;  // bloco de código a ser executado se a condição for verdadeira
}

       flowchart LR
      A --> B
      B -- Sim --> C --> D
      B -- Não ----> D

      A@{ shape: stadium, label: "Início" }
      B@{ shape: question, label: "condição" }
      C@{ shape: process, label: "a" }
      D@{ shape: stadium, label: "Fim" }

    A condição pode ser qualquer expressão lógica ou relacional.

    Se a condição for avaliada como verdadeira (true, ou qualquer valor numérico diferente de zero), o bloco de código dentro das chaves será executado. Se a condição for falsa (false, ou zero), o bloco será ignorado.

    A estrutura if/else estende essa lógica, permitindo especificar um bloco alternativo, executado quando a condição é falsa:

    if (condição) {
    a;  // bloco de código a ser executado se a condição for verdadeira
} else {
    b;  // bloco de código a ser executado se a condição for falsa
}

      A --> B
      B -- Sim --> C --> E
      B -- Não --> D --> E

      A@{ shape: stadium, label: "Início" }
      B@{ shape: question, label: "condição" }
      C@{ shape: process, label: "a" }
      D@{ shape: process, label: "b" }
      E@{ shape: stadium, label: "Fim" }

    Repare que a segunda condição não precisa verificar se a nota é menor que 9: se a execução chegou até ela, é porque a primeira condição foi falsa.

    Os blocos if também podem ser aninhados, permitindo criar lógicas de decisão mais complexas:

    if (condição1) {
    // executado se condição1 for verdadeira
    if (condição2) {
        // executado se condição1 e condição2 forem verdadeiras
    } else {
        // executado se condição1 for verdadeira e condição2 for falsa
    }
} else {
    // executado se condição1 for falsa
}

    Veja bem, preste atenção!

    Quando o bloco tem uma única instrução, as chaves podem ser omitidas. Mas isso é uma armadilha: um else sempre pertence ao if mais próximo que ainda não tem else, independentemente da indentação. No código abaixo, o else pertence ao if (b > 0), e não ao if (a > 0), como a indentação sugere:

    if (a > 0)
    if (b > 0)
        std::cout << "a e b positivos\n";
else
    std::cout << "a não é positivo?\n";   // executado quando a > 0 e b <= 0!

    O compilador avisa sobre isso (suggest explicit braces to avoid ambiguous 'else'). Use sempre as chaves, mesmo em blocos de uma única linha.

    Operador ternário¶

    O operador ternário (? :) é uma forma concisa de expressar uma decisão condicional dentro de uma expressão. Sua sintaxe é:

    condição ? expressão1 : expressão2

    Se a condição for verdadeira, o resultado será expressão1; caso contrário, será expressão2. Este operador é particularmente útil para atribuições condicionais simples:

    #include <iostream>
#include <string>

int main()
{
    int idade = 17;
    std::string status = (idade >= 18) ? "adulto" : "menor de idade";

    std::cout << "Uma pessoa com " << idade << " anos é " << status << ".\n";

    // Também pode ser usado diretamente em expressões
    std::cout << "Você " << (idade >= 16 ? "pode" : "não pode") << " votar.\n";

    int a = 7, b = 12;
    int maior = (a > b) ? a : b;
    std::cout << "O maior é " << maior << '\n';
    return 0;
}

    Neste exemplo, a variável status recebe o valor "adulto" se a idade for maior ou igual a 18, e "menor de idade" caso contrário. Os parênteses em torno do operador ternário dentro de uma saída com << são obrigatórios, porque << tem precedência maior que ?:.

    Use o operador ternário apenas para escolhas simples entre dois valores. Operadores ternários aninhados, ou com expressões longas, tornam o código difícil de ler; nesses casos, prefira um if.

    Estrutura switch-case¶

    A estrutura switch é uma alternativa ao uso de vários if/else quando se deseja comparar uma expressão com vários valores constantes. Sua sintaxe é:

    switch (expressão) {
    case constante1:
        // executado se expressão == constante1
        break;
    case constante2:
        // executado se expressão == constante2
        break;
    // ... mais casos
    default:
        // executado se nenhum dos casos anteriores corresponder
}

    A expressão é avaliada uma única vez, e seu valor é comparado com cada uma das constantes. Se houver uma correspondência, a execução começa no código associado àquele caso. A instrução break encerra o switch; sem ela, a execução continua nos casos seguintes, independentemente de suas constantes corresponderem ou não à expressão. Esse comportamento é conhecido como "queda" (fall-through).

    O caso default é opcional e é executado apenas se nenhum dos outros casos corresponder à expressão.

enum class Operacao { Soma, Subtracao, Multiplicacao, Divisao };

int main()
{
    Operacao op = Operacao::Multiplicacao;
    double a = 6, b = 4;

    switch (op) {
        case Operacao::Soma:          std::cout << a + b << '\n'; break;
        case Operacao::Subtracao:     std::cout << a - b << '\n'; break;

    A estrutura switch difere de if/else encadeados em três aspectos principais:

    • O switch avalia a expressão apenas uma vez, enquanto os if/else avaliam cada condição separadamente;
    • O switch só compara a expressão com valores constantes, conhecidos durante a compilação, enquanto if/else pode usar qualquer condição;
    • A expressão do switch precisa ser de um tipo inteiro (incluindo char, bool e enumerações). Não é possível usar switch com números reais nem com std::string; para eles, use if/else.

    Estruturas iterativas¶

    Iteração vs. interação¶

    É importante distinguir iteração de interação. Iteração é a repetição de um bloco de código, enquanto interação é a comunicação entre diferentes componentes, ou entre o programa e o usuário. As estruturas iterativas, também conhecidas como laços ou loops, permitem executar um bloco de código repetidamente, seja um número determinado de vezes, seja até que uma condição seja atendida.

    Em C++, as estruturas for, while e do/while são, tecnicamente, de repetição indeterminada, pois dependem de uma condição que pode mudar durante a execução. No entanto, o laço for é frequentemente usado para repetições determinadas, e o laço for baseado em intervalo percorre exatamente os elementos de uma sequência.

    Estrutura for¶

    A estrutura for é composta por três partes: inicialização, condição e pós-operação. Sua sintaxe é:

    for (inicialização; condição; pós-operação) {
    // bloco de código a ser repetido
}
    • A inicialização é executada uma única vez, antes do início do laço;
    • A condição é avaliada antes de cada repetição; se for falsa, o laço termina;
    • A pós-operação é executada após cada repetição.

    Veja o fluxograma equivalente à execução da instrução for (a; b; c) d;

    #include <iostream>

int main()
{
    for (int i = 0; i < 5; ++i) {
        std::cout << "Iteração " << i << '\n';
    }

    for (int i = 10; i > 0; i -= 3) {     // contagem regressiva de 3 em 3
        std::cout << i << ' ';
    }
    std::cout << '\n';                    // 10 7 4 1

    for (int i = 1, j = 10; i < j; ++i, --j) {   // duas variáveis
        std::cout << '(' << i << ',' << j << ") ";
    }
    std::cout << '\n';                    // (1,10) (2,9) (3,8) (4,7) (5,6)
    return 0;
}

    No primeiro laço, o bloco é executado exatamente 5 vezes, com i assumindo os valores de 0 a 4. A variável i, declarada na inicialização, só existe dentro do laço. Os outros dois laços mostram que a pós-operação pode ser qualquer expressão, e que é possível controlar mais de uma variável, separando as declarações e as pós-operações por vírgulas.

    Estrutura for baseada em intervalo¶

    Para percorrer todos os elementos de uma sequência (um arranjo, uma std::string, um std::vector ou qualquer contêiner da biblioteca padrão), existe uma forma mais simples do laço for, chamada de for baseado em intervalo (range-based for):

    for (declaração : sequência) {
    // bloco executado uma vez para cada elemento
}

    A cada repetição, a variável declarada recebe um dos elementos da sequência, do primeiro ao último:

    #include <iostream>
#include <string>
#include <vector>

int main()
{
    std::vector<std::string> nomes = {"Ana", "Bruno", "Carla"};

    for (const std::string& nome : nomes) {   // leitura, sem cópia
        std::cout << nome << '\n';
    }

    for (std::string& nome : nomes) {         // alteração dos elementos
        nome += "!";
    }

    for (const auto& nome : nomes) {          // o mesmo, com auto
        std::cout << nome << ' ';
    }
    std::cout << '\n';                        // Ana! Bruno! Carla!

    for (char c : std::string("abc")) {
        std::cout << c << '-';
    }
    std::cout << '\n';                        // a-b-c-

    for (int x : {2, 3, 5, 7, 11}) {          // lista de valores
        std::cout << x << ' ';
    }
    std::cout << '\n';
    return 0;
}

    A forma de declarar a variável do laço define o que acontece com os elementos:

    Declaração Efeito
    for (int x : v) x é uma cópia de cada elemento. Alterar x não altera a sequência. Adequada para tipos pequenos, como números
    for (int& x : v) x é uma referência para cada elemento. Alterar x altera a sequência
    for (const auto& x : v) x é uma referência constante: não há cópia, e o elemento não pode ser alterado. Forma recomendada para ler elementos grandes, como cadeias e estruturas

    O laço baseado em intervalo não dá acesso ao índice do elemento. Quando o índice for necessário, use o laço for tradicional.

    Para repetir um bloco para uma sequência de inteiros, a partir do C++20 também é possível usar std::views::iota, do cabeçalho <ranges>: for (int i : std::views::iota(1, 6)) percorre os valores 1, 2, 3, 4 e 5 (o valor final não é incluído). As views e os ranges são apresentados na seção sobre a biblioteca padrão.

    C++23

    O C++23 acrescentou std::views::enumerate, que percorre uma sequência fornecendo o índice e o elemento ao mesmo tempo:

    for (auto [i, nome] : std::views::enumerate(nomes)) {
    std::cout << i << ": " << nome << '\n';
}

    Em C++20, o equivalente é o laço tradicional com índice:

    for (std::size_t i = 0; i < nomes.size(); ++i) {
    std::cout << i << ": " << nomes[i] << '\n';
}

    Veja bem, preste atenção!

    Não acrescente nem remova elementos de um contêiner enquanto ele estiver sendo percorrido por um laço baseado em intervalo. Em contêineres como std::vector, acrescentar elementos pode fazer com que eles mudem de lugar na memória, e o laço passa a acessar posições inválidas, com comportamento indefinido.

    Equivalência entre for e while¶

    Qualquer laço for pode ser reescrito como um laço while:

    Equivalência entre for e while
    // Laço for
for (int i = 0; i < 5; ++i) {
    std::cout << "Iteração " << i << '\n';
}

// Equivalente usando while
int i = 0;
while (i < 5) {
    std::cout << "Iteração " << i << '\n';
    ++i;
}

    Ambos os laços produzem o mesmo resultado, mas o for agrupa as três partes do controle da repetição em uma única linha, tornando o código mais conciso e claro. Há uma diferença sutil: no while, a variável i continua existindo depois do laço; no for, ela só existe dentro dele.

    Comandos continue e break¶

    Os comandos continue e break são usados para controlar o fluxo dentro dos laços.

    O comando continue interrompe a repetição atual e passa para a próxima. No caso de um laço for, a pós-operação é executada antes da próxima verificação da condição.

    O comando break termina o laço completamente, transferindo o controle para a primeira instrução depois dele.

    #include <iostream>

int main()
{
    std::cout << "Exemplo de continue:\n";
    for (int i = 0; i < 10; ++i) {
        if (i % 2 == 0) {
            continue;  // pula os números pares
        }
        std::cout << i << ' ';
    }
    std::cout << "\n\n";

    std::cout << "Exemplo de break:\n";
    for (int i = 0; i < 10; ++i) {
        if (i == 5) {
            break;  // interrompe o laço quando i é 5
        }
        std::cout << i << ' ';
    }
    std::cout << '\n';
    return 0;
}

    Neste exemplo, o primeiro laço escreve apenas os números ímpares de 0 a 9 (1 3 5 7 9), pois o comando continue pula a repetição quando i é par. O segundo laço escreve os números de 0 a 4, pois o comando break interrompe o laço quando i é igual a 5.

    Veja bem, preste atenção!

    Em laços aninhados, break e continue afetam apenas o laço mais interno em que estão. Para sair de vários laços de uma vez, uma solução é usar uma variável lógica que também faça parte da condição do laço externo:

    bool achou = false;
for (int i = 1; i <= 5 && !achou; ++i) {
    for (int j = 1; j <= 5; ++j) {
        if (i * j == alvo) {
            achou = true;
            break;   // sai apenas do laço de dentro
        }
    }
}

    Outra solução, muitas vezes mais clara, é colocar os laços em uma função e usar return para sair de todos eles ao mesmo tempo.

    Em um laço while, cuidado com o continue: se a atualização da variável de controle estiver no final do bloco, o continue vai pulá-la, e o laço pode nunca terminar.

    Tratamento de exceções¶

    Durante a execução de um programa, situações inesperadas podem acontecer: um arquivo que não existe, um dado em formato incorreto, um índice fora dos limites de um vetor, falta de memória. Quando uma função detecta um problema que ela mesma não sabe resolver, ela pode lançar uma exceção, interrompendo a execução normal e transferindo o controle para um trecho de código preparado para tratar aquele tipo de problema.

    O tratamento de exceções permite separar a lógica principal do programa da lógica de tratamento de erros, mantendo o código mais limpo e legível. E, quando bem usado, permite que o programa se recupere de erros, em vez de simplesmente ser encerrado.

    Blocos try e catch¶

    O código que pode lançar exceções é colocado em um bloco try, seguido de um ou mais blocos catch, cada um responsável por um tipo de exceção. Se uma exceção for lançada dentro do try, o restante do bloco é abandonado e a execução continua no primeiro catch compatível com o tipo da exceção. Se nenhuma exceção for lançada, os blocos catch são ignorados.

    #include <iostream>
#include <stdexcept>
#include <string>

int main()
{
    std::string entrada;
    std::cout << "Digite um número inteiro: ";
    std::cin >> entrada;

    try {
        int numero = std::stoi(entrada);
        std::cout << "Você digitou o número " << numero << ".\n";
    } catch (const std::invalid_argument& e) {
        std::cout << "Erro: entrada inválida. Por favor, digite um número inteiro.\n";
    } catch (const std::out_of_range& e) {
        std::cout << "Erro: número grande demais.\n";
    }

    std::cout << "O programa continua normalmente.\n";
    return 0;
}

O programa continua normalmente.

    As exceções devem ser capturadas por referência constante (const std::invalid_argument& e): isso evita uma cópia e preserva o tipo real da exceção. Toda exceção da biblioteca padrão tem o método what(), que devolve uma mensagem descrevendo o problema.

    Se uma exceção for lançada e nenhum catch a capturar, o programa é encerrado imediatamente, com uma mensagem de erro.

    Exceções da biblioteca padrão¶

    As exceções da biblioteca padrão formam uma hierarquia: todas derivam de std::exception, do cabeçalho <exception>, e a maioria das exceções específicas está no cabeçalho <stdexcept>. As mais comuns estão na tabela abaixo:

    Exceção Quando ocorre Exemplo que gera a exceção
    std::out_of_range Acesso a uma posição inválida com at(), ou valor fora do intervalo de um tipo em uma conversão std::vector<int> v(3); v.at(5);
    std::invalid_argument Argumento com valor inválido, como uma cadeia que não representa um número std::stoi("abc");
    std::length_error Tentativa de criar uma cadeia ou contêiner maior que o tamanho máximo permitido s.reserve(s.max_size() + 1);
    std::domain_error Argumento fora do domínio de uma operação matemática (usada principalmente por funções escritas pelo programador) throw std::domain_error("divisão por zero");
    std::overflow_error Resultado grande demais para ser representado std::bitset<70> b; b.set(); b.to_ulong();
    std::runtime_error Erro que só pode ser detectado durante a execução; base para várias outras exceções throw std::runtime_error("falha ao conectar");
    std::logic_error Erro de lógica do programa, que poderia ter sido evitado; base de std::out_of_range, std::invalid_argument e outras throw std::logic_error("estado inválido");
    std::bad_alloc Falta de memória para uma alocação (cabeçalho <new>) pedir memória demais, como new int[1'000'000'000'000]
    std::bad_optional_access Acesso ao valor de um std::optional vazio (cabeçalho <optional>) std::optional<int> o; o.value();

    #include <exception>
#include <iostream>
#include <stdexcept>
#include <vector>

int main()
{
    std::vector<int> v = {1, 2, 3};

    try {
        std::cout << v.at(10) << '\n';
    } catch (const std::exception& e) {      // captura qualquer exceção da biblioteca padrão
        std::cout << "Erro: " << e.what() << '\n';
    }

    try {
        throw 42;                             // é possível lançar qualquer valor (mas não faça isso)
    } catch (...) {                           // captura qualquer coisa
        std::cout << "Alguma exceção foi lançada\n";
    }
    return 0;
}

    Quando há vários blocos catch, eles são testados na ordem em que aparecem. Por isso, os tipos mais específicos devem vir antes dos mais genéricos: se o catch (const std::exception& e) viesse primeiro, ele capturaria todas as exceções, e os blocos seguintes nunca seriam executados.

    Veja bem, preste atenção!

    Nem todo erro gera uma exceção em C++. Divisão inteira por zero, acesso fora dos limites com colchetes (v[10]), desreferência de ponteiro nulo e estouro de capacidade de inteiros com sinal não lançam exceções: eles têm comportamento indefinido, e normalmente o programa simplesmente é encerrado (ou, pior, continua executando com valores errados). Um try/catch não protege contra esses erros. A única defesa é verificar as condições antes: o divisor é diferente de zero? O índice está dentro dos limites?

    #include <iostream>
#include <stdexcept>

double raiz_quadrada(double x)
{
    if (x < 0) {
        throw std::invalid_argument("raiz de número negativo");
    }
    double r = x;
    for (int i = 0; i < 30; ++i) {
        r = (r + x / r) / 2;      // método de Newton
    }
    return r;
}

int main()
{
    try {
        std::cout << raiz_quadrada(2.0) << '\n';    // 1.41421
        std::cout << raiz_quadrada(-1.0) << '\n';   // lança a exceção
        std::cout << "Esta linha não é executada\n";
    } catch (const std::invalid_argument& e) {
        std::cout << "Erro: " << e.what() << '\n';  // Erro: raiz de número negativo
    }
    return 0;
}

    Quando a exceção é lançada, a função raiz_quadrada é interrompida imediatamente (ela não chega a devolver um valor), e a execução salta para o catch em main. A exceção "atravessa" quantas funções forem necessárias até encontrar um catch compatível. Esse é um dos pontos fortes do mecanismo: o erro é detectado em um lugar e tratado em outro, onde houver informação suficiente para decidir o que fazer.

    Dentro de um catch, a instrução throw; (sem nada depois) relança a mesma exceção, para que ela seja tratada também por um catch mais externo.

    #include <iostream>
#include <stdexcept>
#include <string>

class SaldoInsuficiente : public std::runtime_error {
public:
    SaldoInsuficiente(double saldo, double valor)
        : std::runtime_error("saldo insuficiente: saldo " + std::to_string(saldo) +
                             ", saque " + std::to_string(valor)),
          falta(valor - saldo)
    {
    }

    double falta;
};

void sacar(double& saldo, double valor)
{
    if (valor > saldo) {
        throw SaldoInsuficiente(saldo, valor);
    }
    saldo -= valor;
}

int main()
{
    double saldo = 100.0;

    try {
        sacar(saldo, 30.0);
        std::cout << "Saque realizado. Saldo: " << saldo << '\n';
        sacar(saldo, 100.0);
    } catch (const SaldoInsuficiente& e) {
        std::cout << "Erro: " << e.what() << '\n';
        std::cout << "Faltam " << e.falta << '\n';
    }
    return 0;
}
    Saída
    Saque realizado. Saldo: 70

    Além da mensagem, a exceção carrega uma informação extra (falta), que o código que a captura pode usar para decidir o que fazer. E, por herdar de std::runtime_error, ela também pode ser capturada por um catch (const std::exception& e) genérico.

    Exceções e liberação de recursos¶

    No desenrolamento da pilha para alcançar um tratador de exceção, os objetos automáticos já construídos nos escopos abandonados são destruídos na ordem inversa da construção. Assim, arquivos, contêineres e ponteiros inteligentes liberam seus recursos por RAII. Se nenhuma função tratar a exceção, std::terminate é chamado, e não há garantia de desenrolamento da pilha antes do encerramento.

    void processa(const char* nome)
{
    std::ofstream arquivo(nome);
    arquivo << "início do processamento\n";
    throw std::runtime_error("algo deu errado no meio do caminho");
    // o arquivo é fechado automaticamente, mesmo com a exceção
}

    É por isso que C++ não precisa de um bloco para "limpar" recursos depois de um erro: a limpeza fica a cargo dos próprios objetos. O mesmo não acontece com memória alocada com new e controlada por ponteiros comuns, que vaza se uma exceção impedir a execução do delete. Mais um motivo para usar contêineres e ponteiros inteligentes.

    noexcept

    Uma função declarada com noexcept, como int soma(int a, int b) noexcept, promete que nenhuma exceção escapará dela. Ela ainda pode lançar e tratar exceções internamente. Se uma exceção ultrapassar seu limite, ocorre std::terminate; o compilador não precisa rejeitar uma instrução throw dentro dessa função.

    Quando usar exceções?

    Exceções são adequadas para situações excepcionais, em que a função não tem como cumprir o que promete: um arquivo que deveria existir e não existe, um dado corrompido, um argumento inválido. Elas não devem ser usadas para o controle de fluxo normal do programa, como sair de um laço ou sinalizar que um elemento não foi encontrado em uma busca. Lançar e capturar uma exceção é uma operação relativamente lenta, e o uso excessivo torna o fluxo do programa difícil de acompanhar.
