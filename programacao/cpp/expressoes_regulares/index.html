    Expressões regulares¶

    Em muitas situações, é necessário identificar padrões dentro de um texto: encontrar todas as datas de um documento, verificar se um e-mail digitado tem um formato válido, extrair os elementos químicos de uma fórmula como \(C_6H_{12}O_6\) ou trocar todos os telefones de um texto por um formato padronizado. Fazer isso com as operações básicas de busca em cadeias de caracteres é trabalhoso e propenso a erros. As expressões regulares resolvem esse tipo de problema de forma compacta.

    Esta seção contém uma introdução ao assunto. Existem livros inteiros dedicados às expressões regulares, e um dos melhores é em português: o Livro do Piazinho, do Aurélio Marinho Jargas.

    Para testar expressões regulares, e ver se elas fazem o que você gostaria que elas fizessem, também há sites muito bons, entre eles o RegExr, o Regular Expressions 101 (escolha o modo ECMAScript, que é o usado por padrão em C++) e uma área especial no site do Livro do Piazinho.

    Definição e aplicações¶

    Uma expressão regular é uma linguagem formal para descrever padrões em cadeias de caracteres. Em vez de dizer "procure a palavra casa", ela permite dizer "procure dois dígitos, uma barra, mais dois dígitos, outra barra e quatro dígitos", ou "verifique se o texto é formado por letras, seguidas de uma arroba, seguida de palavras separadas por pontos".

    Expressões regulares são usadas para:

    • Validar dados: verificar se um e-mail, um telefone, um CEP ou uma placa de veículo estão no formato correto;
    • Extrair informações: localizar datas, valores, códigos ou palavras-chave em textos longos e arquivos de registro (logs);
    • Transformar textos: substituir padrões, padronizar formatos e dividir textos com separadores variados.

    Em C++, as expressões regulares estão no cabeçalho <regex>. O padrão é representado por um objeto do tipo std::regex, e as operações são feitas por funções como std::regex_search, std::regex_match e std::regex_replace.

    Use cadeias cruas para escrever os padrões

    As expressões regulares usam muito a barra invertida (\d, \w, \.), que também é o caractere de escape das cadeias de caracteres em C++. Em uma cadeia comum, cada barra precisa ser escrita duas vezes: o padrão \d+\.\d+ vira "\\d+\\.\\d+". As cadeias cruas (R"(...)"), apresentadas na seção de tipos de dados, não interpretam as barras, e deixam o padrão exatamente como ele deve ser: R"(\d+\.\d+)". Use sempre cadeias cruas para escrever expressões regulares.

    Buscando e verificando¶

    As duas operações básicas são:

    • std::regex_search(texto, padrao): verifica se o padrão aparece em algum lugar do texto;
    • std::regex_match(texto, padrao): verifica se o texto inteiro corresponde ao padrão.

    As duas devolvem um bool. Para saber o que foi encontrado e onde, passa-se também um objeto do tipo std::smatch, que recebe o resultado:

    #include <iostream>
#include <regex>
#include <string>

int main()
{
    std::string texto = "A casa amarela tem uma porta azul";
    std::regex padrao("casa");
    std::smatch m;

    if (std::regex_search(texto, m, padrao)) {
        std::cout << "Encontrei '" << m.str() << "' na posição " << m.position() << '\n';  // posição 2
    }

    std::cout << std::boolalpha;
    std::cout << std::regex_search(texto, std::regex("porta")) << '\n';   // true
    std::cout << std::regex_match(texto, std::regex("casa")) << '\n';     // false: não é o texto todo
    std::cout << std::regex_match("casa", std::regex("casa")) << '\n';    // true
    return 0;
}

    Use std::regex_match para validar (o texto todo precisa estar no formato) e std::regex_search para procurar (o padrão pode estar em qualquer lugar).

    Sintaxe básica¶

    Literais e metacaracteres¶

    Os elementos mais simples de uma expressão regular são os literais: caracteres que correspondem exatamente a si mesmos. O padrão casa encontra a sequência "casa" no texto. Já os metacaracteres são símbolos com significado especial:

    • ^: início do texto (ou de uma linha, no modo multilinha). ^C\+\+ encontra C++ é ótimo, mas não Eu uso C++.
    • $: final do texto (ou de uma linha). \.(jpg|png|gif)$ encontra foto.png, mas não foto.pngx.
    • .: qualquer caractere, exceto quebra de linha. a.b corresponde a aab, a3b ou a_b, mas não a ab.
    • \: o caractere de escape, que transforma um metacaractere em literal. \. corresponde a um ponto, e \+ a um sinal de mais.
    • |: alternativa. gato|cachorro encontra tanto gato quanto cachorro.
    • (): agrupamento e captura. (jpg|png|gif) agrupa as alternativas, e permite extrair a parte encontrada.

    #include <iostream>
#include <regex>
#include <string>

int main()
{
    std::cout << std::boolalpha;
    std::cout << std::regex_search("C++ é ótimo", std::regex(R"(^C\+\+)")) << ' '     // true
              << std::regex_search("Eu uso C++", std::regex(R"(^C\+\+)")) << '\n';    // false
    std::cout << std::regex_search("foto.png", std::regex(R"(\.(jpg|png|gif)$)")) << ' '   // true
              << std::regex_search("foto.pngx", std::regex(R"(\.(jpg|png|gif)$)")) << '\n'; // false
    std::cout << std::regex_match("a3b", std::regex("a.b")) << ' '                    // true
              << std::regex_match("ab", std::regex("a.b")) << '\n';                   // false
    return 0;
}

    Classes de caracteres¶

    Uma classe de caracteres, escrita entre colchetes, corresponde a um caractere qualquer do conjunto: [aeiou] corresponde a qualquer vogal minúscula. Intervalos são indicados com hífen ([a-z], [A-Z], [0-9]) e podem ser combinados ([a-zA-Z0-9]). Um ^ logo depois do colchete de abertura nega a classe: [^0-9] corresponde a qualquer caractere que não seja um dígito.

    Algumas classes são tão comuns que têm atalhos:

    Atalho Equivalente Significado
    \d [0-9] Um dígito
    \D [^0-9] Qualquer caractere que não seja dígito
    \w [a-zA-Z0-9_] Um caractere de "palavra": letra, dígito ou sublinhado
    \W [^a-zA-Z0-9_] Qualquer caractere que não seja de palavra
    \s Um espaço em branco (espaço, tabulação, quebra de linha...)
    \S Qualquer caractere que não seja espaço em branco
    \b Uma fronteira de palavra (não corresponde a um caractere, e sim a uma posição)

    #include <iostream>
#include <regex>
#include <string>

int contar(const std::string& texto, const std::regex& padrao)
{
    return std::distance(std::sregex_iterator(texto.begin(), texto.end(), padrao), std::sregex_iterator());
}

int main()
{
    std::string texto = "C++20 foi publicado em 2020, e o C++23 em 2024!";
    std::cout << contar(texto, std::regex("[aeiou]")) << '\n';        // 10 vogais minúsculas
    std::cout << contar(texto, std::regex(R"(\d)")) << '\n';          // 12 dígitos
    std::cout << contar(texto, std::regex(R"(\d{4})")) << '\n';       // 2 grupos de 4 dígitos
    std::cout << contar(texto, std::regex(R"(\s)")) << '\n';          // 9 espaços
    std::cout << contar(texto, std::regex("[^a-zA-Z0-9 ]")) << '\n';  // 6: nem letra, nem dígito, nem espaço
    return 0;
}

    A função contar usa um std::sregex_iterator, que percorre todas as ocorrências do padrão no texto, e conta quantas são com std::distance. Os iteradores de expressões regulares são apresentados em detalhes adiante.

    Veja bem, preste atenção!

    Com std::regex sobre std::string, a busca percorre unidades char, normalmente bytes, e não decodifica UTF-8. A interpretação de classes também pode depender da localidade. Acrescentar letras acentuadas a uma classe como [áé] não a torna uma classe Unicode: os bytes podem ser tratados separadamente. Para processamento Unicode, use uma solução que reconheça explicitamente a codificação.

    #include <iostream>
#include <regex>
#include <string>

int main()
{
    std::regex telefone(R"(\d{2} \d{4,5}-\d{4})");
    std::regex cep(R"(\d{5}-?\d{3})");
    std::regex placa(R"([A-Z]{3}\d[A-Z0-9]\d{2})");

    std::cout << std::boolalpha;
    for (const char* t : {"11 9876-5432", "11 98765-4321", "1 9876-5432"}) {
        std::cout << t << ": " << std::regex_match(t, telefone) << '\n';   // true, true, false
    }
    for (const char* c : {"15015-000", "15015000", "1501-5000"}) {
        std::cout << c << ": " << std::regex_match(c, cep) << '\n';        // true, true, false
    }
    for (const char* p : {"ABC1D23", "ABC1234", "AB1C234"}) {
        std::cout << p << ": " << std::regex_match(p, placa) << '\n';      // true, true, false
    }
    return 0;
}

    O padrão do telefone aceita dois dígitos, um espaço, quatro ou cinco dígitos, um hífen e mais quatro dígitos. No CEP, o hífen é opcional (-?). A placa aceita tanto o formato antigo (três letras e quatro dígitos) quanto o do Mercosul (com uma letra na quinta posição).

    #include <iostream>
#include <regex>
#include <string>

int main()
{
    std::string texto = "O prazo termina em 25/12/2026.";
    std::regex data(R"((\d{2})/(\d{2})/(\d{4}))");
    std::smatch m;

    if (std::regex_search(texto, m, data)) {
        std::cout << "Data completa: " << m[0] << '\n';   // 25/12/2026
        std::cout << "Dia: " << m[1] << '\n';             // 25
        std::cout << "Mês: " << m[2] << '\n';             // 12
        std::cout << "Ano: " << m[3] << '\n';             // 2026
        int ano = std::stoi(m.str(3));
        std::cout << "Ano seguinte: " << ano + 1 << '\n'; // 2027
        std::cout << "Antes: [" << m.prefix() << "], depois: [" << m.suffix() << "]\n";
    }
    return 0;
}
    Operação em std::smatch m Resultado
    m[0], m.str() O trecho encontrado inteiro
    m[i], m.str(i) O trecho capturado pelo grupo i
    m.position(i) A posição, no texto, do início do grupo i
    m.length(i) O tamanho do trecho capturado pelo grupo i
    m.size() O número de grupos mais um (o grupo 0)
    m.prefix(), m.suffix() O texto antes e depois do trecho encontrado

    Veja bem, preste atenção!

    O objeto std::smatch não guarda cópias dos trechos encontrados: ele guarda posições dentro do texto original. Por isso, o texto precisa continuar existindo (e sem alterações) enquanto o resultado for usado. Pelo mesmo motivo, não é possível usar std::regex_search(..., m, ...) com um texto temporário, como o resultado de uma função ou de uma concatenação: guarde o texto em uma variável antes.

    #include <iostream>
#include <regex>
#include <string>

int main()
{
    std::string texto = "Pedido 1234: 3 itens, total 57.90 em 12/05/2026";
    std::regex numero(R"(\d+)");

    for (auto it = std::sregex_iterator(texto.begin(), texto.end(), numero);
         it != std::sregex_iterator(); ++it) {
        std::cout << it->str() << ' ';             // 1234 3 57 90 12 05 2026
    }
    std::cout << '\n';

    std::regex palavra_py(R"(\bPy\w+)");
    std::string t2 = "Python é poderoso, PyCharm também! Mas Happy não.";
    for (std::sregex_iterator it(t2.begin(), t2.end(), palavra_py), fim; it != fim; ++it) {
        std::cout << (*it)[0] << ' ';              // Python PyCharm
    }
    std::cout << '\n';
    return 0;
}

    No segundo padrão, \b exige que Py esteja no início de uma palavra: por isso, o "py" de "Happy" não é encontrado.

    #include <iostream>
#include <map>
#include <regex>
#include <string>

int main()
{
    std::string formula = "C6H12O6";
    std::regex elemento(R"(([A-Z][a-z]?)(\d*))");
    std::map<std::string, int> atomos;

    for (std::sregex_iterator it(formula.begin(), formula.end(), elemento), fim; it != fim; ++it) {
        const std::smatch& m = *it;
        int quantidade = m[2].length() > 0 ? std::stoi(m.str(2)) : 1;
        atomos[m.str(1)] += quantidade;
    }

    for (const auto& [simbolo, n] : atomos) {
        std::cout << simbolo << ": " << n << '\n';   // C: 6, H: 12, O: 6
    }
    return 0;
}

#include <regex>
#include <string>

int main()
{
    std::string texto = "Contato: 11 98765-4321 ou 21 3333-4444";

    std::cout << std::regex_replace(texto, std::regex(R"(\d)"), "#") << '\n';

    std::regex telefone(R"((\d{2}) (\d{4,5})-(\d{4}))");
    std::cout << std::regex_replace(texto, telefone, "($1) $2-$3") << '\n';
    std::cout << std::regex_replace(texto, telefone, "[$&]") << '\n';
    std::cout << std::regex_replace(texto, telefone, "($1) ****-$3",
                                    std::regex_constants::format_first_only) << '\n';

    std::string data = "2026-11-18";
    std::cout << std::regex_replace(data, std::regex(R"((\d{4})-(\d{2})-(\d{2}))"), "$3/$2/$1") << '\n';

    std::string espacos = "muitos     espaços   entre    palavras";
    std::cout << std::regex_replace(espacos, std::regex(R"(\s+)"), " ") << '\n';
    return 0;
}

    #include <iostream>
#include <regex>
#include <string>
#include <vector>

int main()
{
    std::string texto = "maçã, banana;laranja ;  uva,pera";
    std::regex separador(R"(\s*[,;]\s*)");

    std::vector<std::string> partes(
        std::sregex_token_iterator(texto.begin(), texto.end(), separador, -1),
        std::sregex_token_iterator());

    for (const auto& p : partes) {
        std::cout << '[' << p << "] ";       // [maçã] [banana] [laranja] [uva] [pera]
    }
    std::cout << '\n';
    return 0;
}

    Opções de compilação do padrão¶

    O construtor de std::regex aceita, como segundo argumento, opções que alteram o comportamento do padrão. Elas podem ser combinadas com o operador |:

    Opção Efeito
    std::regex::icase Não diferencia letras maiúsculas de minúsculas
    std::regex::multiline ^ e $ passam a corresponder ao início e ao fim de cada linha, e não apenas do texto inteiro
    std::regex::nosubs Os grupos não capturam nada (útil quando só importa saber se houve correspondência)
    std::regex::optimize Pede que o padrão seja otimizado para buscas mais rápidas, com um custo maior na criação
    std::regex::ECMAScript Usa a sintaxe ECMAScript (é a gramática padrão quando nenhuma outra gramática é selecionada; pode ser combinada explicitamente com multiline)

    #include <iostream>
#include <regex>
#include <string>

int main()
{
    std::string texto = "Python, PYTHON, pYtHoN, C++";
    std::regex sem_caixa("python", std::regex::icase);
    std::cout << std::distance(std::sregex_iterator(texto.begin(), texto.end(), sem_caixa),
                               std::sregex_iterator()) << '\n';   // 3

    std::string linhas = "teste inicial\noutro teste\nteste final";
    std::regex inicio_de_linha("^teste", std::regex::ECMAScript | std::regex::multiline);
    std::cout << std::distance(std::sregex_iterator(linhas.begin(), linhas.end(), inicio_de_linha),
                               std::sregex_iterator()) << '\n';   // 2

    std::regex sem_multiline("^teste");
    std::cout << std::distance(std::sregex_iterator(linhas.begin(), linhas.end(), sem_multiline),
                               std::sregex_iterator()) << '\n';   // 1

    std::string duas = "Primeira linha\nSegunda linha";
    std::cout << std::boolalpha << std::regex_search(duas, std::regex("Primeira.+Segunda")) << ' '
              << std::regex_search(duas, std::regex(R"(Primeira[\s\S]+Segunda)")) << '\n';   // false true
    return 0;
}

    O ponto (.) nunca corresponde a uma quebra de linha, e não há uma opção que mude isso. Quando for preciso "qualquer caractere, inclusive quebra de linha", use a classe [\s\S] (um espaço em branco ou algo que não é espaço em branco), como no final do exemplo.

    Verificação antecipada (lookahead)¶

    A construção (?=...), chamada de lookahead positivo, verifica se o que vem a seguir corresponde a um padrão, sem consumir os caracteres. A forma (?!...) (lookahead negativo) verifica se o que vem a seguir não corresponde. Elas permitem impor várias condições ao mesmo texto, como nas regras de uma senha forte:

    #include <iostream>
#include <regex>
#include <string>

int main()
{
    // pelo menos 8 caracteres, com ao menos uma minúscula, uma maiúscula e um dígito
    std::regex senha_forte(R"(^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$)");

    std::cout << std::boolalpha;
    for (const char* s : {"abc12345", "Abc12345", "Abcdefgh", "Ab1"}) {
        std::cout << s << ": " << std::regex_match(s, senha_forte) << '\n';   // false, true, false, false
    }

    std::string precos = "R$ 10, US$ 20, R$ 35, 40 reais";
    std::regex antes_de_reais(R"(\d+(?= reais))");
    std::smatch m;
    if (std::regex_search(precos, m, antes_de_reais)) {
        std::cout << m.str() << '\n';    // 40
    }
    return 0;
}

    Cada (?=.*[a-z]) verifica, a partir do início, se existe uma letra minúscula em algum lugar do texto, sem avançar a posição; depois que as três verificações passam, .{8,}$ exige o tamanho mínimo. No segundo exemplo, \d+(?= reais) encontra um número apenas se ele for seguido de " reais", e o resultado contém só o número.

    Recursos ausentes

    A sintaxe ECMAScript usada por std::regex não tem alguns recursos encontrados em outras implementações de expressões regulares: não há grupos nomeados ((?<nome>...)), não há verificação para trás (lookbehind, (?<=...)) e não há modificadores dentro do padrão (como (?i)). Use os números dos grupos, reorganize o padrão, e passe as opções no construtor.

    Ganancioso e não ganancioso¶

    Por padrão, os quantificadores são gananciosos: eles tentam corresponder ao maior trecho possível. Um ? depois do quantificador (*?, +?, ??, {n,m}?) o torna não ganancioso (ou preguiçoso): ele passa a corresponder ao menor trecho possível:

    #include <iostream>
#include <regex>
#include <string>

int main()
{
    std::string html = "<b>negrito</b> e <i>itálico</i>";
    std::smatch m;

    std::regex_search(html, m, std::regex("<.+>"));      // ganancioso
    std::cout << m.str() << '\n';                         // <b>negrito</b> e <i>itálico</i>

    std::regex_search(html, m, std::regex("<.+?>"));     // não ganancioso
    std::cout << m.str() << '\n';                         // <b>
    return 0;
}

    Com o quantificador ganancioso, <.+> começa no primeiro < e vai até o último > do texto. Com o não ganancioso, <.+?> para no primeiro > que encontrar.

    Erros e desempenho¶

    Um padrão com erro de sintaxe (como um parêntese sem fechar) não é detectado durante a compilação do programa, e sim na criação do objeto std::regex, durante a execução, que lança uma exceção do tipo std::regex_error:

    #include <iostream>
#include <regex>

int main()
{
    try {
        std::regex invalido("(abc");          // parêntese sem fechar
    } catch (const std::regex_error& e) {
        std::cout << "Expressão inválida: " << e.what() << '\n';
    }
    return 0;
}

    Criar um objeto std::regex é uma operação cara: o padrão precisa ser analisado e transformado em uma estrutura interna. Por isso, crie cada std::regex uma única vez e reutilize-o, em vez de criá-lo de novo a cada repetição de um laço:

    #include <iostream>
#include <regex>
#include <string>

int main()
{
    const std::regex email(R"([\w.+-]+@[\w-]+(\.[\w-]+)+)");   // criada uma única vez

    std::string linha;
    while (std::getline(std::cin, linha)) {
        std::cout << linha << ": " << (std::regex_match(linha, email) ? "válido" : "inválido") << '\n';
    }
    return 0;
}

    Veja bem, preste atenção!

    O desempenho de std::regex depende da implementação, do padrão e do texto. Padrões com muitas alternativas e repetições podem causar retrocesso excessivo e tempos muito altos. Meça com as entradas relevantes antes de escolher uma solução. Bibliotecas externas oferecem outras características, como RE2, que garante tempo linear na entrada para os padrões que suporta, e CTRE, que analisa padrões durante a compilação.

    Em competições de programação e juízes online, frequentemente só a biblioteca padrão está disponível, e os limites de tempo são apertados. Nesses ambientes, prefira resolver os problemas de texto com as operações de std::string e laços simples, e reserve <regex> para entradas pequenas.
