    Funções¶

    À medida que os programas crescem, escrever tudo dentro de main deixa de ser viável: o código fica longo, difícil de entender, e trechos parecidos começam a se repetir em vários lugares. Funções resolvem esses problemas. Uma função é um bloco de código com um nome, que recebe dados de entrada (os parâmetros), executa uma tarefa e, opcionalmente, devolve um resultado (o valor de retorno). Depois de escrita, ela pode ser chamada quantas vezes for necessário, de qualquer parte do programa.

    A ideia de dar um nome a um trecho de um algoritmo para reutilizá-lo, na forma de funções e procedimentos, foi apresentada na seção sobre reuso. Dividir um programa em funções traz várias vantagens:

    • Reutilização: um trecho de código escrito uma vez pode ser usado em vários lugares, sem repetição;
    • Legibilidade: um nome bem escolhido, como calcula_media ou le_matriz, explica o que um trecho de código faz, sem que seja preciso ler cada linha dele;
    • Manutenção: se houver um erro no cálculo da média, ele é corrigido em um único lugar;
    • Teste: cada função pode ser testada isoladamente, com entradas conhecidas.

    Definindo e chamando funções¶

    A definição de uma função tem a forma:

    tipo_de_retorno nome(lista_de_parâmetros)
{
    // corpo da função
}
    • O tipo de retorno indica o tipo do valor devolvido pela função. Uma função que não devolve nada tem tipo de retorno void;
    • O nome segue as mesmas regras dos nomes de variáveis;
    • A lista de parâmetros declara, separados por vírgulas, o tipo e o nome de cada dado que a função recebe. Ela pode ser vazia;
    • O corpo contém as instruções executadas quando a função é chamada. A instrução return encerra a função e devolve o valor indicado para quem a chamou.

    #include <iostream>

int quadrado(int x)
{
    return x * x;
}

void linha(int tamanho)
{
    for (int i = 0; i < tamanho; ++i) {
        std::cout << '-';
    }
    std::cout << '\n';
}

int main()
{
    int a = 7;
    int q = quadrado(a);

    linha(20);
    std::cout << "O quadrado de " << a << " é " << q << '\n';
    std::cout << "O quadrado de 12 é " << quadrado(12) << '\n';
    std::cout << "Soma de quadrados: " << quadrado(3) + quadrado(4) << '\n';
    linha(20);
    return 0;
}

    Na chamada quadrado(a), o valor de a (o argumento) é usado para inicializar o parâmetro x, o corpo da função é executado, e o valor devolvido pelo return toma o lugar da chamada na expressão. Como a chamada de uma função que devolve um valor é uma expressão, ela pode ser usada em qualquer lugar onde um valor desse tipo seria aceito: em uma atribuição, em uma saída de dados, como parte de uma conta ou como argumento de outra função.

    A função linha tem tipo de retorno void: ela executa uma tarefa (escrever uma linha de traços), mas não devolve nenhum valor. Por isso, ela é chamada como uma instrução isolada, e não faz sentido usá-la em uma expressão. Em uma função void, a instrução return; (sem valor) pode ser usada para encerrar a função antes do final do corpo.

    Veja bem, preste atenção!

    Uma função com tipo de retorno diferente de void precisa executar um return com um valor em todos os caminhos possíveis. Se a execução chegar ao final do corpo sem passar por um return, o resultado é comportamento indefinido. O compilador avisa sobre isso quando usado com -Wall (control reaches end of non-void function).

    A única exceção é main: se a execução chegar ao final de main sem um return, o efeito é o mesmo de return 0;.

    Cada parâmetro e cada variável declarada no corpo de uma função são variáveis locais: elas existem apenas enquanto a função está sendo executada e não são visíveis fora dela. Duas funções diferentes podem ter variáveis com o mesmo nome sem nenhum conflito. Os conceitos de escopo e tempo de vida são apresentados na seção sobre variáveis, e a seção Variáveis locais, globais e estáticas, mais adiante, mostra os outros tipos de variáveis que interessam no estudo de funções.

    Declaração e definição¶

    O compilador lê o código de cima para baixo e só aceita a chamada de uma função que ele já conhece. Por isso, até aqui, as funções foram escritas antes de main. Quando isso não for conveniente, a função pode ser declarada antes de ser usada e definida depois. A declaração, também chamada de protótipo, é apenas a primeira linha da função, terminada com ponto e vírgula:

    #include <iostream>

double media(double a, double b);   // declaração (protótipo)

int main()
{
    std::cout << media(7.0, 8.5) << '\n';   // 7.75
    return 0;
}

double media(double a, double b)    // definição
{
    return (a + b) / 2;
}

    A declaração informa ao compilador o nome da função, os tipos dos parâmetros e o tipo de retorno, o que é suficiente para verificar se as chamadas estão corretas. O corpo pode estar mais adiante no mesmo arquivo, ou até em outro arquivo.

    Passagem de parâmetros por valor e por referência¶

    Esta é uma das partes mais importantes sobre funções em C++: entender o que acontece com uma variável quando ela é passada como argumento. Há três formas de passar um argumento para uma função, e cada uma tem um comportamento diferente.

    Passagem por valor¶

    Na passagem por valor, que é a forma padrão, o parâmetro é uma nova variável, inicializada com uma cópia do valor do argumento. A função trabalha com essa cópia, e qualquer alteração feita no parâmetro não afeta a variável usada na chamada:

    #include <iostream>

void dobra(int x)
{
    x = x * 2;
    std::cout << "Dentro de dobra: x = " << x << '\n';
}

void troca(int a, int b)
{
    int aux = a;
    a = b;
    b = aux;
}

int main()
{
    int n = 5;
    dobra(n);
    std::cout << "Depois de dobra: n = " << n << '\n';

    int p = 1, q = 2;
    troca(p, q);
    std::cout << "Depois de troca: p = " << p << ", q = " << q << '\n';
    return 0;
}

    Dentro de dobra: x = 10
Depois de dobra: n = 5
Depois de troca: p = 1, q = 2

    A função dobra dobrou o valor de x, mas n continuou valendo 5: x é outra variável, que apenas começou com o mesmo valor de n. Pelo mesmo motivo, a função troca trocou os valores de a e b, que são cópias, e p e q ficaram como estavam. Não há erro de compilação: o programa simplesmente não faz o que parece fazer.

    A passagem por valor é adequada quando a função só precisa ler o argumento, e ele é de um tipo pequeno, como os tipos numéricos, char e bool. Ela tem uma vantagem importante: a função não tem como alterar, nem por engano, as variáveis de quem a chamou.

    Passagem por referência¶

    Na passagem por referência, o parâmetro é declarado como uma referência (com & depois do tipo). Como vimos na seção sobre memória, uma referência é um apelido: o parâmetro passa a ser outro nome para a própria variável usada na chamada. Não há cópia, e tudo o que a função faz com o parâmetro é feito com a variável original:

void dobra(int& x)
{
    x = x * 2;
    std::cout << "Dentro de dobra: x = " << x << '\n';

void troca(int& a, int& b)
{
    int aux = a;
    a = b;
    b = aux;
}

int main()
{
    int n = 5;
    dobra(n);
    std::cout << "Depois de dobra: n = " << n << '\n';

    int p = 1, q = 2;
    troca(p, q);
    std::cout << "Depois de troca: p = " << p << ", q = " << q << '\n';
    return 0;
}

    Dentro de dobra: x = 10
Depois de dobra: n = 10
Depois de troca: p = 2, q = 1

    A única diferença em relação ao programa anterior é o & nos parâmetros, e agora as duas funções fazem o que prometem. Repare que a chamada é escrita exatamente da mesma forma (dobra(n), troca(p, q)): olhando apenas para a chamada, não é possível saber se a passagem é por valor ou por referência. É preciso olhar a declaração da função.

    Como o parâmetro precisa ser um apelido para uma variável, uma função com parâmetro int& só aceita variáveis como argumento. Chamadas como dobra(5) ou dobra(n + 1) não compilam (cannot bind non-const lvalue reference), porque 5 e n + 1 não são variáveis que possam ser alteradas.

    Passagem por ponteiro¶

    Na passagem por ponteiro, a função recebe o endereço da variável, e acessa a variável original por meio do operador de desreferência (*). Tecnicamente, o ponteiro em si é passado por valor (a função recebe uma cópia do endereço), mas, como a cópia aponta para o mesmo lugar, a função consegue alterar a variável original:

    #include <iostream>

void dobra(int* x)
{
    *x = *x * 2;
    std::cout << "Dentro de dobra: *x = " << *x << '\n';
}

void troca(int* a, int* b)
{
    int aux = *a;
    *a = *b;
    *b = aux;
}

int main()
{
    int n = 5;
    dobra(&n);
    std::cout << "Depois de dobra: n = " << n << '\n';

    int p = 1, q = 2;
    troca(&p, &q);
    std::cout << "Depois de troca: p = " << p << ", q = " << q << '\n';
    return 0;
}

    Dentro de dobra: *x = 10
Depois de dobra: n = 10
Depois de troca: p = 2, q = 1

    O resultado é o mesmo da passagem por referência, mas a sintaxe é mais carregada: a chamada precisa do operador de endereço (&n), e o corpo da função precisa do operador de desreferência (*x) em todo acesso. Em compensação, a chamada deixa explícito que a variável pode ser alterada, e um ponteiro pode receber nullptr para indicar que o argumento não foi fornecido (o que obriga a função a verificar isso antes de usá-lo).

    Comparando as três formas¶

    O diagrama abaixo mostra a memória durante a execução de troca(p, q) em cada uma das formas:

    flowchart LR
  subgraph main ["Variáveis de main"]
    p["p = 1"]
    q["q = 2"]
  end
  subgraph valor ["troca por valor"]
    va["a = 1 (cópia)"]
    vb["b = 2 (cópia)"]
  end
  subgraph ref ["troca por referência"]
    ra["a (outro nome para p)"]
    rb["b (outro nome para q)"]
  end
  subgraph ptr ["troca por ponteiro"]
    pa["a = &p"]
    pb["b = &q"]
  end
  p -. copiado para .-> va
  q -. copiado para .-> vb
  ra === p
  rb === q
  pa --> p
  pb --> q
    • Por valor, a e b são variáveis novas, com cópias dos valores. A troca acontece nas cópias, que são destruídas quando a função termina;
    • Por referência, a e b não são variáveis novas: são outros nomes para p e q. A troca acontece em p e q;
    • Por ponteiro, a e b são variáveis novas que guardam os endereços de p e q. A troca acontece em p e q, acessadas por meio dos endereços.

    Um teste de mesa da chamada troca(p, q) deixa a diferença ainda mais clara. Na passagem por valor, a, b e aux são variáveis da função, e p e q nunca mudam:

    Momento p q a b aux
    Antes da chamada 1 2
    Início da função (cópias) 1 2 1 2
    Depois de aux = a 1 2 1 2 1
    Depois de a = b 1 2 2 2 1
    Depois de b = aux 1 2 2 1 1
    Depois da chamada 1 2 (destruída) (destruída) (destruída)

    Na passagem por referência, a e b são apenas outros nomes para p e q, e por isso as colunas andam juntas:

    Momento p (= a) q (= b) aux
    Antes da chamada 1 2
    Depois de aux = a 1 2 1
    Depois de a = b 2 2 1
    Depois de b = aux 2 1 1
    Depois da chamada 2 1 (destruída)

    Referências constantes¶

    E quando a função precisa apenas ler um argumento grande, como uma std::string longa ou um std::vector com milhões de elementos? A passagem por valor funcionaria, mas faria uma cópia completa a cada chamada, o que pode custar muito tempo e memória. A passagem por referência evita a cópia, mas permite que a função altere o argumento, e não aceita valores temporários.

    A passagem por referência constante (const T&) permite ler um objeto compatível sem copiá-lo quando a ligação é direta, e impede modificações por essa referência. Ela também pode se ligar a temporários compatíveis, inclusive os criados por uma conversão. Não aceita qualquer tipo, e não impede alterações por outros acessos a um objeto que não é constante.

    #include <iostream>
#include <vector>

double media(const std::vector<double>& valores)      // leitura, sem cópia
{
    double soma = 0;
    for (double v : valores) {
        soma += v;
    }
    return soma / valores.size();
}

void normaliza(std::vector<double>& valores, double maximo)   // altera o original
{
    for (double& v : valores) {
        v = v / maximo * 10;
    }
}

std::vector<double> dobrados(std::vector<double> valores)   // recebe uma cópia
{
    for (double& v : valores) {
        v *= 2;
    }
    return valores;                                         // devolve a cópia alterada
}

int main()
{
    std::vector<double> notas = {40, 75, 90, 60};

    std::cout << "Média: " << media(notas) << '\n';         // 66.25

    std::vector<double> d = dobrados(notas);
    std::cout << "notas[0] = " << notas[0] << ", d[0] = " << d[0] << '\n';   // 40 e 80

    normaliza(notas, 100);
    std::cout << "Depois de normalizar: ";
    for (double n : notas) {
        std::cout << n << ' ';                              // 4 7.5 9 6
    }
    std::cout << '\n';
    return 0;
}
    • media recebe o vetor por referência constante: lê todos os elementos sem copiá-los e sem poder alterá-los;
    • normaliza recebe o vetor por referência: altera os elementos do vetor notas de main;
    • dobrados recebe o vetor por valor: trabalha em uma cópia, que é alterada e devolvida, enquanto o vetor original permanece intacto. Essa forma faz sentido justamente quando a função precisaria fazer uma cópia de qualquer forma.

    Devolver um vetor é caro?

    Devolver um std::vector (ou uma std::string) de uma função não copia os elementos: o compilador transfere o conteúdo para a variável que recebe o resultado, ou constrói o resultado diretamente nela. Por isso, escrever funções que devolvem contêineres é eficiente e é a forma recomendada, em vez de passar um contêiner por referência só para que a função o preencha.

    Nunca devolva referência para uma variável local

    Uma função pode devolver uma referência, mas nunca uma referência (ou um ponteiro) para uma de suas variáveis locais. A variável é destruída quando a função termina, e a referência devolvida passa a apontar para memória inválida:

    const std::string& saudacao()
{
    std::string s = "Olá";
    return s;   // s é destruída aqui: a referência devolvida é inválida
}

    O compilador avisa (reference to local variable 's' returned). A solução é devolver por valor: std::string saudacao().

    Qual forma usar?¶

    Situação Forma recomendada Exemplo

    #include <iostream>
#include <utility>
#include <vector>

std::pair<int, int> minimo_e_maximo(const std::vector<int>& v)
{
    int menor = v[0];
    int maior = v[0];
    for (int x : v) {
        if (x < menor) menor = x;
        if (x > maior) maior = x;
    }
    return {menor, maior};
}

void divide(int dividendo, int divisor, int& quociente, int& resto)
{
    quociente = dividendo / divisor;
    resto = dividendo % divisor;
}

int main()
{
    std::vector<int> dados = {7, 2, 9, 4, 1, 8};

    auto [menor, maior] = minimo_e_maximo(dados);
    std::cout << "Menor: " << menor << ", maior: " << maior << '\n';   // 1 e 9

    int q, r;
    divide(17, 5, q, r);
    std::cout << "17 / 5 = " << q << ", resto " << r << '\n';           // 3, resto 2
    return 0;
}

    A primeira forma costuma ser mais clara, porque deixa explícito, na assinatura da função, o que é entrada e o que é saída. std::pair e std::tuple são apresentados na seção sobre a biblioteca padrão.

#include <string>

void saudar(const std::string& nome, const std::string& saudacao = "Olá", int repeticoes = 1)

    Os valores padrão só podem ser dados aos últimos parâmetros: depois de um parâmetro com valor padrão, todos os seguintes também precisam ter. Quando a função tem declaração e definição separadas, os valores padrão são escritos apenas na declaração.

    Sobrecarga de funções¶

    Em C++, duas ou mais funções podem ter o mesmo nome, desde que tenham listas de parâmetros diferentes (em quantidade ou em tipos). Isso se chama sobrecarga (overloading). Na chamada, o compilador escolhe a versão adequada com base nos tipos dos argumentos:

    #include <iostream>
#include <string>

int maior(int a, int b)
{
    return (a > b) ? a : b;
}

double maior(double a, double b)
{
    return (a > b) ? a : b;
}

int maior(int a, int b, int c)
{
    return maior(maior(a, b), c);
}

std::string maior(const std::string& a, const std::string& b)
{
    return (a.size() >= b.size()) ? a : b;   // a cadeia mais longa
}

int main()
{
    std::cout << maior(3, 8) << '\n';                 // 8
    std::cout << maior(2.5, 1.5) << '\n';             // 2.5
    std::cout << maior(4, 9, 6) << '\n';              // 9
    std::cout << maior(std::string("sol"), std::string("lua cheia")) << '\n';  // lua cheia
    return 0;
}

    A sobrecarga permite dar o mesmo nome a operações que fazem a mesma coisa com tipos diferentes, o que deixa o código mais natural. A biblioteca padrão usa esse recurso o tempo todo: std::to_string, por exemplo, tem uma versão para cada tipo numérico.

    Veja bem, preste atenção!

    O tipo de retorno não diferencia funções sobrecarregadas: duas funções com os mesmos parâmetros e tipos de retorno diferentes não podem coexistir. E, se os tipos dos argumentos não corresponderem exatamente a nenhuma versão, o compilador tenta conversões; quando mais de uma versão é igualmente possível, a chamada é ambígua e não compila. No exemplo acima, maior(3, 2.5) gera o erro call of overloaded 'maior(int, double)' is ambiguous, porque tanto a versão com int quanto a versão com double exigiriam uma conversão.

    Variáveis locais, globais e estáticas¶

    Além das variáveis locais, há outros dois tipos de variáveis que interessam no estudo de funções:

    • Variáveis globais são declaradas fora de qualquer função. Elas existem durante toda a execução do programa e podem ser acessadas por qualquer função do arquivo;
    • Variáveis locais estáticas são declaradas dentro de uma função, com a palavra-chave static. Elas só podem ser acessadas dentro da função, como as locais, mas existem durante toda a execução do programa, como as globais: são inicializadas uma única vez, na primeira vez em que a execução passa pela declaração, e mantêm o valor entre uma chamada e outra.

    #include <iostream>

int total_geral = 0;              // variável global

int proximo_id()
{
    static int contador = 0;      // inicializada uma única vez
    ++contador;
    return contador;
}

void registra(int valor)
{
    total_geral += valor;
}

int main()
{
    std::cout << proximo_id() << '\n';   // 1
    std::cout << proximo_id() << '\n';   // 2
    std::cout << proximo_id() << '\n';   // 3

    registra(10);
    registra(5);
    std::cout << "Total: " << total_geral << '\n';   // 15
    return 0;
}

    Sem o static, contador seria criada e inicializada com zero a cada chamada, e proximo_id devolveria sempre 1.

    Quando uma variável local tem o mesmo nome de uma variável global, o nome passa a se referir à variável local dentro da função, que "esconde" a global (o sombreamento). A variável global ainda pode ser acessada com o operador de resolução de escopo, escrevendo :: antes do nome: dentro de uma função com uma variável local taxa, taxa é a local e ::taxa é a global. Prefira, porém, nomes diferentes: o sombreamento confunde quem lê o código.

    Veja bem, preste atenção!

    Variáveis globais devem ser evitadas. Como qualquer função pode alterá-las, fica difícil saber quem mudou o valor e quando, e a função deixa de poder ser entendida (e testada) apenas pelos seus parâmetros e pelo seu valor de retorno. Prefira passar os dados por parâmetros. As exceções aceitáveis são constantes usadas por todo o programa (declaradas com constexpr) e, em programação competitiva, arranjos muito grandes: declarados como globais, eles não ocupam a pilha de execução, que tem tamanho limitado, e são inicializados automaticamente com zero.

    Recursão¶

    Uma função pode chamar a si mesma. Isso se chama recursão, e é uma forma natural de resolver problemas que podem ser divididos em versões menores do mesmo problema. Cada chamada tem as suas próprias variáveis locais, independentes das variáveis das outras chamadas. Toda função recursiva precisa de um caso base, que é resolvido diretamente, sem nova chamada, e de um caso recursivo, que reduz o problema e chama a função novamente:

    #include <iostream>

long long fatorial(int n)
{
    if (n <= 1) {            // caso base
        return 1;
    }
    return n * fatorial(n - 1);   // caso recursivo
}

int mdc(int a, int b)
{
    if (b == 0) {
        return a;
    }
    return mdc(b, a % b);
}

int main()
{
    std::cout << "5! = " << fatorial(5) << '\n';     // 120
    std::cout << "20! = " << fatorial(20) << '\n';   // 2432902008176640000
    std::cout << "mdc(48, 18) = " << mdc(48, 18) << '\n';   // 6
    return 0;
}

    A função fatorial usa a definição \(n! = n \times (n-1)!\), com \(1! = 1\). A função mdc usa o algoritmo de Euclides: o máximo divisor comum de \(a\) e \(b\) é igual ao de \(b\) e \(a \bmod b\), e o de \(a\) e \(0\) é \(a\).

    Veja bem, preste atenção!

    Cada chamada de função ocupa um espaço na pilha de memória, que só é liberado quando a chamada termina. Uma recursão sem caso base (ou com um caso base que nunca é atingido) continua chamando a função até esgotar a pilha, e o programa é encerrado com um erro de estouro de pilha (stack overflow). O mesmo pode acontecer com uma recursão correta, mas muito profunda (centenas de milhares de níveis). Nesses casos, reescreva a função com um laço.

    Funções constexpr e inline¶

    Uma função declarada com constexpr pode ser calculada durante a compilação, quando seus argumentos forem constantes conhecidos pelo compilador. O resultado pode, então, ser usado para inicializar constantes constexpr. Com argumentos conhecidos apenas durante a execução, ela funciona como uma função comum:

    constexpr long long potencia(long long base, int exp)
{
    long long r = 1;
    for (int i = 0; i < exp; ++i) r *= base;
    return r;
}

constexpr long long MOD = potencia(10, 9) + 7;   // calculado na compilação: 1000000007

    A palavra-chave inline, por sua vez, permite que uma função seja definida em um arquivo de cabeçalho incluído por vários arquivos-fonte, sem causar erro de definição duplicada na link-edição, desde que as definições satisfaçam a regra de uma definição, incluindo a mesma sequência de tokens e a resolução consistente dos nomes. Apesar do nome, ela não obriga o compilador a "copiar" o corpo da função no lugar da chamada; o compilador decide isso sozinho, com base nas otimizações.

#include <string>

template <typename T>
T maior(T a, T b)

    return (a > b) ? a : b;

{
    std::cout << '[' << a << ", " << b << ", " << c << "]\n";
}

int main()
{
    std::cout << maior(3, 8) << '\n';                                     // 8
    std::cout << maior(2.5, 1.5) << '\n';                                 // 2.5
    std::cout << maior('a', 'z') << '\n';                                 // z
    std::cout << maior(std::string("abacate"), std::string("banana")) << '\n';  // banana
    std::cout << maior<double>(3, 2.5) << '\n';                           // 3
    mostra_tres(1, 2, 3);
    mostra_tres(std::string("x"), std::string("y"), std::string("z"));
    return 0;
}

    A linha template <typename T> indica que T é um tipo ainda não definido. A cada chamada, o compilador deduz o tipo T a partir dos argumentos e gera uma versão da função para aquele tipo: maior(3, 8) gera uma versão para int, maior(2.5, 1.5), uma para double. A função funciona com qualquer tipo que suporte as operações usadas no corpo (no caso de maior, o operador >). Quando os argumentos têm tipos diferentes, o tipo pode ser indicado explicitamente, como em maior<double>(3, 2.5).

    Não é preciso escrever templates para usar a biblioteca padrão, mas é preciso entender a ideia: std::vector<int>, std::vector<std::string> e std::array<double, 10> são templates de classes, em que os tipos (e, às vezes, valores) entre < e > são os parâmetros.

    Expressões lambda¶

    Muitos algoritmos da biblioteca padrão recebem uma função como argumento: std::sort pode receber uma função que diz qual de dois elementos deve vir primeiro; std::count_if recebe uma função que diz se um elemento deve ser contado. Escrever uma função separada, com nome, para cada um desses usos seria trabalhoso. As expressões lambda permitem escrever funções anônimas diretamente no lugar onde são usadas.

    A forma geral de uma lambda é:

    [captura](parâmetros) -> tipo_de_retorno { corpo }

    #include <algorithm>
#include <iostream>
#include <string>
#include <vector>

int main()
{
    auto quadrado = [](int x) { return x * x; };
    std::cout << quadrado(7) << '\n';                    // 49

    auto soma = [](double a, double b) -> double { return a + b; };
    std::cout << soma(1.5, 2) << '\n';                   // 3.5

    std::vector<int> v = {5, 2, 8, 1, 9, 3};

    std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });   // decrescente
    for (int x : v) std::cout << x << ' ';               // 9 8 5 3 2 1
    std::cout << '\n';

    int limite = 4;
    auto acima = std::count_if(v.begin(), v.end(), [limite](int x) { return x > limite; });
    std::cout << acima << " valores acima de " << limite << '\n';   // 3

    int total = 0;
    std::for_each(v.begin(), v.end(), [&total](int x) { total += x; });
    std::cout << "Total: " << total << '\n';             // 28

    std::vector<std::string> nomes = {"Bruno", "Ana", "Carla", "Bia"};
    std::sort(nomes.begin(), nomes.end(), [](const std::string& a, const std::string& b) {
        if (a.size() != b.size()) {
            return a.size() < b.size();    // primeiro pelo tamanho
        }
        return a < b;                      // empate: ordem alfabética
    });
    for (const auto& n : nomes) std::cout << n << ' ';   // Ana Bia Bruno Carla
    std::cout << '\n';
    return 0;
}

    O exemplo mostra os usos mais comuns:

    • Uma lambda pode ser guardada em uma variável (declarada com auto) e chamada como uma função comum, como quadrado e soma;
    • Em std::sort, a lambda recebe dois elementos e devolve true se o primeiro deve vir antes do segundo. Com a > b, a ordem fica decrescente; no último exemplo, a lambda ordena por tamanho e, em caso de empate, por ordem alfabética;
    • Em std::count_if, a lambda recebe um elemento e devolve true se ele deve ser contado.

    Captura de variáveis¶

    O corpo de uma lambda só enxerga os seus próprios parâmetros e variáveis, além das variáveis globais. Para usar variáveis do bloco em que a lambda foi criada, é preciso capturá-las, listando-as entre os colchetes:

    Captura Significado
    [] Não captura nada
    [x] Captura x por valor: a lambda guarda uma cópia de x, feita no momento em que a lambda é criada
    [&x] Captura x por referência: a lambda acessa a própria variável x, e pode alterá-la
    [=] Captura por valor todas as variáveis usadas no corpo
    [&] Captura por referência todas as variáveis usadas no corpo
    [=, &x] Todas por valor, exceto x, por referência

    #include <iostream>

int main()
{
    int a = 1;
    int b = 2;

    auto por_valor = [a]() { return a * 10; };       // cópia de a, feita na criação
    auto por_ref = [&b]() { b = b * 10; };           // referência para b

    a = 100;
    por_ref();

    std::cout << por_valor() << '\n';   // 10: a lambda guardou a = 1
    std::cout << b << '\n';             // 20: a lambda alterou b
    return 0;
}

    Uma captura por referência não prolonga o tempo de vida da variável. Não devolva nem guarde uma lambda que referencia uma variável local já destruída; prefira capturar por valor quando a lambda precisar sobreviver ao escopo.

    No exemplo anterior, [limite] captura o limite por valor, porque a lambda só precisa lê-lo, e [&total] captura o total por referência, porque a lambda precisa acumular a soma na variável de main.

    Guardando funções em variáveis: std::function

    Cada lambda tem um tipo único, criado pelo compilador, e por isso usamos auto para guardá-las. Quando é preciso declarar explicitamente uma variável ou um parâmetro que aceite "qualquer função que receba um double e devolva um double", usa-se std::function<double(double)>, do cabeçalho <functional>:

    double aplica(const std::function<double(double)>& f, double x)
{
    return f(x);
}
