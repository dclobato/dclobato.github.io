    A biblioteca padrão (STL)¶

    A biblioteca padrão de C++ traz, prontas e testadas, as estruturas de dados e os algoritmos que aparecem em praticamente todos os programas: sequências que crescem conforme necessário, pilhas, filas, conjuntos, mapas, ordenação, busca, contagem e muito mais. A parte da biblioteca dedicada a essas estruturas e algoritmos é tradicionalmente chamada de STL (Standard Template Library), nome da biblioteca original que deu origem a ela.

    Conhecer bem a STL é uma das habilidades mais valiosas para quem programa em C++. Ela permite escrever programas mais curtos, mais corretos e, quase sempre, mais rápidos do que soluções escritas do zero. Em competições de programação, saber escolher a estrutura certa da STL é, muitas vezes, metade da solução de um problema.

    Os quatro componentes¶

    A STL é organizada em torno de quatro tipos de componentes que trabalham juntos:

    • Contêineres guardam coleções de elementos. Cada contêiner organiza os elementos de uma forma diferente, adequada a um tipo de uso: std::vector (sequência contígua), std::deque (fila de duas pontas), std::set (conjunto ordenado), std::map (associação entre chaves e valores), entre outros;
    • Iteradores são objetos que apontam para os elementos de um contêiner e permitem percorrê-los, de forma parecida com ponteiros. Os contêineres percorríveis oferecem begin(), que aponta para o primeiro elemento, e end(), que aponta para a posição depois do último;
    • Algoritmos são funções que operam sobre intervalos de elementos, indicados por um par de iteradores: std::sort, std::find, std::count, std::reverse e dezenas de outros. Como trabalham com iteradores, e não com um contêiner específico, cada algoritmo exige uma categoria de iterador e operações compatíveis: std::sort, por exemplo, requer acesso aleatório, e std::list oferece seu próprio sort();
    • Objetos função são "coisas que podem ser chamadas como funções", usadas para personalizar o comportamento dos algoritmos e dos contêineres: funções comuns, expressões lambda e objetos prontos da biblioteca, como std::greater<>.

    #include <algorithm>
#include <iostream>
#include <numeric>
#include <vector>

int main()
{
    std::vector<int> notas = {7, 4, 9, 6, 10, 5};    // contêiner

    std::sort(notas.begin(), notas.end());            // algoritmo + iteradores

    auto pos = std::find(notas.begin(), notas.end(), 9);
    if (pos != notas.end()) {
        std::cout << "Encontrei o 9 na posição " << (pos - notas.begin()) << '\n';
    }

    int aprovados = std::count_if(notas.begin(), notas.end(),
                                  [](int n) { return n >= 6; });   // objeto função (lambda)
    double media = std::accumulate(notas.begin(), notas.end(), 0.0) / notas.size();

    for (int n : notas) {
        std::cout << n << ' ';
    }
    std::cout << "\nAprovados: " << aprovados << ", média: " << media << '\n';
    return 0;
}
    Saída
    Encontrei o 9 na posição 4
4 5 6 7 9 10
Aprovados: 4, média: 6.83333

    O algoritmo std::find devolve um iterador para o elemento encontrado, ou notas.end() se o elemento não existir. Subtrair notas.begin() de um iterador de um std::vector dá a posição (índice) do elemento.

    A partir do C++20, a maioria dos algoritmos também tem uma versão no espaço de nomes std::ranges, que recebe o contêiner inteiro em vez do par de iteradores: std::ranges::sort(notas) é o mesmo que std::sort(notas.begin(), notas.end()). Os iteradores, os algoritmos e os ranges são apresentados em detalhes na página Iteradores e algoritmos.

    Lendo o nome dos tipos¶

    Os contêineres da STL são templates de classes: o tipo dos elementos é indicado entre < e >. Assim, std::vector<int> é um vetor de inteiros, std::vector<std::string> é um vetor de cadeias e std::vector<std::vector<int>> é um vetor de vetores de inteiros (uma matriz). Alguns contêineres recebem mais de um parâmetro: std::map<std::string, int> associa chaves do tipo std::string a valores do tipo int, e std::array<double, 10> é um arranjo de 10 números reais. Cada contêiner tem o seu próprio cabeçalho, com o mesmo nome: <vector>, <map>, <array>, e assim por diante.

    Complexidade das operações¶

    Contêineres diferentes têm desempenhos muito diferentes para a mesma operação. Buscar um elemento em um std::vector não ordenado exige, no pior caso, olhar todos os elementos; em um std::set, exige olhar apenas alguns poucos. Para comparar os contêineres, usamos a notação O, apresentada na seção Complexidade de algoritmos, que também explica o que significa uma complexidade amortizada. As páginas seguintes indicam a complexidade das principais operações de cada contêiner, e a biblioteca de códigos traz uma tabela que resume todas elas.

    Na dúvida, use std::vector

    O std::vector é o contêiner mais usado, e deve ser a escolha padrão sempre que não houver um motivo claro para outro. Ele guarda os elementos lado a lado na memória, o que o torna extremamente rápido para percorrer, e na prática supera estruturas teoricamente mais adequadas em muitas situações com poucos milhares de elementos.
