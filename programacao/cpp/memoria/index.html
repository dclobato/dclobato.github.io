    Ponteiros, referências e memória¶

    Durante a execução de um programa, todas as variáveis ficam guardadas na memória do computador. Podemos imaginar a memória como uma rua muito longa, com bilhões de casas numeradas: cada casa guarda um byte, e o número da casa é o seu endereço. Uma variável do tipo int, que ocupa 4 bytes, ocupa quatro casas vizinhas, e o endereço da variável é o endereço da primeira delas.

    Na maior parte do tempo, não precisamos saber onde as variáveis estão: usamos seus nomes, e o compilador cuida dos endereços. Mas há situações em que é útil (ou necessário) trabalhar diretamente com endereços: para que uma função altere uma variável de quem a chamou, para evitar copiar dados grandes, para criar variáveis durante a execução do programa ou para montar estruturas de dados como listas e árvores. Para isso, C++ oferece dois mecanismos: os ponteiros e as referências.

    Ponteiros¶

    Um ponteiro é uma variável que guarda um endereço de memória. Um "ponteiro para T" guarda o endereço de uma variável do tipo T: um ponteiro para int guarda o endereço de um int, um ponteiro para double guarda o endereço de um double, e assim por diante.

    Ponteiros são declarados com um asterisco (*) depois do tipo:

    Declaração de ponteiros
    char* letra;     // 'letra' guarda o endereço de uma variável do tipo char
double* salario; // 'salario' guarda o endereço de uma variável do tipo double
int* faltas;     // 'faltas' guarda o endereço de uma variável do tipo int

    Veja bem, preste atenção!

    O asterisco pertence à variável, e não ao tipo. Na linha int* a, b;, apenas a é um ponteiro; b é um int comum. Para evitar confusão, declare um ponteiro por linha.

    Você vai encontrar as formas int* p, int *p e int * p, que são equivalentes. Neste texto usamos int* p, que destaca que o tipo de p é "ponteiro para int".

    Dois operadores são usados com ponteiros:

    • O operador &, chamado de operador de endereço, devolve o endereço de memória de uma variável. Se x é uma variável inteira, &x é o endereço onde x está guardada, e pode ser atribuído a um ponteiro para int, e;
    • O operador *, chamado de operador de indireção ou de dereferência, acessa a variável que está no endereço guardado pelo ponteiro. Se o ponteiro p guarda o endereço de x, então *p é a variável x: podemos ler o valor de x com *p e alterá-lo com *p = ....

    Ponteiros também podem apontar para outros ponteiros. Um "ponteiro para ponteiro para T" (declarado com **) guarda o endereço de uma variável que, por sua vez, guarda o endereço de um T. Veja o exemplo a seguir:

    #include <iostream>

int main()
{
    int valor = 10;          // variável inteira comum
    int* ptr = &valor;       // ponteiro para a variável 'valor'
    int** ptr_ptr = &ptr;    // ponteiro para o ponteiro 'ptr'

    std::cout << "valor:           " << valor << '\n';
    std::cout << "&valor:          " << &valor << '\n';
    std::cout << "ptr:             " << ptr << '\n';
    std::cout << "*ptr:            " << *ptr << '\n';
    std::cout << "&ptr:            " << &ptr << '\n';
    std::cout << "ptr_ptr:         " << ptr_ptr << '\n';
    std::cout << "*ptr_ptr:        " << *ptr_ptr << '\n';
    std::cout << "**ptr_ptr:       " << **ptr_ptr << '\n';

    *ptr = 25;               // altera 'valor' por meio do ponteiro
    std::cout << "valor agora:     " << valor << '\n';
    return 0;
}

    Os endereços (escritos em hexadecimal) mudam a cada execução, mas as relações entre eles não. Inicialmente, declaramos a variável valor, com o valor 10. Em seguida, declaramos o ponteiro ptr e o inicializamos com o endereço de valor, obtido com &valor: dizemos que ptr "aponta" para valor. Por isso, o conteúdo de ptr é igual a &valor, e *ptr é igual a 10. Depois, declaramos ptr_ptr, que guarda o endereço do próprio ponteiro ptr. Assim, *ptr_ptr é o conteúdo de ptr (o endereço de valor), e **ptr_ptr é o conteúdo de valor. Por fim, a atribuição *ptr = 25 altera a variável valor sem usar o nome dela.

    flowchart LR
  pp["**ptr_ptr**<br/>0x...45c8"] --> p["**ptr**<br/>0x...45c4"] --> v["**valor**<br/>10"]

    É importante entender que um ponteiro é uma variável como outra qualquer: ele ocupa espaço na memória, tem o seu próprio endereço e guarda um valor (que, no caso, é um endereço). O que muda é a forma como esse valor é usado.

    O ponteiro nulo (nullptr)¶

    Um ponteiro que não aponta para nenhuma variável deve guardar o valor especial nullptr, chamado de ponteiro nulo. Dereferenciar um ponteiro nulo é um erro: o programa normalmente é encerrado pelo sistema operacional. Por isso, sempre que um ponteiro puder ser nulo, ele deve ser verificado antes de ser usado:

    #include <iostream>

int main()
{
    int* p = nullptr;   // não aponta para nada

    if (p != nullptr) {
        std::cout << *p << '\n';
    } else {
        std::cout << "O ponteiro é nulo\n";
    }

    int x = 7;
    p = &x;
    if (p) {            // forma abreviada de p != nullptr
        std::cout << "Agora aponta para " << *p << '\n';
    }
    return 0;
}

    Um ponteiro declarado sem inicialização (int* p;) não é nulo: ele guarda um endereço qualquer, e dereferenciá-lo tem comportamento indefinido. Sempre inicialize ponteiros, com o endereço de uma variável ou com nullptr.

    nullptr, NULL e 0

    Em códigos mais antigos, o ponteiro nulo aparece escrito como 0 ou NULL. Os dois são, na verdade, números inteiros, o que pode causar confusão quando uma função aceita tanto um número quanto um ponteiro. O nullptr tem um tipo próprio, que só pode ser convertido em ponteiro, e é a forma correta em C++.

    Ponteiros e arranjos¶

    Ponteiros e arranjos nativos estão intimamente ligados. Quando o nome de um arranjo é usado em uma expressão, ele é convertido automaticamente em um ponteiro para o seu primeiro elemento. Esse comportamento é chamado de decaimento de arranjo (array decay).

    Somar um inteiro i a um ponteiro produz o endereço do elemento que está i posições adiante, levando em conta o tamanho do tipo: se p aponta para um int de 4 bytes, p + 1 aponta para o próximo int, 4 bytes adiante. Isso é chamado de aritmética de ponteiros, e é ela que está por trás do acesso aos elementos de um arranjo: a[i] é exatamente o mesmo que *(a + i).

    #include <iostream>

int main()
{
    int numeros[5] = {10, 20, 30, 40, 50};
    int* p = numeros;   // o nome do arranjo vira um ponteiro para o primeiro elemento

    std::cout << *p << '\n';         // 10
    std::cout << *(p + 2) << '\n';   // 30
    std::cout << p[3] << '\n';       // 40: p[i] é o mesmo que *(p + i)

    for (int* q = numeros; q != numeros + 5; ++q) {
        std::cout << *q << ' ';      // 10 20 30 40 50
    }
    std::cout << '\n';
    return 0;
}

    Veja bem, preste atenção!

    A aritmética de ponteiros só é válida dentro dos limites do arranjo (e uma posição depois do último elemento, que pode ser usada para comparação, como no laço do exemplo, mas nunca dereferenciada). A linguagem não verifica esses limites: se um ponteiro for deslocado para fora do arranjo e dereferenciado, o programa vai ler ou escrever em memória que pertence a outras variáveis. Esse tipo de erro, chamado de estouro de buffer (buffer overflow), pode corromper dados, encerrar o programa e até ser explorado para executar código malicioso.

    Os contêineres da biblioteca padrão, como std::array e std::vector, oferecem o método at(), que verifica os índices, e algoritmos que percorrem os elementos sem que seja preciso manipular ponteiros diretamente.

    Acessando estruturas via ponteiros¶

    Quando temos um ponteiro para uma estrutura, os membros podem ser acessados de duas formas:

    Aniversario abelardo;
Aniversario* p = &abelardo;

p->nome = "Abelardo Silva";
p->dia = 15;
p->mes = 3;
p->ano = 1985;

    Aniversario abelardo;
Aniversario* p = &abelardo;

(*p).nome = "Abelardo Silva";
(*p).dia = 15;
(*p).mes = 3;
(*p).ano = 1985;

    As duas formas são equivalentes: p->membro é apenas uma forma abreviada de (*p).membro. Os parênteses são necessários na segunda forma porque o operador ponto tem precedência maior que o asterisco. O operador seta (->) é usado com muito mais frequência, por ser mais conciso e legível.

    Ponteiros e const¶

    A palavra-chave const pode ser aplicada a um ponteiro de duas formas diferentes, dependendo de onde ela é escrita:

    int a = 1, b = 2;

const int* p1 = &a;   // ponteiro para int constante
// *p1 = 10;          // erro: não pode alterar o valor apontado
p1 = &b;              // permitido: pode apontar para outro lugar

int* const p2 = &a;   // ponteiro constante para int
*p2 = 10;             // permitido: pode alterar o valor apontado
// p2 = &b;           // erro: não pode apontar para outro lugar

const int* const p3 = &a;  // nem uma coisa, nem outra

    Uma forma de ler essas declarações é da direita para a esquerda: const int* p1 é "p1 é um ponteiro para um int constante"; int* const p2 é "p2 é um ponteiro constante para um int". A primeira forma é a mais comum: ela permite que uma função receba o endereço de uma variável com a garantia de que não vai alterá-la.

    Referências¶

    Uma referência é um apelido, um segundo nome para uma variável que já existe. Ela é declarada com o símbolo & depois do tipo, e precisa ser inicializada com a variável à qual vai se referir:

    Uma referência é outro nome para a mesma variável

    #include <iostream>

int main()
{
    int original = 10;
    int& apelido = original;   // apelido passa a ser outro nome para 'original'

    apelido = 20;              // altera 'original'
    std::cout << original << '\n';           // 20

    original = 30;
    std::cout << apelido << '\n';            // 30

    std::cout << std::boolalpha << (&apelido == &original) << '\n';  // true: mesmo endereço
    return 0;
}

    Tudo o que é feito com a referência é feito com a variável original, porque as duas são a mesma variável, no mesmo endereço de memória. Diferentemente de um ponteiro, uma referência não precisa de nenhum operador especial para ser usada: escrevemos apenas apelido, e não *apelido.

    Veja bem, preste atenção!

    O símbolo & tem significados diferentes dependendo de onde aparece:

    • Na declaração de uma variável, depois do tipo (int& r = x;), ele indica que r é uma referência, e;
    • Em uma expressão, antes de um nome (p = &x;), ele é o operador de endereço.

    Da mesma forma, o * declara um ponteiro em int* p e dereferencia um ponteiro em *p = 5.

    Uma referência tem três características importantes:

    • Precisa ser inicializada na declaração. Não existe referência "vazia": int& r; não compila;

    • Não pode ser redirecionada. Depois de criada, a referência fica ligada à mesma variável até deixar de existir. Uma atribuição a ela altera o valor da variável original, e não a variável a que ela se refere:

      int a = 1;
int b = 2;
int& r = a;
r = b;        // NÃO faz r se referir a b: copia o valor de b para a
std::cout << a << ' ' << b << '\n';   // 2 2

    • Não existe referência nula. Por isso, uma referência pode ser usada sem verificação.

    Referências constantes¶

    Uma referência constante (const T&) permite ler a variável original, mas não alterá-la. Ela é muito usada para passar dados grandes para funções sem fazer cópia e com a garantia de que a função não vai modificá-los. Uma referência constante também pode ser ligada a um valor temporário, como um literal ou o resultado de uma expressão, o que não é possível com uma referência comum:

    const int& r1 = 42;        // permitido
const double& r2 = 1.5 * 3;  // permitido
// int& r3 = 42;           // erro: referência comum precisa de uma variável

    Referências no laço for¶

    Um uso muito comum de referências é no laço baseado em intervalo. Sem a referência, a variável do laço recebe uma cópia de cada elemento, e alterá-la não altera o contêiner. Com a referência, ela é um apelido de cada elemento:

    #include <iostream>
#include <vector>

int main()
{
    std::vector<int> notas = {5, 7, 6, 9};

    for (int n : notas) {      // n é uma cópia de cada elemento
        n = n + 1;             // altera só a cópia
    }
    for (int n : notas) std::cout << n << ' ';   // 5 7 6 9
    std::cout << '\n';

    for (int& n : notas) {     // n é um apelido de cada elemento
        n = n + 1;             // altera o elemento do vetor
    }
    for (int n : notas) std::cout << n << ' ';   // 6 8 7 10
    std::cout << '\n';
    return 0;
}

    Quando os elementos são grandes (como cadeias de caracteres ou estruturas) e só precisam ser lidos, a forma recomendada é for (const auto& elemento : conteiner): não há cópia, e o compilador impede alterações acidentais.

    Ponteiros ou referências?¶

    Característica Ponteiro (T*) Referência (T&)
    Precisa ser inicializado na declaração Não (mas deveria) Sim
    Pode ser nulo Sim (nullptr) Não
    Pode passar a apontar/referir para outra variável Sim Não
    Sintaxe de uso *p, p->membro r, r.membro
    Tem aritmética Sim Não

    Uma regra prática: use referências sempre que possível, e ponteiros quando for necessário representar a ausência de valor (nullptr), mudar o alvo durante a execução, ou trabalhar com memória dinâmica. O uso mais importante de ponteiros e referências, a passagem de parâmetros para funções, é apresentado na seção de funções.

    Memória automática e memória dinâmica¶

    As variáveis de um programa podem ficar em três regiões da memória, que diferem no tempo de vida e no tamanho disponível:

    Região O que fica nela Quando é criada Quando é liberada Tamanho
    Pilha (stack), ou memória automática Variáveis locais e parâmetros Quando a execução chega à declaração Automaticamente, quando a execução sai do bloco ou da função Pequeno: costuma ser de 8 MB no Linux e de 1 MB no Windows
    Memória estática Variáveis globais e variáveis locais static Antes de o programa começar (com todos os bytes zerados) Quando o programa termina Limitado apenas pela memória disponível
    Heap, ou memória dinâmica Objetos criados com new, e os elementos dos contêineres da biblioteca padrão Quando o programa pede, durante a execução Com delete, ou automaticamente pelos contêineres e ponteiros inteligentes Limitado apenas pela memória disponível

    As variáveis que declaramos até agora são automáticas: elas são criadas quando a execução chega à declaração e destruídas automaticamente quando a execução sai do bloco ({ ... }) em que foram declaradas. A pilha é rápida, mas tem duas limitações. A primeira é o tamanho: um arranjo local muito grande não cabe na pilha, e o programa é encerrado com Segmentation fault assim que começa a usá-lo:

    Declarar o arranjo como static (ou como variável global) o coloca na memória estática, onde há espaço de sobra; essa é uma prática comum em programação competitiva, em que o tamanho máximo da entrada é conhecido. A solução mais comum, porém, é usar um std::vector: a variável v fica na pilha, mas ocupa só 24 bytes, porque guarda apenas o endereço e o tamanho dos elementos, que ficam no heap. Todos os contêineres da biblioteca padrão funcionam assim, e por isso um std::vector com milhões de elementos pode ser uma variável local sem nenhum problema.

    A segunda limitação da pilha é que o tamanho de cada variável precisa ser conhecido durante a compilação, e não pode mudar depois.

    Quando precisamos de uma quantidade de memória que só é conhecida durante a execução, ou de uma variável que continue existindo depois que o bloco em que foi criada termina, usamos a memória dinâmica, alocada em outra região, chamada de heap. Em C++, a memória dinâmica é alocada com o operador new, que devolve o endereço da memória alocada, e liberada com delete:

    #include <iostream>

int main()
{
    int* p = new int(42);         // cria um int na memória dinâmica
    std::cout << *p << '\n';      // 42
    delete p;                     // devolve a memória
    p = nullptr;                  // evita usar o endereço liberado por engano

    int n = 5;
    int* v = new int[n];          // arranjo com tamanho definido na execução
    for (int i = 0; i < n; ++i) {
        v[i] = i * i;
    }
    for (int i = 0; i < n; ++i) {
        std::cout << v[i] << ' '; // 0 1 4 9 16
    }
    std::cout << '\n';
    delete[] v;                   // arranjos são liberados com delete[]
    return 0;
}

    A memória alocada com new não é liberada automaticamente: ela continua ocupada até que o programa execute o delete correspondente (ou até o programa terminar). Essa responsabilidade é a origem de alguns dos erros mais comuns e mais difíceis de encontrar em C++:

    Erros comuns com memória dinâmica

    • Vazamento de memória (memory leak): esquecer o delete, ou perder o último ponteiro que guardava o endereço da memória alocada. A memória fica ocupada sem que ninguém possa usá-la ou liberá-la. Em um programa que roda por muito tempo, os vazamentos vão consumindo a memória do computador aos poucos;
    • Ponteiro pendente (dangling pointer): usar um ponteiro depois que a memória para a qual ele aponta foi liberada. O endereço continua guardado no ponteiro, mas a memória pode já ter sido entregue a outra parte do programa. As consequências não são previsíveis;
    • Liberação dupla (double free): executar delete duas vezes no mesmo endereço, o que normalmente corrompe as estruturas internas de gerenciamento de memória e encerra o programa, e;
    • Forma errada de liberação: usar delete em memória alocada com new[], ou delete[] em memória alocada com new. O resultado é comportamento indefinido.

    Por esses motivos, em C++ moderno, new e delete raramente são usados diretamente. Para sequências de tamanho variável, usa-se std::vector, que aloca e libera a memória sozinho. Para objetos individuais na memória dinâmica, usam-se os ponteiros inteligentes.

    Deixe o compilador procurar os erros por você

    O GCC tem um modo de compilação que verifica, durante a execução, todos os acessos à memória: a opção -fsanitize=address (o AddressSanitizer). O programa fica mais lento, mas, quando um dos erros acima acontece (ou quando um arranjo é acessado fora dos limites), ele é interrompido com uma mensagem que diz qual foi o erro e em que linha do código fonte ele aconteceu. Compile também com -g, para que as linhas apareçam na mensagem:

    g++ -std=c++20 -Wall -Wextra -g -fsanitize=address -o programa programa.cpp

    Use essa opção enquanto testa o programa, e compile sem ela a versão final.

    Ponteiros inteligentes¶

    Um ponteiro inteligente é um objeto que guarda um ponteiro e libera automaticamente a memória apontada quando deixa de existir. Ele segue um princípio muito importante em C++, chamado RAII (Resource Acquisition Is Initialization): um recurso (memória, arquivo aberto, conexão de rede) é adquirido na criação de um objeto e liberado automaticamente na destruição desse objeto. Como os objetos automáticos são destruídos ao final do bloco em que foram criados, o recurso é sempre liberado, mesmo que o programador esqueça ou que ocorra um erro no meio do caminho.

    Os ponteiros inteligentes estão no cabeçalho <memory>. Os dois principais são std::unique_ptr e std::shared_ptr.

    std::unique_ptr¶

    Um std::unique_ptr é o único dono da memória para a qual aponta. Ele é criado com a função std::make_unique, usado como um ponteiro comum (com * e ->), e libera a memória automaticamente quando deixa de existir. Como a posse é única, um std::unique_ptr não pode ser copiado; a posse pode, porém, ser transferida para outro std::unique_ptr com std::move.

    #include <iostream>
#include <memory>
#include <string>
#include <utility>

struct Sensor {
    std::string nome;
    double leitura;
};

int main()
{
    std::unique_ptr<Sensor> s = std::make_unique<Sensor>(Sensor{"temperatura", 23.5});
    std::cout << s->nome << ": " << s->leitura << '\n';

    // std::unique_ptr<Sensor> copia = s;            // erro: não pode ser copiado
    std::unique_ptr<Sensor> novo_dono = std::move(s); // a posse é transferida

    std::cout << std::boolalpha << (s == nullptr) << '\n';   // true: s não é mais dono de nada
    std::cout << novo_dono->nome << '\n';

    return 0;   // a memória do Sensor é liberada automaticamente aqui
}

    Não há nenhum delete no programa, e mesmo assim não há vazamento de memória: quando novo_dono deixa de existir, no final de main, ele libera o Sensor. Na grande maioria dos casos em que é preciso alocar um objeto na memória dinâmica, std::unique_ptr é a escolha certa.

    std::shared_ptr¶

    Um std::shared_ptr permite que vários ponteiros sejam donos compartilhados do mesmo objeto. Ele mantém uma contagem de quantos donos o objeto tem; cada cópia do ponteiro aumenta a contagem, e cada cópia destruída a diminui. Quando a contagem chega a zero, o objeto é liberado. Ele é criado com a função std::make_shared:

    std::cout << "Donos: " << a.use_count() << '\n';       // 1

    {
        std::shared_ptr<int> b = a;                        // a e b compartilham o mesmo int
        *b = 200;
        std::cout << "Donos: " << a.use_count() << '\n';   // 2
    }                                                      // b deixa de existir aqui

    std::cout << "Donos: " << a.use_count() << '\n';       // 1
    std::cout << "Valor: " << *a << '\n';                  // 200
    return 0;
}

    O controle da contagem tem um custo, e a posse compartilhada torna mais difícil saber quando um objeto vai ser liberado. Por isso, use std::shared_ptr apenas quando o compartilhamento for realmente necessário, e prefira std::unique_ptr nos demais casos.

    Resumo: quem é dono da memória?

    • Para sequências de elementos, use std::vector (ou outro contêiner da biblioteca padrão);
    • Para um objeto na memória dinâmica com um único dono, use std::unique_ptr, criado com std::make_unique;
    • Para um objeto compartilhado por vários donos, use std::shared_ptr, criado com std::make_shared, e;
    • Use ponteiros comuns (T*) e referências apenas para observar ou acessar objetos que pertencem a outra parte do programa, nunca para ser dono deles.

    Seguindo essas regras, new e delete praticamente desaparecem do código, e com eles os vazamentos de memória e as liberações duplas.

    Mover em vez de copiar

    O std::move usado com o std::unique_ptr faz parte de um recurso da linguagem chamado semântica de movimento. A ideia é simples: quando um objeto não vai mais ser usado, em vez de copiar todo o seu conteúdo para outro objeto, podemos "transferir" os recursos dele (por exemplo, a memória que ele aloca) para o novo dono, o que é muito mais rápido. Depois da transferência, o objeto original fica em um estado válido, mas não especificado (no caso do std::unique_ptr, ele passa a ser nulo), e não deve mais ser usado, a não ser que receba um novo valor.

    A biblioteca padrão usa a semântica de movimento internamente o tempo todo: é por causa dela que devolver um std::vector com milhões de elementos de uma função não exige copiar esses elementos. Para quem está começando, basta saber que ela existe e que std::move é a forma de pedir explicitamente uma transferência.

    Riscos e vantagens dos ponteiros¶

    A manipulação direta de memória com ponteiros é frequentemente considerada um dos aspectos mais desafiadores de C++. Ela tanto possibilita operações poderosas quanto introduz riscos significativos de erros: vazamentos de memória, ponteiros pendentes, liberações duplas, acessos fora dos limites de arranjos e dereferências de ponteiros nulos ou não inicializados. Como ponteiros são, essencialmente, números que podem ser manipulados por aritmética, um erro de cálculo pode fazer com que apontem para qualquer lugar da memória; apontar para um lugar inválido não é, por si só, um problema, mas dereferenciar esse ponteiro é.

    Por outro lado, os ponteiros permitem escrever código altamente eficiente, acessando e modificando dados diretamente na memória, o que é essencial em aplicações que exigem alto desempenho, como jogos, sistemas embarcados e drivers de dispositivos. Eles também permitem a criação de estruturas de dados dinâmicas, como listas ligadas e árvores, que crescem e diminuem conforme necessário. Boa parte da biblioteca padrão de C++ é construída sobre ponteiros, mesmo que eles fiquem escondidos.

    Em C++, uma abordagem disciplinada elimina a maior parte dos problemas: inicializar sempre os ponteiros (com nullptr, quando não houver um endereço válido), verificar se são nulos antes de dereferenciá-los, preferir referências a ponteiros quando possível, e deixar a posse da memória com contêineres e ponteiros inteligentes, que a liberam automaticamente.
