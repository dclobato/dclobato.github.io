    Orientação a objetos¶

    A Programação Orientada a Objetos (POO) é um paradigma de programação que organiza o código em torno de objetos: entidades que reúnem dados (os atributos) e as operações que atuam sobre esses dados (os métodos). Em vez de pensar no programa como uma sequência de funções que manipulam dados soltos, pensamos em objetos que representam coisas do problema (uma conta bancária, um aluno, um produto, uma figura geométrica) e que sabem cuidar dos próprios dados.

    C++ oferece suporte completo à orientação a objetos, e foi justamente para isso que a linguagem foi criada.

    Classes e objetos¶

    Uma classe é um modelo que define quais atributos e métodos os objetos de um tipo terão. Um objeto é uma instância concreta de uma classe, com seus próprios valores para cada atributo. A classe Pessoa, por exemplo, define que toda pessoa tem um nome e uma idade e sabe se apresentar; os objetos p1 e p2 são duas pessoas específicas.

    #include <iostream>
#include <string>

class Pessoa {
public:
    std::string nome;
    int idade;

    void apresentar() const
    {
        std::cout << "Olá, meu nome é " << nome << " e tenho " << idade << " anos.\n";
    }

    void fazer_aniversario()
    {
        ++idade;
    }
};

int main()
{
    Pessoa p1;
    p1.nome = "Ana";
    p1.idade = 30;

    Pessoa p2{"Carlos", 25};

    p1.apresentar();          // Olá, meu nome é Ana e tenho 30 anos.
    p2.apresentar();          // Olá, meu nome é Carlos e tenho 25 anos.

    p1.fazer_aniversario();
    p1.apresentar();          // Olá, meu nome é Ana e tenho 31 anos.
    return 0;
}

    A classe é declarada com a palavra-chave class, seguida do nome e do corpo entre chaves, terminado por ponto e vírgula (que é frequentemente esquecido). Os métodos são funções declaradas dentro da classe; quando chamados em um objeto, como em p1.apresentar(), eles acessam diretamente os atributos daquele objeto. Por isso, p1.fazer_aniversario() altera a idade de p1, e não a de p2.

    O const depois dos parênteses de apresentar indica que esse método não altera o objeto; voltaremos a ele adiante.

    class ou struct?

    Em C++, class e struct permitem atributos, métodos, construtores e herança. Diferem no acesso padrão dos membros e da herança: público em struct, privado em class. Especificadores explícitos substituem esses padrões. Por convenção, struct costuma representar registros simples, e class, objetos cujas regras precisam ser protegidas.

    Encapsulamento¶

    O encapsulamento é o princípio de esconder os detalhes internos de um objeto e expor apenas uma interface controlada para o mundo exterior. Na classe Pessoa, qualquer parte do programa pode escrever p1.idade = -50;, deixando o objeto em um estado sem sentido. Com o encapsulamento, os atributos ficam protegidos, e só podem ser alterados pelos métodos da classe, que garantem que as regras sejam respeitadas.

    O acesso aos membros de uma classe é controlado por três especificadores de acesso:

    public Qualquer parte do programa
    private Apenas os métodos da própria classe
    protected Os métodos da própria classe e das classes derivadas dela (veja a seção sobre herança)

    #include <iostream>
#include <string>
#include <vector>

class ContaBancaria {
public:
    ContaBancaria(const std::string& titular, double saldo_inicial)
        : titular_(titular), saldo_(saldo_inicial)
    {
    }

    void depositar(double valor)
    {
        if (valor > 0) {
            saldo_ += valor;
            historico_.push_back("Depósito: " + std::to_string(valor));
        }
    }

    bool sacar(double valor)
    {
        if (valor > 0 && valor <= saldo_) {
            saldo_ -= valor;
            historico_.push_back("Saque: " + std::to_string(valor));
            return true;
        }
        return false;
    }

    double saldo() const
    {
        return saldo_;
    }

    const std::string& titular() const
    {
        return titular_;
    }

private:
    std::string titular_;
    double saldo_;
    std::vector<std::string> historico_;
};

int main()
{
    ContaBancaria conta("Maria", 1000);
    conta.depositar(500);
    if (!conta.sacar(2000)) {
        std::cout << "Saque recusado\n";
    }
    conta.sacar(300);
    std::cout << conta.titular() << " tem saldo de " << conta.saldo() << '\n';  // Maria tem saldo de 1200
    // conta.saldo_ = 1000000;   // erro: 'saldo_' é privado
    return 0;
}

    O saldo só pode ser alterado por depositar e sacar, que recusam valores negativos e saques maiores que o saldo, e registram cada operação no histórico. Não há como o restante do programa deixar a conta em um estado inválido: uma tentativa de acessar saldo_ diretamente gera o erro de compilação 'double ContaBancaria::saldo_' is private within this context.

    O sublinhado no final dos nomes dos atributos privados (saldo_, titular_) é uma convenção comum, que ajuda a distinguir atributos de variáveis locais e parâmetros, e permite usar o nome sem sublinhado (saldo()) para o método que devolve o valor.

    Construtores¶

    Um construtor é um método especial, executado automaticamente quando um objeto é criado. Ele tem o mesmo nome da classe e não tem tipo de retorno. Sua função é deixar o objeto em um estado válido desde o primeiro instante, inicializando todos os atributos. Uma classe pode ter vários construtores, com parâmetros diferentes (é um caso de sobrecarga).

    Os atributos podem ser inicializados na declaração ou na lista de inicialização de membros, escrita entre os parênteses dos parâmetros e o corpo do construtor, depois de dois pontos:

class Ponto {
public:
    Ponto() : x_(0), y_(0)                       // construtor padrão
    {
        std::cout << "Ponto() -> (" << x_ << ", " << y_ << ")\n";
    }

    Ponto(double x, double y) : x_(x), y_(y)     // construtor com parâmetros
    {
        std::cout << "Ponto(x, y) -> (" << x_ << ", " << y_ << ")\n";
    }

    double x() const { return x_; }
    double y() const { return y_; }

private:
    double x_;
    double y_;
};

class Retangulo {
public:
    Retangulo(Ponto canto, double largura, double altura)
        : canto_(canto), largura_(largura), altura_(altura)
    {
    }

    double area() const { return largura_ * altura_; }

private:
    Ponto canto_;
    double largura_;
    double altura_;
};

int main()
{
    Ponto origem;              // chama o construtor padrão
    Ponto p(3, 4);             // chama o construtor com parâmetros
    Ponto q{1.5, -2};          // o mesmo, com chaves

    Retangulo r(p, 10, 5);
    std::cout << "Área: " << r.area() << '\n';   // Área: 50
    return 0;
}

    Um construtor padrão pode ser chamado sem argumentos; ele também pode ter parâmetros, se todos tiverem valores padrão. Se a classe não declarar construtores, o compilador normalmente declara um padrão, mas ele pode ser definido como excluído (deleted) se uma base ou um atributo não puder ser inicializado. Declarar outro construtor normalmente impede essa declaração automática; use = default quando apropriado.

    Veja bem, preste atenção!

    Para criar um objeto com o construtor padrão, não use parênteses vazios: Ponto origem(); não cria um objeto, e sim declara uma função chamada origem, sem parâmetros, que devolve um Ponto. Use Ponto origem; ou Ponto origem{};.

    Os atributos também podem receber valores padrão diretamente na declaração. Eles são usados por todos os construtores que não inicializarem aquele atributo na lista de inicialização. Combinado com = default, que pede ao compilador para gerar o construtor padrão, isso evita repetir valores iniciais em vários construtores:

#include <string>

class Configuracao {
public:
    Configuracao() = default;
    explicit Configuracao(int volume) : volume_(volume) {}

    void mostrar() const
    {
        std::cout << idioma_ << ", volume " << volume_ << ", tela cheia: " << std::boolalpha << tela_cheia_ << '\n';
    }

private:
    std::string idioma_ = "pt-BR";   // valores padrão dos membros
    int volume_ = 50;
    bool tela_cheia_ = false;
};

int main()
{
    Configuracao a;       // pt-BR, volume 50, tela cheia: false
    Configuracao b(80);   // pt-BR, volume 80, tela cheia: false
    a.mostrar();
    b.mostrar();
    return 0;
}

    A palavra-chave explicit em um construtor de um único parâmetro impede que ele seja usado para conversões automáticas. Sem ela, uma linha como Configuracao c = 80; seria aceita, convertendo silenciosamente o número em uma configuração. Declare como explicit todo construtor de um único parâmetro, a menos que a conversão automática seja realmente desejada.

    Destrutores e RAII¶

    Um destrutor é o método especial executado automaticamente quando um objeto deixa de existir: ao final do bloco em que foi declarado, no caso de objetos automáticos. Ele tem o nome da classe precedido de ~, não tem parâmetros nem tipo de retorno, e serve para liberar os recursos que o objeto adquiriu.

#include <string>

class Recurso {
public:
    explicit Recurso(const std::string& nome) : nome_(nome)
    {
        std::cout << "Adquirindo " << nome_ << '\n';
    }

    ~Recurso()
    {
        std::cout << "Liberando " << nome_ << '\n';
    }

private:
    std::string nome_;
};

int main()
{
    Recurso a("A");
    {
        Recurso b("B");
        Recurso c("C");
        std::cout << "Fim do bloco interno\n";
    }
    std::cout << "Fim de main\n";
    return 0;
}
    Saída
    Adquirindo A
Adquirindo B
Adquirindo C
Fim do bloco interno
Liberando C
Liberando B
Fim de main
Liberando A

    Objetos automáticos são destruídos na ordem inversa à da construção na saída normal do bloco, incluindo return e break, e no desenrolamento da pilha para tratar exceções. Encerramentos abruptos não oferecem essa garantia. Essa garantia é a base do princípio RAII (Resource Acquisition Is Initialization), que já apareceu nas seções sobre memória e arquivos: um recurso é adquirido no construtor e liberado no destrutor, e por isso nunca é esquecido. É assim que funcionam std::string, std::vector, std::ofstream e std::unique_ptr.

    A regra do zero

    Na grande maioria das classes, não é preciso escrever um destrutor. Se os atributos forem tipos que já cuidam dos próprios recursos (números, std::string, contêineres da biblioteca padrão, ponteiros inteligentes), o destrutor gerado automaticamente pelo compilador destrói cada atributo corretamente, e as operações de cópia e movimento seguem as capacidades desses atributos. Um atributo unique_ptr, por exemplo, impede a cópia automática da classe. Essa recomendação é conhecida como "regra do zero". Um destrutor escrito à mão só é necessário em classes que gerenciam diretamente um recurso, como memória alocada com new, e essas classes exigem cuidados adicionais com cópias, que vão além deste texto.

    #include <iostream>
#include <stdexcept>
#include <string>

class Produto {
public:
    Produto(const std::string& nome, double preco)
        : nome_(nome)
    {
        set_preco(preco);           // reaproveita a validação
    }

    const std::string& nome() const { return nome_; }   // somente leitura: não há setter

    double preco() const { return preco_; }

    void set_preco(double preco)
    {
        if (preco < 0) {
            throw std::invalid_argument("preço não pode ser negativo");
        }
        preco_ = preco;
    }

    double preco_com_desconto(double percentual) const
    {
        return preco_ * (1 - percentual / 100);
    }

private:
    std::string nome_;
    double preco_ = 0;
};

int main()
{
    Produto p("Teclado", 150.0);
    std::cout << p.nome() << ": " << p.preco() << '\n';                  // Teclado: 150

    p.set_preco(129.9);
    std::cout << "Novo preço: " << p.preco() << '\n';                    // 129.9
    std::cout << "Com 10% de desconto: " << p.preco_com_desconto(10) << '\n';  // 116.91

    try {
        p.set_preco(-5);
    } catch (const std::invalid_argument& e) {
        std::cout << "Erro: " << e.what() << '\n';                       // Erro: preço não pode ser negativo
    }
    std::cout << "Preço continua: " << p.preco() << '\n';                // 129.9
    return 0;
}

    O exemplo mostra três ideias importantes:

    • Validação: o setter set_preco recusa preços negativos, lançando uma exceção. O construtor também usa set_preco, para que a mesma regra valha na criação do objeto;
    • Atributos somente leitura: o nome do produto tem getter, mas não tem setter. Depois que o objeto é criado, o nome não pode mais ser alterado;
    • Valores calculados: preco_com_desconto não corresponde a nenhum atributo, mas é usado da mesma forma que um getter. Quem usa a classe não precisa saber se um valor está guardado ou é calculado.

    O getter nome() devolve uma referência constante (const std::string&), o que evita copiar a cadeia a cada chamada e, ao mesmo tempo, impede que ela seja alterada por quem chamou o método.

    Métodos const¶

    Um método declarado com const depois dos parênteses promete não alterar o objeto. O compilador verifica essa promessa: uma tentativa de alterar um atributo dentro de um método const gera um erro (assignment of member in read-only object).

    Mais importante: só os métodos const podem ser chamados em objetos constantes, e objetos recebidos por referência constante (const Produto&, a forma mais comum de passar objetos para funções) são constantes. Se o getter preco() não fosse const, uma função que recebesse um const Produto& não conseguiria nem consultar o preço (passing 'const Produto' as 'this' argument discards qualifiers).

    Use const sempre que possível

    Declare como const todo método que não altera o objeto: getters, métodos de consulta, métodos de cálculo e métodos que apenas escrevem o objeto na tela. Isso documenta a intenção, evita alterações acidentais e permite que os objetos sejam passados por referência constante.

    Vantagens dos getters e setters

    • Validação: os dados são verificados antes de serem armazenados, e o objeto nunca fica em um estado inválido;
    • Flexibilidade: a forma como os dados são armazenados internamente pode mudar sem afetar o código que usa a classe;
    • Controle de acesso: atributos podem ser somente leitura (apenas getter);
    • Depuração: é possível registrar, em um único lugar, todas as alterações de um atributo.

    Por outro lado, não crie getters e setters automaticamente para todos os atributos: um setter sem nenhuma validação para cada atributo privado é, na prática, o mesmo que deixar os atributos públicos. Pense em quais operações fazem sentido para o objeto (como depositar e sacar, em vez de set_saldo).

    Ordem de inicialização

    As classes base são inicializadas antes dos atributos, e os atributos seguem a ordem de declaração na classe, independentemente da ordem escrita na lista de inicialização. Escreva a lista nessa mesma ordem e não use um atributo que ainda não foi inicializado.

    Membros estáticos¶

    Um atributo declarado com static pertence à classe, e não a cada objeto: existe uma única cópia, compartilhada por todos os objetos. Da mesma forma, um método static pode ser chamado sem nenhum objeto, usando o nome da classe e o operador ::, e não tem um objeto implícito (this). Ele pode acessar membros não estáticos se receber ou criar um objeto para isso.

class Aluno {
public:
    explicit Aluno(const std::string& nome) : nome_(nome), matricula_(++total_)
    {
    }

    void mostrar() const
    {
        std::cout << matricula_ << " - " << nome_ << '\n';

private:
    std::string nome_;
    int matricula_;
    static inline int total_ = 0;    // compartilhado por todos os objetos
};

int main()
{
    Aluno a("Ana");
    Aluno b("Bruno");
    Aluno c("Carla");
    a.mostrar();                                                  // 1 - Ana
    c.mostrar();                                                  // 3 - Carla
    std::cout << "Total de alunos: " << Aluno::total() << '\n';   // 3
    return 0;
}

    Cada novo aluno incrementa o contador compartilhado total_, e usa o valor como sua matrícula. A palavra inline permite inicializar o atributo estático dentro da própria classe.

    Herança¶

    A herança permite criar uma nova classe a partir de uma classe existente, aproveitando seus atributos e métodos. A nova classe (chamada de classe derivada, ou subclasse) contém uma parte correspondente à classe original (a classe base, ou superclasse), respeita suas regras de acesso, e pode acrescentar novos atributos e métodos. A herança representa uma relação do tipo "é um": um cachorro é um animal, um aluno é uma pessoa.

    #include <iostream>
#include <string>

class Animal {
public:
    explicit Animal(const std::string& nome) : nome_(nome) {}

    void comer() const
    {
        std::cout << nome_ << " está comendo.\n";
    }

    const std::string& nome() const { return nome_; }

protected:
    std::string nome_;
};

class Cachorro : public Animal {
public:
    Cachorro(const std::string& nome, const std::string& raca)
        : Animal(nome), raca_(raca)        // chama o construtor da classe base
    {
    }

    void latir() const
    {
        std::cout << nome_ << " (" << raca_ << ") diz: Au au!\n";   // nome_ é protected
    }

private:
    std::string raca_;
};

int main()
{
    Cachorro rex("Rex", "vira-lata");
    rex.comer();      // herdado de Animal: Rex está comendo.
    rex.latir();      // próprio de Cachorro: Rex (vira-lata) diz: Au au!
    return 0;
}

    A linha class Cachorro : public Animal declara que Cachorro herda publicamente de Animal: os membros públicos de Animal continuam públicos em Cachorro. O construtor da classe derivada chama o construtor da classe base na lista de inicialização (: Animal(nome)). O atributo nome_ foi declarado como protected, e por isso pode ser acessado pelos métodos de Cachorro, mas não pelo restante do programa.

    Polimorfismo¶

    O polimorfismo permite que objetos de classes diferentes sejam tratados por meio de uma interface comum, e que cada um responda à mesma chamada à sua maneira. Uma função que recebe um Animal pode mandar qualquer animal "falar", e cada um vai emitir o seu próprio som, sem que a função precise saber se o animal é um cachorro, um gato ou uma vaca.

    #include <iostream>
#include <memory>
#include <string>
#include <vector>

class Animal {
public:
    explicit Animal(const std::string& nome) : nome_(nome) {}
    virtual ~Animal() = default;                        // destrutor virtual

    virtual std::string som() const = 0;                // função virtual pura

    void falar() const
    {
        std::cout << nome_ << " diz: " << som() << '\n';
    }

protected:
    std::string nome_;
};

class Cachorro : public Animal {
public:
    using Animal::Animal;                               // herda os construtores
    std::string som() const override { return "Au au!"; }
};

class Gato : public Animal {
public:
    using Animal::Animal;
    std::string som() const override { return "Miau!"; }
};

class Vaca : public Animal {
public:
    using Animal::Animal;
    std::string som() const override { return "Muuu!"; }
};

void apresentar(const Animal& a)                        // aceita qualquer Animal
{
    a.falar();
}

int main()
{
    std::vector<std::unique_ptr<Animal>> fazenda;
    fazenda.push_back(std::make_unique<Cachorro>("Rex"));
    fazenda.push_back(std::make_unique<Gato>("Mimi"));
    fazenda.push_back(std::make_unique<Vaca>("Mimosa"));

    for (const auto& animal : fazenda) {
        animal->falar();
    }

    Gato tom("Tom");
    apresentar(tom);
    return 0;
}
    Saída
    Rex diz: Au au!
Mimi diz: Miau!
Mimosa diz: Muuu!
Tom diz: Miau!

    Vários elementos trabalham juntos neste exemplo:

    • virtual: indica que o método pode ser redefinido pelas classes derivadas, e que a versão executada deve ser escolhida durante a execução, de acordo com o tipo real do objeto. Quando falar() chama som(), é executada a versão de Cachorro, de Gato ou de Vaca, conforme o objeto;
    • = 0: transforma som() em uma função virtual pura. Neste exemplo, ela não tem implementação na base; uma função pura pode ter uma definição separada, sem deixar de ser pura. Uma classe com pelo menos uma função virtual pura é uma classe abstrata: ela não pode ter objetos (Animal a("x"); não compila), e serve como base. Uma derivada só pode ser instanciada se não restarem funções virtuais puras sem uma implementação final concreta;
    • override: indica que o método redefine um método virtual da classe base. Ele não é obrigatório, mas deve ser usado sempre, porque o compilador verifica se realmente existe um método virtual correspondente. Se a assinatura estiver diferente (por exemplo, sem o const), o compilador acusa o erro (marked 'override', but does not override), em vez de criar silenciosamente um método novo;
    • Destrutor virtual: se a hierarquia permite destruir objetos derivados por um ponteiro para a base, o destrutor da base deve ser virtual. Sem isso, o delete do exemplo tem comportamento indefinido, não apenas uma destruição incompleta. Uma alternativa de projeto é impedir essa exclusão pela base com um destrutor protegido não virtual;
    • using Animal::Animal;: faz com que as classes derivadas herdem os construtores da classe base, sem precisar reescrevê-los;
    • Coleções polimórficas: para guardar animais de tipos diferentes no mesmo vetor, guardamos ponteiros para a classe base (aqui, std::unique_ptr<Animal>, que libera cada animal automaticamente). A função apresentar, que recebe uma referência para Animal, funciona com qualquer animal pelo mesmo motivo.

    Veja bem, preste atenção!

    O polimorfismo de execução usa funções virtuais. Referências e ponteiros para a base permitem preservar o tipo dinâmico de um objeto derivado; chamadas virtuais também podem usar a sintaxe com ponto sobre um objeto. Sem virtual, quem decide qual versão executar é o tipo declarado da referência, e não o tipo real do objeto:

    class Animal { public: void som() const { std::cout << "...\n"; } };
class Gato : public Animal { public: void som() const { std::cout << "Miau!\n"; } };

Gato g;
const Animal& a = g;
a.som();     // "...": sem virtual, quem decide é o tipo da referência

    E guardar objetos derivados diretamente em variáveis (ou em um std::vector) do tipo da classe base copia apenas a parte da classe base, perdendo o resto. Esse problema é chamado de fatiamento (slicing).

    Uma classe ou um método marcado com final não pode mais ser herdado ou redefinido.

    #include <algorithm>
#include <iostream>
#include <vector>

class Fracao {
public:
    Fracao(int num, int den = 1) : num_(num), den_(den) {}

    Fracao operator+(const Fracao& outra) const
    {
        return Fracao(num_ * outra.den_ + outra.num_ * den_, den_ * outra.den_);
    }

    Fracao operator*(const Fracao& outra) const
    {
        return Fracao(num_ * outra.num_, den_ * outra.den_);
    }

    bool operator==(const Fracao& outra) const
    {
        return num_ * outra.den_ == outra.num_ * den_;
    }

    bool operator<(const Fracao& outra) const
    {
        return num_ * outra.den_ < outra.num_ * den_;    // supõe denominadores positivos
    }

    friend std::ostream& operator<<(std::ostream& os, const Fracao& f)
    {
        return os << f.num_ << '/' << f.den_;
    }

private:
    int num_;
    int den_;
};

int main()
{
    Fracao a(1, 2);
    Fracao b(1, 3);

    std::cout << a << " + " << b << " = " << a + b << '\n';   // 1/2 + 1/3 = 5/6
    std::cout << a << " * " << b << " = " << a * b << '\n';   // 1/2 * 1/3 = 1/6
    std::cout << std::boolalpha << (Fracao(2, 4) == a) << ' ' << (b < a) << '\n';  // true true

    std::vector<Fracao> v = {Fracao(3, 4), Fracao(1, 8), Fracao(1, 2)};
    std::sort(v.begin(), v.end());                // usa operator<
    for (const auto& f : v) std::cout << f << ' ';   // 1/8 1/2 3/4
    std::cout << '\n';
    return 0;
}

    Alguns detalhes:

    • a + b é transformado pelo compilador em a.operator+(b): o objeto da esquerda é o objeto em que o método é chamado, e o da direita é o parâmetro;
    • O operador << para escrita em fluxos tem um std::ostream à esquerda, e não uma Fracao. Por isso, ele não pode ser um método de Fracao; ele é declarado como uma função friend ("amiga"), que não é um método, mas tem acesso aos membros privados da classe. Ele devolve o próprio fluxo, para que as saídas possam ser encadeadas;
    • Com operator< definido, objetos do tipo Fracao podem ser ordenados com std::sort e usados como elementos de std::set ou como chaves de std::map, que dependem dessa comparação.

    Comparações geradas automaticamente¶

    #include <compare>
#include <iostream>
#include <set>

struct Data {
    int ano;
    int mes;
    int dia;

    auto operator<=>(const Data&) const = default;   // gera <, <=, >, >=, == e !=
};

int main()
{
    Data a{2026, 3, 15};
    Data b{2026, 11, 2};
    std::cout << std::boolalpha << (a < b) << ' ' << (a == b) << ' ' << (a != b) << '\n';  // true false true

    std::set<Data> feriados = {{2026, 12, 25}, {2026, 1, 1}, {2026, 9, 7}};
    for (const Data& d : feriados) {                 // em ordem cronológica
        std::cout << d.dia << '/' << d.mes << '/' << d.ano << '\n';
    }
    return 0;
}

    Como os atributos estão declarados na ordem ano, mês e dia, a comparação gerada coloca as datas em ordem cronológica. Para gerar apenas a igualdade (== e !=), basta bool operator==(const Data&) const = default;.

    #include <algorithm>
#include <iostream>
#include <string>
#include <vector>

struct Jogador {
    std::string nome;
    int pontos = 0;
    int vitorias = 0;

    bool operator==(const Jogador&) const = default;
};

int main()
{
    std::vector<Jogador> ranking = {
        {"Ana", 30, 9},
        {"Bruno", 30, 10},
        {.nome = "Carla", .pontos = 25},
    };

    std::sort(ranking.begin(), ranking.end(), [](const Jogador& a, const Jogador& b) {
        if (a.pontos != b.pontos) return a.pontos > b.pontos;
        return a.vitorias > b.vitorias;
    });

    for (const auto& j : ranking) {
        std::cout << j.nome << ' ' << j.pontos << ' ' << j.vitorias << '\n';
    }
    std::cout << std::boolalpha << (ranking[0] == Jogador{"Bruno", 30, 10}) << '\n';  // true
    return 0;
}

    Boas práticas¶

    • Mantenha os atributos privados e ofereça métodos que representem as operações que fazem sentido para o objeto;
    • Inicialize todos os atributos, na lista de inicialização do construtor ou com valores padrão na declaração;
    • Declare como const todo método que não altera o objeto, e passe objetos para funções por referência constante;
    • Declare como explicit os construtores de um único parâmetro;
    • Prefira atributos que gerenciam os próprios recursos (std::string, contêineres, ponteiros inteligentes) e siga a regra do zero;
    • Em hierarquias de classes, declare o destrutor da classe base como virtual e use override em todos os métodos redefinidos;
    • Use struct para registros simples de dados, e class quando houver regras a proteger.
